# GitHub

GitHub 在 Paperclip 中支持仓库工具和一个实验性的聊天/审查机器人。它们是 **连接器** 页面上的两个独立条目：**GitHub** 用于仓库工具，**GitHub 代码审查机器人** 用于机器人。请选择适合您工作需求的选项。

## 您需要哪一种？

| 如果您想要 | 设置 | 它提供什么 |
| --- | --- | --- |
| 智能体作为其自身工作的一部分读取和操作仓库 | **GitHub** → **连接 GitHub** | 智能体可以调用的 GitHub 操作，以及对于托管身份，运行时 shell 使用的凭据 |
| 人员从 GitHub 开始工作，或智能体审查 PR | **GitHub 代码审查机器人** | 分配给一个智能体的机器人 App，在启用时提供任务绑定的审查工具和 PR 检查 |

个人 GitHub 连接不会创建机器人 App。常规仓库工具请使用 [GitHub 连接器设置](github-setup.md)，实验性聊天流程请使用 [设置 GitHub 审查机器人](github-review-bot-setup.md)。阅读 [理解 GitHub PR 审查机器人](understanding-github-review-bots.md) 以区分安装、触发器和合并要求。

在赋予智能体 GitHub 身份之前，请阅读 shell 例外说明——这是最常被误解的边界。

## Shell 例外

Paperclip 的逐操作 **允许** / **先询问** / **关闭** 开关控制通过 Paperclip 工具网关的工具调用。当 GitHub 连接作为专用身份绑定到智能体时，该身份也会提供给智能体的工作区 shell，而 shell 命令不经过网关。

当您更改 GitHub 权限时，Paperclip 会声明：

> **危险：** Shell Git 和 `gh` 在运行时使用此账户，不受逐工具“先询问”控制的约束。

这**不**意味着以下三点：

- **这不是关于其他连接器的声明，无论方向如何。** 此警告仅关于此连接上的 shell Git 和 `gh`。它未说明任何其他连接器的行为方式，您不应将其解读为承诺其他所有内容都限制在网关内——模型提供商连接提供凭据而非进行工具调用，消息通道通过其自身传输层承载对话。[连接器访问方式](access-model.md) 说明了哪些控制适用于哪种类型的连接。
- **这不是关于智能体不受限制的声明。** 上限是 GitHub 账户所能执行的操作：安装时选择的仓库，以及该账户在这些仓库上的权限。请缩小账户权限，而非调整开关。
- **人工批准不等于代码审查。** 已批准的 **先询问** 调用意味着某人对一次 API 调用说了“是”。Pull request 审查是 GitHub 上的独立控制，由审查者执行。两者不能互相替代。

实际后果：对于将推送代码的智能体，重要的限制在于 GitHub 端——选定的仓库、分支保护、必需的审查——而非 Paperclip 的逐工具开关。

## GitHub 作为智能体工具

### 选择凭据

| 路径 | 何时使用 | 可用性 |
| --- | --- | --- |
| **连接 GitHub** | 默认选项。Paperclip 管理 GitHub App 授权，且该身份也可供 shell Git 和 `gh` 使用 | 仅当实例已注册 Paperclip Cloud 且 Cloud 宣传 GitHub 连接器配置文件时 |
| **个人访问令牌（高级）** | 无 Cloud 注册，或您希望直接控制令牌 | 始终可用 |

这两者并不等效。细粒度个人访问令牌携带您在令牌上选择的权限。托管路径的权限来自 GitHub App 注册和安装时选择的仓库——GitHub 不为其返回 OAuth 范围列表，因此没有范围字符串可供检查。如果您需要精确推理权限，细粒度令牌更易于审计；如果您需要用于 shell 工作的持久身份，托管路径是提供该功能的路径。

### 选择身份

托管路径提供个人访问或专用智能体访问。其定义不提供组织共享授权：

| 设置选择 | 效果 |
| --- | --- |
| **我的 GitHub 账户** | *“当您负责时，每个智能体都可以使用您的 GitHub。”* 选择 **仅我选择的智能体** 以缩小范围 |
| **为智能体分配的专用账户** | *“无论谁启动运行时，该智能体始终使用此账户。”* 提交和评论可归属于该智能体 |

当您希望智能体的提交与人员的提交可区分时，专用智能体身份是正确选择。创建专用身份是管理操作：*“仅连接管理器可以授权专用智能体身份。”*

### 仓库访问

对于托管 GitHub App 路径，仓库范围在 GitHub 中设置。连接的身份证反映安装情况：

- **可访问的 GitHub 仓库** 列出选定的仓库，或对于组织范围安装显示 **所有当前和未来仓库**。
- **在 GitHub 上添加更多仓库** 和 **在 GitHub 上配置访问** 链接到 GitHub 的安装设置。
- **刷新访问** 在您更改安装后重新读取安装信息。

对于托管 App，优先选择选定仓库。授予所有当前和未来仓库的安装会随着组织的增长而扩大范围。

对于个人访问令牌，请在 GitHub 中审查令牌的资源所有者、选定仓库、权限、过期时间以及任何组织批准。GitHub App 安装控制不会设置 PAT 的范围。

### 操作

GitHub 的托管服务器提供操作列表，因此 Paperclip 不发布冻结副本。在连接的 **权限** 选项卡上阅读实时列表，并在 GitHub 更改后使用 **刷新操作**。

GitHub 添加的操作会发生什么取决于您选择的凭据路径。在 **托管** 路径上，新操作和更改的操作在您开启之前会被保留。在 **个人访问令牌** 连接上，它们会在已生效的策略下变为活动状态——因此在刷新后审查列表，而不是假设它只能缩小范围。[设置操作权限](action-permissions.md) 包含完整规则。

操作被分类为读取、写入或破坏性，并可设置为 **允许**、**先询问** 或 **关闭**——请记住这些设置能限制什么以及不能限制什么。参见 [设置操作权限](action-permissions.md)。

### 尝试使用

使用读取操作针对您预期选定凭据能够访问的仓库：

```txt
Read the README in YOUR_ORG/YOUR_REPO and report its first heading. Do not change anything.
```

将标题与仓库进行比较，并检查任务的连接器调用。对于托管访问，还需检查 GitHub App 安装的选定仓库；对于 PAT，检查令牌的仓库选择和权限。一次成功的读取不能证明凭据无法访问其他仓库。不要通过推送、pull request 或合并来验证。

> **注意：** 示例任务，非记录的测试结果。

## GitHub 作为通道

人员在议题或 pull request 中评论，提及智能体，Paperclip 创建任务。

### 连接前

- **GitHub 审查机器人** 必须为实例开启。这是其独立的实验性设置，默认关闭，且独立于 **聊天连接器**，由实例管理员在实验性设置中启用。
- 在组织中创建 GitHub App 并安装它的权限。
- 将回答问题的智能体。

### 设置机器人

[设置 GitHub 审查机器人](github-review-bot-setup.md) 通过 Storybook 示例引导您完成实验性设置。设置分为两步——**选择智能体** 和 **连接 GitHub**——之后 GitHub 会要求您批准创建和安装 App。然后 Paperclip 导入您授权的仓库，等待签名 webhook 传递，链接您的账户，并打开机器人的设置。您也可以连接您已有的 App。

机器人自身的 App 提供分配给智能体的受治理 GitHub 工具。在设置完成时，检查 **首次审查前** 下列出的任何内容；仅工作正常的 webhook 不能证明智能体可以运行。您的个人连接链接您的身份，但不替代机器人的 App 凭据。工作区 shell Git 访问需单独配置。

### 访问

提供商通道或仓库访问决定消息可以到达集成的位置；它本身不授权智能体工作。Paperclip 还检查发送者的链接身份和公司成员资格。链接用户必须是活跃的非查看者成员。未链接的发送者取决于连接的 **允许未链接人员** 设置和任何赞助要求。在邀请人员使用智能体之前，请审查这些控制。

### 尝试使用

1. 在已安装 App 的仓库中，打开一个草稿议题。
2. 评论，提及智能体，并要求其确认已连接。
3. 预期收到回复评论和 Paperclip 中匹配的任务。

> **注意：** 程序说明，非记录的测试结果。请使用草稿仓库或议题。

## 与工作区 git 设置不同

[将智能体连接到 GitHub 仓库](../how-to/connect-agent-to-github.md) 是不同的任务：将项目工作区指向远程，并将 Paperclip 的审查阶段与 GitHub 的匹配。该页面仍然是 git 和 `gh` 工作流本身的正确参考。此连接器是凭据到达那里的方式。两者都要使用。

## 故障排查

| 问题 | 可能原因 | 修复 |
| --- | --- | --- |
| 未提供 **连接 GitHub** | 实例未注册 Paperclip Cloud，或 Cloud 未宣传 GitHub 配置文件 | 使用 **个人访问令牌（高级）** |
| 未列出 **GitHub 代码审查机器人** | 实例的 **GitHub 审查机器人** 已关闭 | 请求管理员启用 |
| 智能体看到的仓库少于预期 | 安装未包含它们 | **在 GitHub 上添加更多仓库**，然后 **刷新访问** |
| *“您没有权限重新连接此身份。”* | 该身份属于其他人或智能体 | 请求其所有者，或使用您自己的 |
| 工具调用成功但 shell `git push` 失败 | 账户的仓库权限，或分支保护 | 在 GitHub 上检查两者 |
| 评论未创建任务 | App 未安装在该仓库上，或未选择事件 | 在那里安装并确认两个评论事件 |
| GitHub 中 Webhook 传递失败 | Webhook 密钥或 URL 不匹配 | 在 Paperclip 中重新生成密钥并更新 App |
| **需要关注** | 令牌已过期或安装已移除 | 选择 **重新连接** |

## 限制

托管仓库工具路径依赖于 Cloud 注册。审查机器人路径依赖于实验性 **GitHub 审查机器人** 设置并使用其自身的 App。两者都需要适当的 GitHub 仓库访问；审查机器人还在 Paperclip 中有一个已启用仓库子集。Paperclip 无法使用逐操作设置限制 shell Git 或 `gh`。

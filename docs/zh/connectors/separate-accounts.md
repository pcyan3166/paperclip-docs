# 为人员和智能体使用独立账户

Paperclip 支持个人、组织共享和专用智能体凭据。设置过程中显示的选择取决于连接器和连接方式；并非每种方式都支持这三种类型。

例如，托管 GitHub 提供 **我的 GitHub 账户** 或 **为智能体提供的专用账户**。Gmail 提供个人或组织共享访问权限，不提供专用智能体身份。无凭据方式没有可供选择的账户身份。将连接分配给某个智能体不会改变其凭据类型。

## 凭据类型

### 仅限本人

*“智能体仅在您作为责任人的运行中使用它。”*

这是您自己的账户，基于您自己的同意。智能体仅在您作为责任人的工作中借用它。当其他人启动运行时，此凭据对其不可用。

任何活跃成员都可以创建一个。将其用于第一个连接器、任何涉及个人邮箱或日历的操作，以及在公司承诺使用某提供商之前对其进行评估。

### 组织身份

一个与公司内符合条件的人员共享的账户。设置过程中可以将此标记为 **组织内的任何人**；连接的人类受众决定了哪些人的运行可以使用它。您单独选择哪些智能体可以使用该连接。共享凭据不会绕过任何受众限制。

创建一个组织身份是管理操作。Paperclip 在服务器端强制执行此规定：*“只有连接管理员才能将此凭据与组织共享。”*

将其用于共享机器人账户是预期模型的服务，并且您希望有一个地方可以撤销访问权限。

### 专用智能体身份

*“无论谁启动运行，该智能体始终使用此账户。”*

对于支持此功能的方式（如托管 GitHub），这是一个属于单个智能体的账户。Paperclip 会询问 *“哪个智能体拥有此 GitHub 账户？”* 并将凭据绑定到该智能体。任何人启动的运行在该智能体执行操作时都会使用该账户。

这也是一个管理操作：*“只有连接管理员才能授权专用智能体身份。”*

当提供商自身的审计轨迹很重要时，请使用此方式。专用 GitHub 账户意味着提交、评论和拉取请求可以归因于智能体，而不是恰好触发运行的某个人。

## 选择指南

| 问题 | 答案 |
| --- | --- |
| 这是我的个人账户吗？ | **仅限本人** |
| 提供商的日志是否应为该智能体命名一个独立账户？ | 在支持的地方使用 **为智能体提供的专用账户**；否则，连接一个独立的提供商账户并限制其人类和智能体受众 |
| 是否有真正的共享服务账户用于此目的？ | **组织身份** |
| 我是否仍在决定是否使用此提供商？ | **仅限本人** |

## 下游变化

**归因。** 专用身份在提供商处显示为其自身的操作者。共享身份无论谁执行操作，都显示为同一个账户。

**撤销。** 撤销组织身份是即时且彻底的：*“已安装智能体立即失去此共享身份。”* 撤销个人授权仅影响该人员。

**Shell 工具。** 专用 GitHub 身份也会传递给运行的 shell，其中每个工具的 **先询问** 不适用。此 shell 访问权限也适用于托管的个人 GitHub 身份；它并非专用智能体授权所独有。参见 [GitHub](github.md)。

## 后续更改

一旦连接存在，其身份即被固定。在恢复或重新连接时，Paperclip 将存储的身份视为权威来源，并且不会接受来自客户端的矛盾授权类型——该保护机制的存在是为了防止重新连接悄悄替换组织授权背后的凭据。

若要切换到不同的身份，请创建一个具有所需身份的新连接，将智能体访问权限迁移过去，然后删除旧连接。[重新授权、撤销或断开连接](reauthorize-and-disconnect.md) 涵盖了删除操作。

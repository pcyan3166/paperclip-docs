# Slack

Slack 为您的团队提供了一种无需离开对话界面即可与智能体协作的方式。有人在频道中提及该智能体，Paperclip 会将其转化为任务，回复将返回到该线程中。同一个 Slack 机器人还允许该智能体阅读讨论内容、发布更新，并从其常规任务和例程中向您发送消息。

Paperclip 中有两个独立的 Slack 连接，拥有各自的凭据。对于大多数团队而言，**与智能体聊天** 是您所需要的选项。

> **警告：** Slack 功能已可用，但尚未完全完善。后续修复计划已排期。聊天路由位于一个实验性设置之后，而独立的智能体工具路由存在已知的兼容性限制。在依赖 Slack 进行生产工作之前，请审阅这两个部分。

## 您需要哪种？

| 如果您希望 | 设置 | 它能提供什么 |
| --- | --- | --- |
| 人们通过在 Slack 中与智能体对话来开始和继续工作，且该智能体在工作时能在 Slack 中阅读和发布内容 | **与智能体聊天** | 为单个智能体提供一个 Slack 机器人：提及和私信变为 Paperclip 任务，且智能体获得受治理的 Slack 工具 |
| 智能体使用 Slack 自己的托管 MCP 服务器，并配合个人 Slack 授权 | **将此连接用作智能体工具** | Slack 的 MCP 操作，受操作权限治理 |

连接其中一个不会连接另一个。当 **聊天连接器** 开启且您在 **连接器** 下选择 **Slack** 时，Paperclip 会询问 **选择连接方式** 并提供这两个选项。

## Slack 作为频道

人们在频道中提及智能体或向其发送私信，Paperclip 便会创建一个任务。回复会返回到线程中。

### 连接前准备

- 必须为实例开启 **聊天连接器**。这是一个实验性设置，默认关闭，由实例管理员在实验性设置中启用。
- 实例需要一个可公开访问的 HTTPS 地址。Slack 通过调用 Paperclip 来传递事件；此路由不使用 Slack 的套接字模式。Paperclip Cloud 已具备此条件。如果您自行托管，私有地址（例如仅您的 tailnet 可访问的 Tailscale Serve URL）是不够的。如果缺少此条件，向导将显示 **需要公共 HTTPS URL** 并附带 **了解如何设置 HTTPS** 链接。
- 在工作区中创建和安装 Slack 应用的权限。如果您的工作区要求对新应用进行管理员审批，您也需要获得该审批。
- 一个属于该公司的 Paperclip 账户，以便您最后可以链接自己的 Slack 账户。

### 进行连接

打开 **连接器**，选择 **Slack**，然后选择 **与智能体聊天**。第一个屏幕会询问 **您想与哪个智能体聊天？** 选择人们将要与之对话的智能体。对于该连接，此智能体是固定的；若要代表不同的智能体，请连接另一个 Slack 应用。

每个智能体都有自己的 Slack 应用，因此它在 Slack 中会以自己的名称和头像显示。创建该应用有两种方式：

| 设置方式 | 您需要做什么 |
| --- | --- |
| **自动设置**（默认） | 粘贴一个临时的 Slack 令牌。Paperclip 创建应用，您批准安装。 |
| **手动设置** | 在令牌步骤的 **高级** 选项下，选择 **手动创建** 或 **使用现有应用**，然后自行根据 Paperclip 的清单创建应用并粘贴其凭据。 |

在智能体步骤中，**高级** 选项显示 **Slack 应用名称**、**机器人显示名称** 和 **斜杠命令**。Paperclip 会根据智能体的名称填入这些内容，后续所有指令都将使用您在此处保存的内容。

您可以随时通过 **保存并退出** 离开任何设置步骤，并通过连接行中的 **完成设置** 返回。您的进度会被保留。

#### 自动设置

自动设置包含四个步骤：**选择智能体**、**应用配置访问令牌**、**安装 Slack 应用** 和 **发送消息**。

1. **应用配置访问令牌。** 点击 **获取您的应用配置访问令牌**。在 Slack 应用设置中，找到 **您的应用配置令牌**，选择 **生成令牌**，并为您的机器人选择工作区。复制 **访问令牌**（而非刷新令牌）并粘贴到字段中。点击 **创建 Slack 应用**。Paperclip 仅使用此令牌一次来创建和配置应用，随后将其丢弃。
2. **安装 Slack 应用。** Paperclip 会打开 Slack 以便您批准安装。如果未自动打开，或您已关闭它，请点击 **在 Slack 中安装**。请使用您自己的 Slack 账户：Paperclip 将批准安装的账户链接到您，机器人会向您发送一条欢迎私信（“您的 Slack 账户已连接到 Paperclip”）。
3. **向您的智能体发送消息。** 点击 **打开 Slack** 并向机器人发送一条消息。Paperclip 会自动检查该消息，并在收到后显示 **成功**。点击 **完成**。如果它持续等待，请打开 **未生效？** 以查看 **事件订阅** 和 **请求 URL** 步骤。

Paperclip 会将智能体的头像上传为应用图标。如果上传失败，设置将继续进行，您可以稍后在 Slack 中上传图标。

#### 手动设置或现有应用

在令牌步骤中，打开 **高级** 选项并选择 **手动创建** 以根据 Paperclip 的清单自行构建应用，或选择 **使用现有应用** 以连接您已有的应用。手动路径包含六个步骤：

1. **选择智能体。**
2. **创建 Slack 应用。** 点击 **创建 Slack 应用**：Slack 将在新标签页中打开，且已预填 Paperclip 的清单。选择您的工作区，创建应用并安装。如果您之前已创建该应用，请改用 **我已创建应用**。若要检查生成的配置，请打开 **查看 Slack 应用清单**。
3. **添加凭据。** 这两个密钥位于不同的 Slack 界面，向导会在每个字段旁边提供指引：
   - **Bot User OAuth Token**，来自 **OAuth & 权限**。它以 `xoxb-` 开头。
   - **签名密钥**，来自 **基本信息**。它没有令牌前缀。`xapp-` 应用令牌不是签名密钥。

   点击 **连接 Slack 应用**。
4. **验证 Slack 连接。** 在您的 Slack 应用中，选择 **事件订阅**。在预填的 **请求 URL** 旁边，如果尚未验证，请点击 **重试**，如果 Slack 要求则保存。一旦 Slack 验证了连接，Paperclip 会自动继续。
5. **连接您的 Slack 账户。** 复制 Paperclip 显示的命令（您的斜杠命令后接 `connect`，例如 `/yourbot connect`）并在您的 Slack 工作区中发送。它仅用于识别您，不会启动任何智能体工作。当您的 Slack 账户出现在 Paperclip 中时，点击 **这是我的 Slack 账户**。仅确认属于您的账户。您将看到 **已链接到您**，然后 **继续到消息测试**。
6. **尝试一下**（可选）。打开一个频道，如有需要邀请机器人，并发送建议的消息，例如 `@yourbot you there?`。从 Slack 的 @提及建议中选择该机器人，以确保其真正收到通知。在线程中继续对话。Paperclip 会自动检查您的消息；以 **我已发送测试消息** 结束。

在手动路径中，请使用生成的清单，而不是手动配置范围。这是受支持的配置，手动挑选范围是设置半成功的最常见原因。请在 Slack 的 **基本信息** → **显示信息** 下自行上传应用图标。

> **危险：** 机器人令牌、签名密钥和配置令牌均为完整凭据。请仅将它们粘贴到 Paperclip 中。如果其中一个泄露，请在 Slack 中轮换它并重新连接。

#### 如果设置被中断

| 您看到的内容 | 应采取的措施 |
| --- | --- |
| 配置令牌已过期或被拒绝 | 生成新令牌并重试。您的草稿会被保留。 |
| Paperclip 不确定 Slack 是否已创建应用 | 点击 **打开 Slack 应用设置** 进行检查。如果不存在应用，勾选 **我已检查 Slack 且未创建应用。创建新应用。** 并重试。 |
| 您的 Slack 应用已保存，但其事件设置仍需应用 | 粘贴一个新的配置令牌并点击 **重试应用配置**。Paperclip 将重用同一个应用。 |
| 您的凭据已保存但连接检查失败 | 点击 **重试连接**。如果 Slack 访问权限已更改，请点击 **在 Slack 中重新授权**。 |

### 对话如何转化为工作

| 在 Slack 中 | 在 Paperclip 中 |
| --- | --- |
| 已链接的人员在频道中提及智能体 | 每个新的被提及线程对应一个任务 |
| 已链接的人员向智能体发送私信 | 智能体在私信中回复（当 **允许私信** 开启时）。若 **要求 @提及** 开启，私信也必须 @提及机器人。 |
| 对话在线程中继续 | 在同一任务上继续。若 **要求 @提及** 开启，频道回复必须 @提及机器人。 |
| 智能体已回答且无剩余工作 | 任务显示为 **空闲** |

Paperclip 会通过反应表情确认，以便人们在智能体完成思考之前就能看到消息已被接收。

新的 Slack 连接默认开启 **要求 @提及**。这防止普通闲聊启动智能体工作：智能体仅响应 @提及它的消息，包括其已在线程中的回复。此设置适用于私信和频道。如果您希望已关注线程中的任何回复都能到达智能体，请在 **设置** 中关闭此选项。在此设置存在之前建立的连接将保持其先前的行为。

如果您从 Slack 线程中停止智能体的运行，当前响应将结束。您在线程中的下一条消息将在同一任务上启动一个新的回合。

**空闲** 意味着智能体已回答并在等待下一条消息。它不是审查请求，因此已回答的 Slack 线程不会让您的审查队列或活跃工作数量变得杂乱。您仍可在连接的 **对话** 选项卡、搜索以及最近任务中找到它。线程中的新消息，或您从 Paperclip 发送的消息，会立即重新激活该任务。如果投递失败、有待决决策或有更多工作排队，任务将保持活跃状态。

### 从 Paperclip 回复

与 Slack 关联的任务会显示带有 **打开 Slack** 链接的 **已连接到 Slack** 横幅。您在任务上发送的消息以及智能体的回复，也会发布到 Slack 线程中，并标注您的姓名。您还可以在横幅的编辑器中编写内容并点击 **发送到频道**：您的消息将以您的姓名发布到 Slack 并启动智能体。您的 Slack 账户必须链接到此连接，您的消息才能通过。

### 智能体在 Slack 中能做什么

机器人连接为其智能体提供一组 Slack 工具。请用自然语言请求操作，例如“总结此线程并为决策创建后续任务”。智能体可以：

- 阅读频道、线程、消息、文件和源链接，并搜索可用的频道历史记录。
- 发送消息和文件，做出反应，置顶，书签，以及处理画布和列表。

某些操作始终需要先通过 Paperclip 进行审批：创建频道、邀请人员、删除机器人的消息、移除书签以及与频道共享列表。Slack 内部消息中说的“已批准”不算数。机器人创建的频道在有人开启之前，回复功能保持关闭状态。

智能体以请求者的已链接人员的权限进行操作。只有已链接的人员才能指挥这些工具，且智能体只能阅读机器人和该人员都能看到的频道。私有频道的内容保留在其源频道或该人员与机器人的私信中。机器人不能自行加入频道、邀请自己或阅读其他人与它的私信。

打开连接 **设置** 选项卡底部的 **Slack 工具** 以检查应用是否具备工具所需的所有权限。若要更改哪些操作需要审批，请参阅 [设置操作权限](action-permissions.md)。

如果您在这些工具存在之前连接了 Slack，**Slack 工具** 将显示 **添加权限以解锁更多工具** 并列出缺失的范围。您的连接将继续正常工作。若要解锁其余功能，请在 Slack 中打开您的应用，前往 **OAuth & 权限**，添加这些 Bot Token 范围，并将应用重新安装到您的工作区。

相同的工具也可供智能体在其常规的 Paperclip 任务和例程中使用，使用分配给该智能体的机器人以及负责该工作的已链接人员的 Slack 账户。

### 稍后发送消息或按计划发送

您可以从智能体的任何任务中请求一条 Slack 消息：“报告准备好时给我发一条 Slack 消息”。它会打开与您的私信（任务的责任人）并在那里发布。您需要一个已链接的 Slack 账户才能实现此功能。

对于类似“每个工作日早上 10 点在 #team 发布站会摘要”的需求，请使用分配给该智能体的常规 [例程](../guides/projects-workflow/routines.md)。在例程的指令中填入时间、时区和目标频道。没有单独的 Slack 调度器。每次运行都会使用例程的责任人，并在触发时再次检查其 Slack 链接、频道访问权限和权限。例程结果仅在智能体明确发送时才到达 Slack，因此请说明消息应发送到哪里。

> **注意：** 发送私信需要 `im:write` 范围。如果您的应用是在此范围添加之前创建的，请使用更新后的清单重新安装。

### 设置与访问

连接页面包含 **设置**、**访问**、**对话** 和 **活动** 选项卡。

- **设置** 列出 **允许的频道**（机器人所在的所有频道）、**允许私信** 和 **要求 @提及** 切换开关、**附加通信指令** 以及 **Slack 工具** 摘要。
- **访问** 包含已链接人员、**邀请人员**，以及两个可选部分：**访客访问** 和 **个人 Slack 搜索**。

**允许的频道** 控制智能体在哪里回复和写入，而不是它能阅读什么。要添加频道，请在 Slack 中邀请机器人加入。您邀请机器人加入的频道默认启用，且当您打开列表时，列表会自动刷新。如果您关闭某个频道，它将保持关闭状态，直到有人在 Paperclip 中重新开启；新的提及或邀请不会重新启用它。

默认情况下，智能体在 Slack 中以对话方式回复：先回答，使用短段落或短列表，较大的交付物通过附件或链接提供。使用 **附加通信指令**（最多 4,000 个字符）添加您自己的指导，例如产品名称或受众。它在新任务开始时生效，且不授予任何额外权限。

### 访问

提供商频道访问权限决定消息可以到达集成的位置；它本身不授权智能体工作。Paperclip 还会检查发送者的已链接身份和公司成员资格。已链接用户必须是活跃的非查看者成员，且他们的消息以其自己的 Paperclip 权限运行。

要让团队成员使用智能体，请点击 **访问** 选项卡上的 **邀请人员** 并使用 **复制邀请** 分享指令：

1. 他们在您的 Slack 工作区中发送连接命令（您的斜杠命令后接 `connect`）。
2. 机器人向他们发送一个私有链接。他们打开链接，登录 Paperclip 并确认其 Slack 账户。链接在 15 分钟后过期且仅有效一次。
3. 如果他们还不是组织成员，他们需请求访问权限，管理员批准请求后他们才能链接。

无需任何人创建另一个 Slack 应用或共享凭据。邀请某人加入 Slack 频道不会赋予其 Paperclip 访问权限。智能体也知道此流程：如果团队成员在 Slack 中询问如何连接，它会提供正确的命令。

**允许未链接人员**，位于 **访客访问** 下，对于新连接默认关闭。开启时，没有已链接账户的人员可以启动隔离任务。他们不能批准操作、花费或管理访问权限，且在隔离不可用时，其请求将被拒绝。

### 可选：个人 Slack 搜索

在 **访问** 选项卡上，**个人 Slack 搜索** → **您的 Slack 搜索访问** 允许每个已链接人员通过 **连接 Slack 搜索** 授权私有搜索。基本的频道阅读无需此功能即可工作。连接管理员首先需要在 **连接管理员的 OAuth 应用配置** 下设置 Slack 应用的 **客户端 ID** 和 **客户端密钥**，在 Slack 中注册显示的回调 URL 以及用户范围 `search:read.public`、`search:read.private` 和 `search:read.files`。

> **注意：** 即使连接了个人授权，当前运行时也未启用 Slack 的实时搜索。Paperclip 会在同一屏幕上显示此限制。智能体改用有界的频道历史搜索，并报告其覆盖范围。

## Slack 作为智能体工具

此路由将智能体连接到 Slack 自己的托管 MCP 服务器，使用个人 Slack 授权而非机器人。

如果您希望的是一个能在 Slack 中阅读和发布的智能体，上述聊天连接已为其智能体提供了受治理的 Slack 工具。为此目的，您不需要同时使用此路由。

### 智能体工具兼容性通知

**Slack 智能体工具路由可用，但在 v2026.1001.0 中存在已知的兼容性限制。** 该版本仍配置了与 Slack 当前托管 MCP 要求不同的 OAuth 端点和范围。成功的机器人安装并不验证 MCP 连接。

Slack MCP 要求注册内部或市场发布的应用、用户令牌 OAuth 端点，以及预期工具的用户范围。请参阅 [Slack 的 MCP 身份验证要求](https://docs.slack.dev/ai/slack-mcp-server/)。

请等待具有经过验证的 Slack MCP 兼容性的版本，或在尝试此路由前联系 [support@paperclip.ing](mailto:support@paperclip.ing)。下方的访问说明解释了预期的工具行为；它们并非此版本上成功设置的记录。

### 访问与操作

频道可达性由 Slack 决定：已授权的令牌可以看到其范围和工作区允许的内容，私有频道要求授权用户为成员。Paperclip 在此路由上没有频道选择器，因此请在 Slack 端限制访问。

Slack 的服务器提供操作列表。发布被分类为写入操作，因此除非您希望智能体在未提示的情况下向共享工作区发布，否则请将其保持为 **先询问**。打开连接的 **权限** 选项卡以查看实时列表。请参阅 [设置操作权限](action-permissions.md)。

## 故障排除

| 问题 | 可能原因 | 解决方法 |
| --- | --- | --- |
| 未提供 **与智能体聊天** | 实例的 **聊天连接器** 已关闭 | 请管理员启用 |
| 出现 **需要公共 HTTPS URL** | Slack 无法访问实例 | 将实例置于公共 HTTPS 地址之后，然后继续 |
| Slack 拒绝安装应用 | 工作区限制应用安装或要求审批 | 询问工作区管理员，然后通过 **完成设置** 恢复 |
| 配置令牌被拒绝 | 应用配置令牌有效期短且绑定到单个工作区 | 为正确的工作区生成新令牌并粘贴 **访问令牌**，而非刷新令牌 |
| Paperclip 警告签名密钥 | 您将机器人或应用令牌粘贴到了 **签名密钥** 中 | 从 **基本信息** 复制 **签名密钥** |
| **验证 Slack 连接** 持续等待 | 自您保存凭据以来，Slack 未重新检查请求 URL | 在 **事件订阅** 中，点击请求 URL 旁边的 **重试** |
| 连接命令后账户始终未出现 | 命令发送到了不同的工作区或应用 | 在已安装的工作区中发送您应用的精确斜杠命令加上 `connect` |
| 频道中的提及无反应 | 机器人不在频道中，频道在 **允许的频道** 中已关闭，或机器人被输入为纯文本 | 邀请机器人，启用频道，并从 @提及建议中选择机器人 |
| 线程中的回复未到达智能体 | **要求 @提及** 已开启，因此频道回复需要 @提及 | 在回复中 @提及机器人，或在 **设置** 中关闭 **要求 @提及** |
| 智能体阅读频道但不在其中回复 | 频道在 **允许的频道** 中已关闭 | 在 **设置** 中启用 |
| **设置** 显示 **添加权限以解锁更多工具** | 应用早于较新的 Slack 工具 | 在 Slack 中添加列出的 Bot Token 范围并重新安装应用 |
| 计划或请求的私信未到达 | 责任人没有已链接的 Slack 账户，或应用缺少 `im:write` | 从 **访问** 中链接账户，或使用更新后的清单重新安装 |
| 签名验证失败 | 签名密钥与已安装的应用不匹配 | 复制当前的签名密钥并重新连接 |
| 智能体工具路由：“此应用的 Slack MCP 访问已禁用” | Slack 应用设置中 MCP 访问已关闭；登录不会开启它 | 请 Slack 应用所有者启用 MCP 访问，然后刷新连接 |
| 工具路由要求客户端 ID 和密钥 | 预期行为——Slack 在此路由要求您自己的 OAuth 应用 | 在 Slack 控制台中注册应用 |

## 限制

- 每个连接在任一路由上仅支持一个工作区。
- 聊天路由需要公共入口，不支持套接字模式。
- 机器人不能自行加入频道；需由人员邀请。私有频道需要明确的成员资格。
- Slack 起源工作中的搜索是有界的历史扫描，而非全工作区搜索，且除非获取，否则不阅读线程回复。
- 在 Paperclip 中移除连接不会卸载 Slack 应用。应用及其机器人将保留在您的工作区中，直到您在 Slack 中移除它们。

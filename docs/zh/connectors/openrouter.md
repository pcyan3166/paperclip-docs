# OpenRouter

OpenRouter 连接为智能体提供一个凭据，该凭据通过单一账户路由至多个模型提供商。这是模型访问权限，而非一组工具——没有需要授权的操作。

OpenRouter 仅支持 API 密钥。该提供商没有订阅登录方式，Paperclip 会在登录屏幕上说明这一点。

## 连接前准备

- 一个已设置信用额度或账单的 OpenRouter 账户，以及来自 [OpenRouter 密钥](https://openrouter.ai/keys) 的 API 密钥。
- 一个运行 Claude、Codex、OpenCode 或 Hermes 的智能体。Paperclip Runner 对其 Codex、OpenCode 和 ACP Claude 提供商使用相同的规则。
- 一个受 OpenRouter 和您所选运行时支持的上游模型 ID。OpenCode 添加 `openrouter/` 运行时前缀；其他运行时使用原始上游 ID。

## 连接 OpenRouter

1. 打开 **连接器** 并选择 **OpenRouter**。
2. 粘贴 API 密钥。Paperclip 将其存储为机密信息，之后不可读取。
3. 可选地输入 **模型 ID（逗号分隔）**，然后在选择 **连接** 之前选择账户受众和智能体访问权限。

设置是一个单屏界面，没有单独的访问步骤。一旦账户保存，您可以从已保存的连接中更改哪些人员和智能体可以使用它。

## 分配凭据

在智能体的 **连接** 选择器中选择命名账户并保存。路由的 OpenRouter 连接需要显式选择；它们不能成为责任用户的提供商默认值。您可以选择符合条件的 **个人** 账户或 **公司共享** 账户。

每次运行都需要一个可以使用该凭据的责任用户，并且该连接必须已为该智能体或全公司范围安装。账户所有者必须保持为公司活跃成员。选择账户不会绕过这些检查。

使用所选连接显示的模型 ID。如果您将连接的模型列表留空，Paperclip 将从 OpenRouter 的公共目录中发现选项并提供刷新功能。您也可以自行输入提供商 ID。对于 OpenCode，`anthropic/claude-sonnet-4.5` 变为 `openrouter/anthropic/claude-sonnet-4.5`；Claude、Codex 和 Hermes 保留 `anthropic/claude-sonnet-4.5`。

没有路由元数据的旧版 OpenRouter 账户保留其仅限 OpenCode 的行为和 `openrouter/` 模型要求。针对该旧版账户的现有责任用户默认值可以继续工作；重新连接不会将其静默转换为路由连接。当您需要扩展的运行时支持时，请创建新连接。

> **警告：** 成功认证并不意味着特定模型对您可用。OpenRouter 根据其自身的可用性、您的信用额度以及任何提供商特定要求，决定您的账户可以路由到哪些上游模型。适用于一个模型的密钥可能在另一个模型上被拒绝。

### 从智能体设置中连接

在智能体的 **连接** 选择器中选择 **连接账户…** 以打开模型提供商设置。连接 OpenRouter，然后选择返回的账户和模型。连接的访问设置仍决定哪些人员和智能体可以使用它。

如果任务显示认证卡片，请使用 **修复连接** 替换存储的密钥。只有账户所有者可以重新连接。现有的路由和共享设置保持不变，任务在成功设置后恢复。

## 检查您的使用限制

在将长期任务交给智能体之前，您可以查看提供商配额剩余多少。打开已保存的账户并找到 **使用情况**，然后选择 **检查使用情况**。对于 OpenRouter 密钥，当 OpenRouter 返回相关信息时，Paperclip 会向 OpenRouter 查询该密钥的信用上限、重置频率以及免费模型的每日上限。

Paperclip 仅在您请求时读取限制。打开账户、列出连接和启动运行都不会触发检查。每个限制窗口显示已使用量及重置时间，并在提供商指示时标记为 **已达限制** 或 **已阻止**。**超额** 显示是否可用额外付费使用。提供商未提供的任何内容显示为 **未报告**，绝不显示为零。成功检查后，按钮变为 **刷新**。

检查是只读的。它不会将工作转移到另一个账户，不会在达到限制时停止运行，不会刷新凭据，也不会购买信用额度。

| 消息 | 含义 |
| --- | --- |
| *"再次登录以检查使用情况。"* | 存储的凭据已过期。重新连接账户 |
| *"拒绝访问使用情况。"* | 提供商拒绝共享此凭据的使用情况 |
| *"检查次数过多。请稍后重试。"* | 提供商对检查本身进行了速率限制。您的配额不受影响 |
| *"重新连接以检查使用情况。"* | 账户当前不可用。请先重新连接 |

董事会用户可以通过 API 使用 `GET /api/companies/{companyId}/ai-connections/{connectionId}/usage` 运行相同的检查。

## 尝试使用

```txt
Reply with the single word: ready
```

在记录所选连接和模型后，在兼容的智能体上运行它。OpenCode 使用 `openrouter/` 前缀；其他兼容运行时使用上游模型 ID。

**回复证明** OpenRouter 凭据已被接受，运行时和所选模型兼容，且上述检查已通过——Paperclip 拒绝不合格的绑定，而不是回退到另一个账户。**它不能证明哪个 OpenRouter 账户被计费**；Paperclip 不显示每次运行的该归属信息，因此如果您需要确认，请在您的 OpenRouter 账户中检查活动记录和信用余额。

如果失败，每次只更改一项——模型 ID 是最常见的原因。

> **注意：** 示例任务，非记录的测试结果。

## 故障排除与限制

| 问题 | 可能原因 | 修复方法 |
| --- | --- | --- |
| *"选择与此运行时和模型兼容的 AI 连接"* | 连接路由或模型与所选运行时不匹配 | 检查这是路由账户还是旧版仅限 OpenCode 的连接，然后选择兼容的模型 |
| 没有订阅选项 | 预期行为。OpenRouter 仅支持 API 密钥 | 使用 API 密钥 |
| *"连接账户并选择您的个人默认值"* | 智能体使用旧版责任用户绑定，且该人员没有默认值 | 恢复该默认值，或在智能体设置中显式选择路由账户 |
| *"此运行需要责任用户选择 AI 连接"* | 运行没有责任人来评估凭据检查 | 为工作指定符合条件的责任用户。绑定共享连接 **不能** 绕过此限制 |
| 密钥有效但某个模型被拒绝 | OpenRouter 未为您的账户路由该模型 | 选择另一个模型，或向 OpenRouter 检查该模型的要求 |
| 使用量上升后运行失败 | OpenRouter 信用额度耗尽或应用了速率限制 | 在已保存的账户上选择 **检查使用情况** 以查看密钥的信用上限，然后在 OpenRouter 中充值或提高限制 |
| 状态 **需要关注** | 密钥已被撤销或轮换 | 使用当前密钥重新连接 |

限制：一个连接对应一个 OpenRouter 账户，且不授予任何工具访问权限。模型目录是选项列表，而非账户权限或运行时兼容性的证明。OpenRouter 决定您的账户可以访问哪些上游模型。

# 回复连接器审核请求

当智能体调用设置为 **Ask first** 的操作时，调用会停止并等待人工处理。这是您进行回复的地方。

## 查找等待中的请求

有两个位置，指向同一个队列：

- **Connectors → Review**，涵盖公司范围内的所有内容。
- 连接器自身的 **Review** 选项卡，范围限定于该特定连接。

待处理项目标记为 **Waiting for your OK**。在有项目待处理时，连接器列表会将该连接标记为 **Needs attention**。

对应的 API 等效操作为：

```http
GET /api/companies/{companyId}/tools/action-requests?status=pending
```

## 请求显示的内容

审核卡片中显示的操作、连接和请求详情。可用的详情取决于请求类型。如果预览无法明确将要发生的变更，请在批准前检查任务并要求智能体进行澄清。

## 三种回复选项

| 回复 | 发生的情况 |
| --- | --- |
| **Allow once** | 批准此存储的调用，但不为未来调用创建规则。除非有其他策略允许，否则新的调用仍需批准。 |
| **Always allow** | 批准此调用，并允许同一智能体在此连接上使用 **不同的参数** 执行相同操作，若存在当前项目，则限于该项目范围内。仅对符合条件的请求提供此选项。 |
| **Decline** | 拒绝此请求而不执行其操作。智能体必须改变方法。 |

当您仅打算批准眼前的特定请求时，请选择 **Allow once**。**Always allow** 比记住一组完全相同的参数范围更广。

## 信任规则

信任规则是根据一次批准创建并保存的公司工具策略。它并非不可见：规则列在公司工具策略下，显示其匹配的选择器，且每一条都可以被撤销。

撤销信任规则会移除该允许项。未来的调用将根据剩余策略进行评估，包括已配置的 **Ask first**。这不会撤销已经运行的调用。

在您对授权该操作在所述范围内使用其他参数感到放心之前，请优先选择 **Allow once**。一次成功的读取或一次无害的写入并不能证明之后的每次使用都是可接受的。

## 智能体的体验

调用“先询问”操作的智能体不会收到错误，也不会收到结果——它会被告知需要批准，然后等待。当您回复后，Paperclip 会再次唤醒智能体。

批准意味着批准并运行：Paperclip 尝试使用其保存的参数执行存储的调用。批准并非提供商操作成功的证明；请检查执行结果。智能体在批准后不应重新发出调用；如果唤醒消息显示已执行，则该结果即为最终结果。

被拒绝的请求意味着操作未发生。预期智能体改变方法，而不是重试相同的调用。

待处理请求会过期。过期后，该项目显示为 **Expired — send it again**，智能体必须发起新的调用以开启新请求。

## 如果请求似乎卡住

- 测试调用显示 **Denied — see Review for why** 意味着请求被拒绝，而非连接器损坏。
- 请求从未出现通常意味着调用从未到达网关。检查操作是否未设置为 **Off**，以及智能体是否在连接的允许集合中。
- 处于 **Paused** 状态的连接不会产生审核请求，因为智能体根本无法使用它。

# 通过 MCP 聚合器连接应用

某些应用在 Paperclip 中没有自己的连接器。**MCP 聚合器**填补了这一空白：它是一个外部服务，代表您连接到许多应用，并通过一个 MCP 服务器将它们提供给 Paperclip。Paperclip 在**连接器**页面上列出了其中四个——**Arcade**、**Composio**、**Executor** 和 **Zapier**——它们在所有实例上均可用，无需开启任何设置。

在整个过程中请记住一点：聚合器位于您的智能体和应用之间。它持有应用的登录凭据并传递请求。Paperclip 仍然决定哪些人员和智能体可以使用该连接以及他们可以调用其哪些工具，但聚合器在应用内部执行的任何操作均由聚合器端管理。

## 优先使用原生连接器

如果 Paperclip 为某个应用提供了自己的连接器，请使用该连接器。这是 Paperclip 审查的路径，也是智能体被引导使用的路径。聚合器适用于没有原生连接器的应用。

## 四个提供商

每个提供商都有自己的目录条目和自己的连接。设置屏幕显示您所选提供商的步骤，并提供指向该提供商指南的链接。

| 提供商 | 粘贴内容 | 登录 |
| --- | --- | --- |
| **Arcade** | 您在 Arcade 中创建的网关的 MCP 网关 URL，并选中其工具。 | 当网关要求时进行浏览器登录。 |
| **Composio** | 通常无需粘贴：**Composio Connect** URL 已预填。仅当您在其他地方设置了 Composio 会话时才替换它。 | 使用您的 Composio 账户进行浏览器登录。 |
| **Executor** | 您的 Executor 工作区“集成”部分下“连接智能体”中的 URL。如果 Paperclip 可以访问自托管端点，则该端点有效。 | 提示时进行浏览器登录。 |
| **Zapier** | 来自 Zapier MCP 服务器的完整服务器 URL，包含令牌。参见 [Zapier](zapier.md)。 | 无——令牌是 URL 的一部分，因此请将 URL 视为机密。 |

## 设置一个

1. 在左侧边栏中，选择**连接器**，找到提供商并选择它。
2. 阅读主按钮上方的访问摘要。新的网关设置通常默认包含您组织中的所有人以及所有智能体；选择**更改**以缩小任一受众范围。[与人员和智能体共享连接器](share-access.md) 解释了这些选择。
3. 将地址粘贴到 **MCP 服务器 URL** 中，并选择 **Connect {provider}**，例如 **Connect Arcade**。除非您打开**重用现有会话**，否则 Composio 使用其预填的 URL。当 Paperclip 连接到服务器并读取其工具列表时，会显示*“正在连接并发现工具…”*。
4. 如果提供商需要登录，将打开一个提供商窗口。在那里完成操作并返回；Paperclip 会等待确认。
5. 审查**权限**，并将每个工具设置为**允许**、**先询问**或**关闭**，这与任何连接器上的操作相同——参见[设置操作权限](action-permissions.md)。

非 MCP 端点的 URL 会立即被捕获并提示*“请输入有效的 MCP URL”*。仪表板页面不是 MCP 端点，因此请复制提供商提供的服务器 URL。

### 高级身份验证

大多数设置仅需 URL 即可。如果您的提供商提供的是令牌或标头而非浏览器登录，请选择**更改**，并在**身份验证**下使用**登录方法**：

- **自动（如需则登录）**——支持浏览器登录的提供商的默认选项。
- **Bearer 令牌**——仅粘贴令牌，不要包含 Bearer 一词。
- **自定义标头**——添加提供商提供的每个标头名称和值。
- **无额外身份验证**——仅 URL 即可。

来自设置屏幕的两个特定提供商注意事项：对于 Arcade 标头，请使用 API 密钥作为 Bearer 令牌，并为操作用户添加 `Arcade-User-ID` 标头。对于 Executor，API 密钥必须是用户密钥；工作区和组织密钥无法打开 MCP 会话。

### 如果登录未完成

取消登录不会丢失您的工作。Paperclip 会显示*“连接已取消。您的设置详情已保留；准备好时请重试。”*，按钮变为**重试**。如果您需要中途停止，可以离开并在稍后继续——连接将显示**继续设置**，且您的访问选择保持不变。

## 当智能体请求某个应用时

您无需提前设置这些。当智能体需要一个 Paperclip 没有原生连接器的应用，且已知一个或多个聚合器支持该应用时，智能体会要求您进行选择。您会看到类似以下的问题：

> *“通过外部服务连接 HubSpot？这些服务处理与 HubSpot 的连接和请求。连接提供商尚未授权 HubSpot。”*

智能体发现这些应用的方式与发现任何连接器相同：通过名称，或用通俗语言描述需求。完整的句子有效，小的拼写错误和拆分名称也有效。要了解聚合器可以访问哪些应用，Paperclip 维护自己的列表，该列表基于提供商发布的目录构建，包括 Composio 的公共工具包目录，因此智能体的搜索始终不离开 Paperclip。该列表中的匹配项是线索，而非承诺：它并不意味着您的提供商账户已连接到该应用。

选项列出了支持该应用的提供商，第一个标记为**推荐**，外加**暂不连接**。Paperclip 的排序为 Composio、Arcade、Executor，然后是 Zapier。选择**暂不连接**即停止：不连接任何内容。

如果您选择了一个已有连接的提供商，设置卡片会提供重用该连接的选项（*“使用现有连接或连接新账户”*），或者您可以选择**连接新账户**。重用账户会保持其现有的访问权限不变。

选择提供商是连接该提供商，而非其背后的应用。连接后，智能体会检查该应用是否确实可以通过该提供商访问，并引导您完成提供商所需的任何额外授权。在确认之前，它不应报告成功。

## Paperclip 控制什么，不控制什么

Paperclip 控制对其为该连接列出的工具的访问。这些工具内部的应用和操作权限由提供商管理。

因此，请有意地设置这两层：

- 在提供商中，仅连接您需要的应用，并仅暴露您需要的操作。
- 在 Paperclip 中，活动操作默认为**允许**，包括写入。如果您希望访问权限更窄，请将写入设置为**关闭**或**先询问**，并在更改提供商的工具选择后运行**刷新操作**。审查出现的内容。

## 查找和管理应用账户

目录默认从 **Paperclip** 开始。使用 **Composio**、**Arcade**、**Installed**（已安装）或 **All**（全部）来更改视图。搜索匹配应用名称、别名、提供商和已保存的账户。未安装的目录每页显示 50 个条目；匹配的已安装应用会排在该目录上方。

没有原生设置的应用可能作为一个卡片出现，显示其可用提供商的标志。当多个提供商支持时，**连接** 会打开提供商选择。即使同一应用也出现在外部提供商的目录中，原生连接器仍保留其自己的设置。

已保存的原生和导入账户分组在其应用卡片下。导入的行显示 **由 {provider} 管理**，并链接到提供它的已保存网关。当提供商管理的账户存在时，提供商过滤器包含原生应用卡片，而不仅仅是因为提供商的公共目录列出了该应用。

Composio、Arcade 和 Executor 网关可以在 **权限** 中显示 **已连接应用**。在可用发现功能的地方，Paperclip 在首次加载时刷新列表。使用 **刷新 Composio**、**刷新 Arcade** 或 **刷新 Executor**（在那里或在已保存网关的菜单中）以再次检查该网关。Executor 仍可作为连接使用；其目录过滤器暂时隐藏。

失败或不完整的检查会将最后已知的账户标记为 **未验证**。已开始但未完成登录的账户显示 **等待登录**，过期的账户显示 **需要登录**。替换凭据会隐藏来自前一个凭据的观察结果，直到新凭据被检查。发现报告账户；它不授予访问权限或授权应用。

导入账户的菜单打开上游提供商。重命名、移除和应用授权在那里进行。Paperclip 的访问和操作设置保留在父网关上，并适用于其所有应用；分组卡片不创建独立的应用级访问边界。从 Paperclip 中移除已保存的网关不会删除提供商的账户。

有关特定提供商的设置和发现，请参见 [Composio](composio.md)、[Arcade](arcade.md) 和 [Executor](executor.md)。

## 旧的 Composio 连接

通过 Paperclip 早期 Composio 集成创建的 Composio 连接不再运行。从 **连接器** 添加新的 Composio 连接，进行设置，然后移除旧的连接。凭据和权限不会迁移。[Paperclip 识别但不列出的提供商](recognized-providers.md#composio-listed-again-old-connections-retired) 包含详细信息。

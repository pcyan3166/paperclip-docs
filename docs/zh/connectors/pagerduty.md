# PagerDuty

智能体可以处理 PagerDuty 的事件、服务、排班和值班信息——这对于让智能体总结事件或检查谁在值班非常有用。

## 首先选择您的区域

PagerDuty 将账户托管在不同的服务区域，这些区域是不同的端点，且没有跨区域访问权限。请选择托管您账户的那个区域：

| 选项 | 适用场景 |
| --- | --- |
| **美国服务区域** | PagerDuty 账户托管在美国 |
| **欧盟服务区域** | PagerDuty 账户托管在欧盟 |

选择错误的区域是最常见的设置失败原因，而且它看起来并不像区域问题：认证会直接失败，或者账户显示为空。如果您不确定，请检查您用于登录 PagerDuty 的域名。

## 连接前准备

- 一个 PagerDuty 账户，以及从中获取的**用户 API 令牌**。
- 确认账户托管在哪个区域。

该令牌携带该用户的权限。如果智能体仅应拥有读取权限，请从一个角色为只读的账户中签发令牌——这比仅依靠操作设置提供了更强的边界保护。

## 连接 PagerDuty

1. 打开**连接器**并选择**PagerDuty**。
2. 阅读主按钮上方的访问说明行。它说明了连接以谁的身份登录以及哪些智能体可以使用它。若要选择其他身份、缩小智能体范围或使用其他登录方法，请选择**更改**。
3. 检查服务区域。若要切换**美国服务区域**和**欧盟服务区域**，请选择**更改**。
4. 粘贴**PagerDuty API 密钥**。Paperclip 将其作为机密信息存储。

### 创建哪种 PagerDuty 令牌

Paperclip 的字段要求提供**用户 API 令牌**，而非通用的 REST API 密钥。在 PagerDuty 中，这两者是不同的凭据：

- **用户 API 令牌**代表一个人，并继承该用户自己的 PagerDuty 角色和团队访问权限。请在您的 PagerDuty 用户设置下创建一个。
- **通用 REST API 密钥**是账户范围的，并非此字段所期望的内容。

由于用户令牌继承其用户的权限，**您创建它的账户决定了访问权限。** 由具有只读 PagerDuty 权限的用户创建的令牌赋予智能体只读的 PagerDuty 访问权限，这是限制此连接器范围的最清晰方式。在具有广泛权限的账户下创建令牌会将这些权限授予智能体。

PagerDuty 自身的参考文档是 [PagerDuty MCP 服务器文档](https://support.pagerduty.com/main/docs/pagerduty-mcp-server)。

## 选择访问权限

访问范围取决于令牌：即签发用户可见的服务、团队和事件，受 PagerDuty 自身角色和团队成员资格的限制。Paperclip 中没有服务或团队选择器。

事件操作具有深远的影响，这很容易被低估。确认或解决事件会改变谁被呼叫并停止升级——在真实的服务中断期间，这会立即对人员造成影响。

> **警告：** 将事件变更操作——确认、解决、重新分配，以及任何创建或触发事件的操作——设置为**先询问**或**关闭**。智能体若静默解决其不理解的事件，就会终止升级流程。

读取操作可以安全地保持为**允许**。参见 [设置操作权限](action-permissions.md)。

## 尝试使用

```txt
Show me the most recent PagerDuty incident and tell me its status, service, and who it is assigned to. Do not acknowledge or resolve anything.
```

与 PagerDuty 进行对比。读取现有事件可以确认令牌、区域和智能体的权限，而不会呼叫任何人或干扰升级流程。

不要通过创建测试事件来验证——这会呼叫当前值班人员。

> **注意：** 这是示例任务，而非记录的测试结果。

## 故障排查与限制

| 问题 | 可能原因 | 解决方法 |
| --- | --- | --- |
| 使用您认为有效的令牌时认证失败 | 通常是服务区域错误；也可能使用了通用 REST API 密钥而非用户 API 令牌 | 确认令牌是用户 API 令牌，然后尝试另一个区域 |
| 连接成功但没有事件或服务显示 | 区域错误，或令牌的用户没有团队访问权限 | 以该用户身份登录 PagerDuty 并检查他们自己是否能看到这些事件。如果可以，请尝试另一个区域 |
| 某些服务不可见 | PagerDuty 团队成员资格和角色限制了令牌的用户 | 在 PagerDuty 中调整该用户的团队或角色 |
| 写操作被拒绝 | 令牌的用户角色为只读 | 如果您这样配置了，这是预期行为 |
| 事件被意外解决 | 变更操作被设置为**允许** | 在 PagerDuty 中重新打开它并收紧操作设置 |
| **需要关注** | 令牌已被吊销 | 签发新令牌并重新连接 |

限制：每个连接仅限一个账户和一个区域。Paperclip 内部没有服务或团队过滤器。PagerDuty 的 API 速率限制适用。

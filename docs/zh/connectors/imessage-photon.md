# iMessage Photon

用户从 Apple Messages 向您的智能体发送消息，Paperclip 随即开始工作。消息投递通过 [Photon Cloud](https://photon.codes/) 进行，这是一个提供 iMessage 线路的第三方服务。

> **注意：** 这不会让 Paperclip 访问您自己的 Messages 历史记录、您的 Apple ID 或您拥有的 Mac 电脑。本地不会安装任何内容。智能体在 Photon 运营的一条线路上可达，只有在该线路上进行的对话才会到达 Paperclip。

## 连接前准备

- **聊天连接器** 必须为实例开启。这是一个实验性设置，默认关闭，需由实例管理员在实验性设置中启用。
- 一个 Photon Cloud 账户和项目，以及该项目的 **项目密钥（project secret）**。
- 关于您需要哪种类型线路的决定——见下文。这决定了群组功能是否可用。
- 将要回复的智能体。

## 首先选择线路类型

Photon 提供两种配置方式，它们在影响您可构建内容的方式上有所不同：

| 线路 | 直接消息 | 群组聊天 |
| --- | --- | --- |
| **Pro（共享线路）** | 是，前提是每位发送者已在 Photon 中注册并在 Paperclip 中关联其身份 | 否 |
| **专用线路** | 是 | 是，针对您单独启用的群组 |

共享 Pro 线路需要针对每位发送者进行设置，因此适合少量已知人员。如果您需要群组对话或面向开放受众，则应选择专用线路。请与 Photon 确认当前的线路可用性和定价。

## 连接 iMessage Photon

### 1. 连接项目

1. 在 Photon 中创建项目，并记录其 **项目 ID** 和 **项目密钥（project secret）**。
2. 打开 **连接器** 并选择 **iMessage Photon**。
3. 在 **访问** 步骤中，选择身份以及哪些智能体可以使用该连接。
4. 提供项目 ID 并粘贴 **项目密钥（Project secret）**，然后选择分配方式：**共享**（Pro 项目共享号码）或 **专用**（您选择的一条线路）。
5. 在专用分配中，选择 **线路**。仅可选择符合条件的线路；如果没有提供选项，说明该线路在 Photon 端尚未就绪。
6. 选择将要回复的智能体。

Paperclip 在此时会将凭据与 Photon 进行验证。有两种失败情况值得注意：*"Photon 分配已更改；请重新检查项目"* 意味着项目的分配不再与您选择的一致；*"请选择符合条件的专用 Photon 线路"* 意味着您选择的线路不可用。

### 2. 关联发送者——这是必需步骤，而非可选步骤

**未与 Paperclip 人员关联的发送者完全无法在此通道上启动工作。** 其他 Paperclip 通道可以将未关联的发送者作为受限访客在隔离运行中运行；iMessage Photon 不允许这样做。在关联之前，什么都不会发生。

关联通过发现机制工作——您先向该线路发送消息，以便 Paperclip 能看到发送者，然后您关联其发现的内容：

1. **在共享分配中**，首先在 Photon 项目的 **用户** 下注册您的发送者，并在 **入门指南** 下找到项目分配的号码。在专用分配中，使用线路本身的号码，Paperclip 会显示一个 **复制** 按钮。
2. 从 Apple Messages 向该号码发送一条 **全新** 的消息。
3. 该消息会发现您的电话号码或 Apple 账户地址。打开连接的 **访问** 设置，并将该确切身份关联到 Paperclip 人员。
4. 发送 **另一条全新请求**。Paperclip 不会重放您在步骤 2 中发送的消息，且较早的消息不会追溯启动工作。
5. 等待智能体的实际回复。设置在该回复送达时完成，而非在您发送时完成。

> **警告：** 步骤 4 是人们容易遗漏的一步。关联不会追溯地将发现消息转换为任务——您必须在之后再次发送。

### 3. 群组，仅限专用线路

1. 在 Messages 中将线路号码添加到群组。
2. 在群组中发送一条消息。
3. 在连接的 **设置** 中启用已发现的群组。
4. 在群组中发送一条全新请求。

在共享分配中，此功能不可用，而不仅仅是未配置：Paperclip 会拒绝并提示 *"Photon 共享通道仅支持直接消息；群组需要专用通道。"*

Photon 的 [连接和路由指南](https://photon.codes/docs/spectrum-ts/providers/imessage/connection-and-routing) 涵盖了提供商端的内容。

> **危险：** 项目密钥用于验证整个 Photon 项目。请仅将其存储在 Paperclip 中，如果它曾暴露，请在 Photon 中轮换该密钥。

## 对话如何转化为工作

| 在 Messages 中 | 在 Paperclip 中 |
| --- | --- |
| 已注册的发送者向线路发送消息 | 为已连接的智能体创建一个任务 |
| 他们继续回复 | 对话在同一任务上继续 |
| 在专用线路上，已启用的群组中收到消息 | 作为群组上下文路由到已连接的智能体 |

## 选择访问权限

有两个独立的控制项，位于两个不同的侧面，值得将它们区分开来：

| 控制项 | 所在位置 | 决定内容 |
| --- | --- | --- |
| 发送者注册、线路分配、群组成员资格 | **Photon** | 消息是否到达 Paperclip |
| 身份关联、群组启用、回复智能体 | **Paperclip** | 到达的消息是否启动工作 |

因此，消息可以通过 Photon 但在 Paperclip 中仍不执行任何操作——这是该连接器“无法工作”的常见原因，且这是 Paperclip 端的关联问题，而非 Photon 故障。

身份关联使 Paperclip 能够将对话归属于某个人。**在此通道上，未关联的发送者会被拒绝**，而不是像在其他地方那样作为受限访客运行。这是有意为之：Apple Messages 发送者是一个电话号码，Paperclip 不会为无法归属的电话号码启动智能体工作。

连接的身份和智能体设置与其他连接器相同；参见 [连接器访问如何工作](access-model.md)。回复智能体在连接上设置。

## 尝试使用

仅在您自己的身份已关联后执行此操作——否则您测试的是关联步骤，而非连接本身。

1. 从您已关联身份所属的 Apple 设备，向线路发送一条全新消息：`hello, can you confirm you are connected?`
2. 预计几分钟后在 Messages 中收到回复。
3. 确认 Paperclip 中出现匹配的任务，并分配给已连接的智能体。

首先使用您自己已关联的号码。在专用线路上，在启用任何群组之前，先确认直接消息有效。

> **注意：** 这是操作程序，而非记录的测试结果。

## 故障排查与限制

| 问题 | 可能原因 | 解决方法 |
| --- | --- | --- |
| iMessage Photon 未出现在 **连接器** 中 | 实例的 **聊天连接器** 已关闭 | 请管理员启用它 |
| 发送者的消息从未启动工作 | 其身份未在 Paperclip 中关联。在共享线路上，他们可能也未在 Photon 中注册 | 如有需要，在 Photon 的 **用户** 中注册他们，在 **访问** 中关联已发现的身份，然后让他们发送一条全新消息 |
| 已关联身份但仍无反应 | 关联后不会重放发现消息 | 发送一条新消息。只有关联后发送的消息才会启动工作 |
| 设置无法完成 | 它在智能体送达的回复时完成，而非在您发送的消息时 | 等待回复；如果没有收到，请回溯检查关联步骤 |
| *"Photon 共享通道仅支持直接消息"* | 在共享分配上启用了群组聊天 | 移至专用线路；此情况会被拒绝而非降级处理 |
| *"请选择符合条件的专用 Photon 线路"* | 所选线路在 Photon 端不符合条件 | 选择符合条件的线路，或在 Photon 中解决线路状态问题 |
| 专用线路上群组消息被忽略 | 群组已发现但从未启用 | 在连接的 **设置** 中启用它，然后发送一条全新请求 |
| 消息在工作一段时间后停止 | Photon 中的项目密钥已轮换 | 使用当前密钥重新连接 |
| 所有人的投递延迟或失败 | Photon 端的问题，而非 Paperclip | 检查 Photon 的状态和项目配置 |
| 错误的智能体回复 | 回复智能体在连接上设置 | 在连接上更改它 |

限制：每个连接仅限一个 Photon 项目和一个智能体。Pro 共享线路不支持群组。Paperclip 依赖 Photon 进行投递，因此其可用性限制了该连接器的可用性。没有本地或原生 Apple Messages 集成。

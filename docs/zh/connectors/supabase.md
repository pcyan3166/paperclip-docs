# Supabase

智能体可以检查并操作 Supabase 项目——包括其数据库、架构和项目配置。

> **警告：** 请使用开发项目。Supabase 连接可以访问真实数据，且若未启用只读模式，可能会更改架构和数据库内容。除非您已阅读 Supabase 官方的 MCP 安全指南并有意接受相关风险，否则请勿连接生产项目。

此连接器默认启用写入工具。它们受 Paperclip 的操作设置管理，但默认状态并非只读——您需要主动选择启用只读模式。

## 连接前准备

- 拥有一个 Supabase 账户，且该账户有权访问您希望智能体使用的项目。
- 该项目的 **项目引用**（project reference），可从其 Supabase 设置中获取。Paperclip 在两种身份验证方法中均要求提供此项——此处不存在无范围限定的配置。
- 对于密钥方法：需要一个 **Supabase 个人访问令牌**。请参见下文，因为在此连接器上，使用错误类型的凭据是最容易犯的错误。
- 在连接之前而非之后，决定好是否启用只读模式。

### 密钥方法所需的凭据类型

**您的 Supabase 密钥** 字段接受 **个人访问令牌**，这是 Supabase 描述的用于对“管理 API 及基于其构建的工具（如 Supabase CLI 和 MCP 服务器）”进行身份验证的凭据。占位符为 `sbp_...`。

项目的 **anon** 密钥和 **service-role** 密钥 *不能* 与之互换。前者用于对项目数据进行身份验证；而个人访问令牌用于对管理操作进行身份验证。在此处粘贴 service-role 密钥将无法工作，且该凭据被复制传播的风险远大于个人访问令牌。

请在 [账户访问令牌](https://supabase.com/dashboard/account/tokens) 下创建一个。Supabase 提供两种类型，其区别至关重要：

| 类型 | 包含内容 |
| --- | --- |
| **经典** | 您账户的完全访问权限——“对您当前所属的每个组织和每个项目，以及您未来创建或加入的每个项目，拥有所有权限” |
| **限定范围**（前缀 `sbp_fc`） | 仅包含您选择的组织、项目和权限 |

建议优先使用限定为单个开发项目的限定范围令牌。请注意，限定范围仅能缩小您自身账户可执行的操作范围；它永远不会授予更多权限。请参阅 Supabase 的 [个人访问令牌文档](https://supabase.com/docs/guides/platform/personal-access-tokens)。

## 连接 Supabase

1. 打开 **连接器** 并选择 **Supabase**。
2. 阅读主按钮上方的访问说明行。它说明了连接以谁的身份登录以及哪些智能体可以使用它。若要选择不同身份、缩小智能体范围或使用其他登录方法，请选择 **更改**。
3. 检查您将如何执行身份验证。设置默认从 **使用 Supabase 登录**（浏览器登录）开始。若要改为粘贴上述个人访问令牌，请选择 **更改** 并选择 **使用 API 密钥**。
4. 设置下方的范围控制项。**只读模式** 位于 **更改** 下，与其他高级设置在一起，默认关闭，除非您手动开启。
5. 完成设置。

## 限定连接范围

| 控制项 | 建议 |
| --- | --- |
| **项目引用** | 必填。将连接范围限定为单个开发项目 |
| **只读模式** | 除非智能体确实需要更改数据库，否则请开启 |
| **功能组** | 可选，用于缩小暴露的工具组范围 |

**项目引用在两种方法中均为必填字段。** Supabase 自身的 MCP 端点可能接受不带项目的请求，但 Paperclip 不允许您在未提供项目引用的情况下完成设置——因此，“此连接仅触及一个项目”的姿态是此处唯一可用的选项。这是有意为之。

只读模式是另一个值得提前做出的决定。在智能体已经拥有写入工具之后才开启只读模式，无法撤销其已执行的操作。

> **注意：** 只读模式和功能组作为请求参数传递给 Supabase 的 MCP 服务器——由 Supabase 强制执行，而非 Paperclip。您实际看到的效果是工具列表变窄，但强制执行边界在于提供商。Paperclip 自身对运行内容的控制在于操作设置。

## 选择访问权限

项目访问范围属于 Supabase 账户，并由您设置的项目引用进一步缩小。组织和项目权限属于 Supabase，而非 Paperclip——拥有组织所有者权限的账户会将这些权限带入连接。

请明确此处写入访问权限的范围。它不仅限于插入行：根据暴露的工具不同，它可能包括架构更改和项目配置。这些操作无法从 Paperclip 中撤销。

至少将写入操作保留为 **先询问**，对于涉及架构的任何操作，建议优先设置为 **关闭**。请参阅 [设置操作权限](action-permissions.md)。

## 试用

请使用元数据读取，而非针对真实数据的查询：

```txt
List the tables in the Supabase project and tell me how many there are. Do not query any row data or change anything.
```

预期结果是与项目匹配的表列表。元数据读取可在不请求行内容的情况下确认凭据和项目范围。架构和表名仍可能敏感，且元数据请求仍会消耗提供商资源。

请勿通过迁移、架构更改或特权 SQL 语句进行验证。

> **注意：** 此为示例任务，非记录的测试结果。

## 故障排查与限制

| 问题 | 可能原因 | 解决方法 |
| --- | --- | --- |
| 设置无法完成 | **项目引用** 为空；此项为必填 | 从项目的 Supabase 设置中复制项目引用 |
| 密钥被拒绝 | 粘贴了项目 anon 或 service-role 密钥，而非个人访问令牌 | 在账户访问令牌下创建个人访问令牌并使用该令牌 |
| 令牌有效但无法访问某项目 | 限定范围令牌未包含该项目，或您的账户无权访问该项目 | 扩大令牌的范围，或在 Supabase 中授予该账户访问权限 |
| 缺少写入工具 | **只读模式** 已开启，且 Supabase 正在遵守该设置 | 这是推荐的姿态；仅在有意情况下关闭 |
| 发生了未预期的架构更改 | 写入工具默认启用且该操作被允许 | 开启只读模式，或将架构工具设置为 **关闭**；使用 Supabase 自身的备份进行恢复 |
| 身份验证成功但项目不可见 | 账户无权访问该项目 | 在 Supabase 中授予访问权限 |
| 查询失败或超时 | Supabase 项目限制，而非 Paperclip | 检查项目的套餐和资源限制 |
| **需要关注** | 密钥已被撤销或登录已过期 | 选择 **重新连接** |

限制：每个连接始终仅限一个项目。Paperclip 无法回滚数据库更改——恢复依赖于 Supabase 的备份。只读模式是 Supabase 遵守的请求，而非 Paperclip 的保证，且它不能替代使用开发项目。

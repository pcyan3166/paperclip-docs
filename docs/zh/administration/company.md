# 公司管理

每个 Paperclip 公司都有一个小型界面集群，用于控制其身份、成员资格和可移植性。作为Paperclip 控制台用户（或拥有相应权限的成员），您将在这些页面中设置公司名称和徽标，决定谁可以登录，分发邀请链接，审核加入请求，并将整个公司移入或移出一个可移植包。CEO 智能体从不接触这些功能——这是刻意保留给人类操作者的领域。

本指南将按照您通常遇到这些界面的顺序，逐一介绍：**常规设置**、**连接**、**成员**（其**邀请**选项卡现在与成员列表并列）、**加入请求**、**导出**和**导入**。如果您想了解招聘审批本身的工作方式，请参阅[审批指南](../guides/day-to-day/approvals.md)。如果您想理解位于成员模型之下的报告树结构，请参阅[组织结构](../guides/org/org-structure.md)。

<a id="general-settings"></a>
## 常规设置

**常规**页面汇集了适用于整个组织而非单个智能体或项目的设置。打开**设置**，**常规**是设置侧边栏中的第一项——这是您默认落地的位置。

公司和实例设置现在共享同一导航，因此实例范围的常规控制也出现在这里。在组织部分下方，您会找到部署和身份验证就绪摘要、日志脱敏、备份保留、AI 反馈共享，以及一个**退出登录**按钮（除非操作员已将其隐藏）——有关每项功能的具体说明，请参阅[设置](./settings.md#instance-general)。键盘快捷键不再是一个设置项——对于每个已登录用户，它们[始终开启](./settings.md#keyboard-shortcuts)。以下部分涵盖组织特定的设置。

![常规设置页面，显示组织名称、描述和徽标字段](../../user-guides/screenshots/light/company/settings.png)

### 名称和描述

**常规**部分包含两个字段：

- **组织名称** — 显示在组织切换器和整个 UI 中的显示名称。
- **描述** — 显示在组织个人资料上的可选单行描述。如果不需要，请留空。

更改在您点击**保存更改**之前不会持久化。保存按钮仅当其中一个字段被修改时才会出现，如果名称为空，该按钮将被禁用。

### 徽标

**外观**部分控制代表您组织在侧边栏和切换器中的小方形图块：

- **徽标** — 上传 PNG、JPEG、WEBP、GIF 或 SVG 文件。上传后，文件输入框旁会出现一个**移除徽标**按钮，以便您再次清除它。如果上传失败，错误消息将内联显示。

当未设置徽标时，Paperclip 会绘制一个自动生成的图案图标，其色调由组织名称派生——没有单独的品牌颜色设置可供选择。字段的左侧会渲染图块的实时预览，以便您在保存前查看结果。

### 招聘

**招聘**部分包含一个开关：

- **新招聘需董事会审批** — 开启时，CEO 或经理尝试招聘的每个智能体都将保持待定状态，直到董事会成员从审批队列中批准。关闭时，招聘立即通过。这直接关联到[审批指南](../guides/day-to-day/approvals.md)中描述的流程。

该开关立即保存；此设置没有单独的保存按钮。

### 交互治理

**交互治理**部分为每种交互卡片类型（建议任务、问题、确认等）设置默认情况下谁可以响应以及允许的最严格受众。每种类型都有一个**默认策略**和一个**上限**。有关两者如何协同工作，请参阅[设置公司范围的交互治理](../guides/day-to-day/issues.md#setting-company-wide-interaction-governance)。

### 决策模型

除非实例管理员已开启**实验性快速响应**，否则**决策模型**部分也位于**常规**页面，在**交互治理**下方。这是您选择 Paperclip 用于可选小模型决策的共享 OpenAI 或 OpenRouter API 连接的地方。当快速响应开启时，该部分移至**连接**页面。有关设置、测试以及用量的显示位置，请参阅[成本和预算 → 决策](../guides/day-to-day/costs.md#decisions)。

### 反馈共享、导出和导入

此页面上不再有组织级别的反馈开关。点赞/点踩投票是否可以将 AI 输出发送给 Paperclip Labs，现在是同一页面更下方的实例范围**AI 反馈共享**设置——请参阅[设置](./settings.md#ai-feedback-sharing)。

旧的**公司包**快捷方式也已消失。**导出**和**导入**现在是设置侧边栏中的独立项目，它们打开本指南最后两个部分所涵盖的页面。

### 危险区域

页面底部有一个**危险区域**，其中包含一个**归档组织**按钮。归档会将组织从侧边栏中隐藏，并在数据库中持久化该更改。在归档生效之前会出现确认对话框，如果有可用的下一个非归档组织，UI 会自动将您切换到该组织。

归档还会使公司静默，使其停止在后台执行工作：每个活动智能体都会被暂停（暂停原因为 `company_archived`），任何排队中或进行中的唤醒请求都会被取消。归档不是破坏性的——与删除不同，您的智能体、项目和问题都会被保留——但在您恢复它之前，公司不会再次唤醒其智能体。

## 连接

仅当实例管理员开启**实验性快速响应**时，**连接**页面才会出现在设置导航中。它包含两个部分：

- **决策模型** — Paperclip 用于可选小模型决策的共享连接。请参阅[成本和预算 → 决策](../guides/day-to-day/costs.md#decisions)。
- **快速响应** — 发布简短确认的连接。请参阅[成本和预算 → 快速响应](../guides/day-to-day/costs.md#fast-responses)。

<a id="members"></a>
## 成员

**成员**页面是管理人类成员资格的地方：谁属于该组织，他们持有什么角色，以及在该角色之上他们拥有哪些权限。从**设置 → 成员**打开，或直接从侧边栏打开。该页面包含两个选项卡——**成员**（在此处介绍）和**邀请**（在下一节介绍）——它们过去是单独的页面，现在并列显示。

![成员列表](../../user-guides/screenshots/light/company/access.png)

### 角色

Paperclip 使用四种人类成员角色。角色决定一组隐式权限授予：

- **所有者** — 完全的公司访问权限。包括创建智能体和技能，管理执行环境，邀请人类和智能体，管理成员和权限，分配任务，批准加入请求，以及管理工具和 MCP 设置——连接、运行时槽位、网关和测试调用。
- **管理员** — 拥有邀请和审批权限的操作员。可以像所有者一样创建智能体和技能，管理执行环境，邀请用户，分配任务，批准加入请求，并管理工具和 MCP 设置（连接、运行时、网关和测试调用）。管理员不能做而所有者能做的一件事是管理其他成员的权限。
- **操作员** — 协助运行工作的动手成员。可以编辑公司的工作——创建智能体和技能，管理执行环境，邀请人员，分配任务，编写流水线，使用和管理工具连接，以及查看智能体操作审计流——但不能批准加入请求或管理成员权限。
- **查看者** — 只读访问。没有内置授予。

编辑对话框中的角色下拉菜单也接受**未设置**，这将使成员没有任何隐式授予。

有关每个角色默认授予的确切列表，以及每个权限键控制的内容，请参阅[角色与权限](./roles-and-permissions.md)。

> **注意：** Paperclip 的智能体指挥链（CEO、经理、下属）与这些人类角色是分开的。人类角色限制对 Paperclip UI 和公司级别操作的访问；智能体角色描述公司内部的报告树。有关智能体方面，请参阅[组织结构](../guides/org/org-structure.md)。

### 成员列表

成员部分为每个人类成员显示一行，包含：

- **用户账户** — 显示名称和电子邮件（如果两者都未设置，则显示主体 ID）。
- **角色** — 人类成员角色，或“未设置”。
- **状态** — `active`、`pending` 或 `suspended`，渲染为彩色徽章。
- **权限** — 附加到成员的显式权限授予的逗号分隔摘要。当成员仅依赖隐式角色授予时，显示“无显式权限”。
- **操作** — 一个**编辑**按钮，打开成员编辑器。

如果您没有管理成员的权限，Paperclip 会用一条解释原因的消息替换页面主体。查看该页面但没有活动公司成员资格的实例管理员会看到一个横幅，指出当前账户具有管理员级别的访问权限，但不是该公司的成员。

### 编辑成员

点击**编辑**会打开一个包含三个控件的对话框：

1. **公司角色** — 与上述相同的角色列表，加上“未设置”。
2. **成员状态** — `Active`、`Pending` 或 `Suspended`。
3. **权限** — 显式权限授予的双列网格。网格上方的只读面板列出了所选角色隐式提供的权限。在此处勾选一个框会将权限显式存储在成员上，因此即使角色后来更改，它也会持久化。

您最常使用的键是 `agents:create`、`skills:create`、`environments:manage`、`users:invite`、`users:manage_permissions`、`tasks:assign`、`tasks:assign_scope`、`tasks:manage_active_checkouts`、`pipelines:write`、`audit:view_agent_actions` 和 `joins:approve`。每个框都标有人类名称及其底层键以供参考。其中两个——`tasks:assign_scope` 和 `tasks:manage_active_checkouts`——从不作为角色隐式授予的一部分，因此成员获得它们的唯一方法是在此处勾选框。`pipelines:write` 和 `audit:view_agent_actions` 仅随操作员角色提供，因此在此处勾选它们以授予其他人。有关键的完整列表、每个键限制的内容以及默认包含它的角色，请参阅[角色与权限](./roles-and-permissions.md)。

点击**保存访问**以持久化更改，或点击**取消**以不保存而关闭对话框。

### 添加和移除成员

成员页面没有“添加成员”按钮。新人类通过下一节描述的邀请流程进入组织，一旦接受即成为成员。要移除人类，通过编辑对话框将其**状态**设置为 `suspended`；该行保持可见，以保留审计轨迹。

### 待定的人类加入

如果您持有 `joins:approve` 权限且有待定的人类加入请求，**待定的人类加入**卡片将出现在成员列表上方。每个条目显示请求者的名称、电子邮件和邀请上下文，并带有**批准人类**和**拒绝人类**按钮。此卡片复制了适用于人类的加入请求队列的子集——完整覆盖（包括智能体加入）位于队列页面。

<a id="invites"></a>
## 邀请

成员页面的**邀请**选项卡为新人类创建邀请链接。每个链接是一次性的——首次成功使用会消耗该链接。接受邀请的人一旦登录即获得所选角色；只有智能体邀请仍会创建需要某人批准的加入请求。

![邀请选项卡，邀请人员卡片及其角色选择位于邀请历史上方](../../user-guides/screenshots/light/company/invites.png)

### 创建邀请

**邀请人员**卡片有一个必填选择，在**选择角色**下：邀请应授予哪个角色。选项是上述四种角色——**查看者**、**操作员**（默认）、**管理员**和**所有者**——每个都带有简短描述和该角色获得内容的一行摘要。

点击**创建邀请**会执行三件事：

1. 针对当前 Paperclip 域生成一个新的邀请链接。
2. 如果浏览器允许，将 URL 复制到您的剪贴板。
3. 在表单下方的**最新邀请链接**面板中显示该邀请。

如果剪贴板不可用，Paperclip 会显示一个警告提示。使用 URL 旁边的**复制链接**按钮，或从字段中手动复制。

### 邀请过期和状态

邀请链接有四种可能的状态，在历史表中显示为徽章：**活动**、**已接受**、**已过期**和**已撤销**。只有 `Active` 邀请可以被消耗——链接在首次使用时变为 `Accepted`，并可以从同一页面手动 `Revoked`。

### 邀请历史

创建器下方是一个分页的**邀请历史**表，每个邀请一行：

- **状态** — 上述徽章。
- **对象** — 邀请对象：对于人类邀请，是其授予的角色；对于智能体邀请，是**智能体**。
- **邀请人** — 创建邀请的人类的名称和电子邮件。
- **创建时间** — 创建时间戳。
- **加入请求** — 如果邀请已产生请求，则指向加入请求队列的**审核请求**链接。
- **操作** — 对于仍处于 `Active` 状态的邀请，有一个**撤销**按钮。

该表每次显示五个邀请，当有更多页面时包含一个**查看更多**按钮。标题中的**打开加入请求队列**链接跳转到完整队列。

### 被邀请者看到的内容

当人类打开邀请 URL 时，他们会落在 Paperclip 加入页面上。一旦他们登录并接受，他们立即以邀请携带的角色（例如**操作员**）加入组织——没有单独的审批步骤。智能体邀请的工作方式不同：它们创建加入请求，智能体在拥有 `joins:approve` 的人批准之前不会加入。

## 加入请求

**加入请求队列**整合了针对该组织收到的所有加入请求——人类和智能体。从 `/inbox/requests` 打开，或从邀请选项卡上**邀请历史**中的**打开加入请求队列**链接打开。由于人类邀请现在在接受时立即授予访问权限，因此到达这里的大多数是智能体请求。

![加入请求队列及其状态和请求类型过滤器；当没有等待项时列表为空](../../user-guides/screenshots/light/company/join-requests.png)

### 过滤器

列表上方有两个下拉菜单：

- **状态** — `Pending approval`（默认）、`Approved` 或 `Rejected`。
- **请求类型** — `All`、`Human` 或 `Agent`。

更改任一过滤器都会刷新列表。“已批准”和“已拒绝”在您需要审核过去决策时很有用。

### 每张卡片上的内容

每个请求卡片显示：

- 一个**状态**徽章（`pending approval`、`approved` 或 `rejected`）、一个**请求类型**徽章（`human` 或 `agent`），以及对于智能体请求，一个**适配器类型**徽章。
- 请求者的名称和一个次要标识符——人类为电子邮件，智能体为能力或源 IP。
- 一个**邀请上下文**面板，包含邀请的 `allowedJoinTypes` 和默认角色，以及如果附加了邀请消息则显示该消息。
- 一个**请求详情**面板，包含提交时间戳、源 IP 和智能体能力（如适用）。

对于处于 `pending approval` 状态的请求，卡片还显示**批准**和**拒绝**按钮。一旦操作完成，卡片在新状态过滤器下保留在列表中用于审计目的，但不再暴露操作按钮。

### 权限

队列需要 `joins:approve` 权限。没有该权限的账户会看到一条“您没有权限审核此组织的加入请求。”消息，而不是列表。

## 导出

**导出**页面将当前组织——其智能体、项目、任务、技能和设置——转换为可下载的 zip 可移植 markdown 包。它是一个完整页面，而不是对话框：从设置侧边栏中的**导出**打开，或从组织结构图上方的**导出组织**按钮打开。

![导出页面，左侧为包文件树，右侧为文件预览](../../user-guides/screenshots/light/company/export.png)

### 包含的内容

页面加载时，Paperclip 构建所有将被导出内容的预览。预览渲染为左侧的**包文件**树，右侧为选中文件的预览。

在树的顶部，**包含什么**为每个类别提供一个复选框：**智能体**、**项目**、**技能**、**例程**、**任务**和**附件**。智能体、项目和技能默认勾选。任务、例程和附件默认未勾选——因为任务历史和例程历史可能很大，所以是可选的——如果您希望包中包含这些历史，请勾选它们。**附件**随任务和例程一起传输，因此直到勾选其中之一之前，它保持灰色。

页面顶部的栏显示：

- 组织名称和您正在导出的文件数量，以及估计的 zip 大小。
- 当预览标记出您在下载前应该查看的内容时，显示一个琥珀色警告计数（例如，`2 warnings`）。
- 一个**未包含在此导出中**的通知，列出永远不会进入包的内容（例如审批、成本事件和活动日志条目）。
- 一个**导出 N 个文件**按钮，用于下载 zip。

### 选择导出内容

文件树中的每个条目都有一个复选框。取消勾选文件或目录会将其从下载中移除。有几个值得了解的细节：

- 树可以通过其上方的输入框进行搜索。搜索会自动展开匹配的目录，并在您清除查询时恢复先前的展开状态。
- `README.md` 和 `.paperclip.yaml` 是即时重新生成的，因此它们始终反映当前选择。
- `tasks/` 目录是分页的——默认显示十个条目，并带有**显示更多任务**按钮。已勾选和搜索匹配的任务始终固定在首屏上方。
- 点击文件会在预览窗格中打开其内容。URL 会随导航更新，因此您可以深度链接到导出中的特定文件。

### 下载

点击**导出 N 个文件**以构建最终包。Paperclip 使用过滤后的文件（包括重新生成的 README 和 `.paperclip.yaml`）组装 zip 并触发浏览器下载。成功提示确认文件计数和 zip 的根路径。

有关每个文件中包含内容的更深入描述，请参阅[导出与导入](../guides/power/export-import.md)。

## 导入

**导入**页面是反向操作：它接受导出的包并将其加载到 Paperclip 中，作为新组织或叠加在现有组织之上。从设置侧边栏中的**导入**打开，或从组织结构图上方的**导入组织**按钮打开。

![导入页面，包含导入源、目标和冲突策略控件](../../user-guides/screenshots/light/company/import.png)

### 选择源

**导入源**部分支持两种源类型：

- **GitHub 仓库** — 粘贴指向包含 `COMPANY.md` 的文件夹的树或 blob URL。
- **本地 zip** — 上传从 Paperclip 导出的 `.zip` 包。Paperclip 警告不要在 Finder 或 Explorer 中重新压缩存档；请使用导出页面的下载文件。

### 选择目标

**目标**下拉菜单有两个选项：

- **创建新组织** — 默认。可选的**新组织名称**字段允许您覆盖包中的名称。
- **现有公司：*名称*** — 将包应用于当前选中的组织之上。

### 冲突策略

**冲突策略**下拉菜单控制当传入项与目标公司中已存在的内容发生冲突时发生什么：

- **冲突时重命名** — 默认。Paperclip 为每个冲突实体建议一个新名称（以包名称为前缀，例如 `gstack-CEO`）。
- **冲突时跳过** — 保留现有项，丢弃传入副本。
- **替换现有** — 用传入版本覆盖当前实体。

### 预览

点击**预览导入**以运行预览而不应用任何内容。预览填充三件事：

1. 一个**重命名**列表，显示每个发生冲突的智能体和项目以及它将重命名为什么。每行有一个自由形式的目标名称输入框、一个**跳过**按钮和一个锁定所选名称的**确认重命名**按钮。
2. 一个**适配器**列表，针对包中的每个智能体，带有可用适配器的下拉菜单。新智能体默认使用与目标公司 CEO 相同的适配器。**配置适配器**按钮展开内联配置表单，以便您在导入运行前设置每个智能体的值（环境、工作目录等）。
3. 一个布局与导出树相同的文件树，但每行都有一个**操作徽章**（`create`、`update`、`skip` 或 `replace`），以便您可以查看 Paperclip 计划对每个文件做什么。将被重命名的目录显示箭头和目标名称。

顶部的粘性栏统计选中的文件数，并显示冲突和错误的数量。

### 应用导入

当您对预览满意时，点击**导入 N 个文件**。如果预览中有错误或没有选择文件，该按钮将被禁用。成功时，Paperclip 刷新公司列表，将您导航到导入（或更新）公司的仪表板，并在包包含侧边栏顺序时恢复导入的侧边栏顺序。

现有公司导入在安全导入路径中是非破坏性的：传入的问题始终作为新问题创建，并且 `replace` 在安全导入中被服务器阻止。如果您需要完全替换，请使用专用的实例管理员流程。

请参阅[导出与导入](../guides/power/export-import.md)获取结构参考——包格式的逐字段描述补充了上述演练。

公司管理涵盖了 Paperclip 中围绕智能体而非位于其内部的部分：身份、成员资格和可移植性。一旦您设置好公司并邀请人员加入，日常工作发生在审批队列、仪表板以及本指南其余部分设置的任务界面中。

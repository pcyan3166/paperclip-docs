# 插件

Paperclip 开箱即用的一些功能——运行智能体、管理任务、调用适配器。它还有许多其他功能并不具备，因为这些功能对于您的特定环境来说过于具体：例如仪表板上的 Hello World 小部件、用于项目工作区的文件浏览器，或针对您恰好使用的第三方服务的冒烟测试运行器。插件就是您添加这些功能的方式。

插件是一个自包含的软件包，安装到 Paperclip 中，运行自己的后台工作进程，并可以向 Paperclip 用户界面贡献自己的页面、小部件和设置。与[智能体适配器](../guides/org/agent-adapters.md)（它教会 Paperclip 如何与新的 AI 模型通信）不同，也与[技能](../guides/org/skills.md)（它是智能体加载到提示词中的可重用指令文档）不同，插件是扩展 Paperclip 本身的软件组件。它拥有自己的代码、自己的进程，以及在 UI 中的独立界面。

> 插件目前处于 Alpha 阶段。运行时和 API 仍在变动中，因此目前请预期会有破坏性变更，并尽可能锁定版本。

## 插件管理器

插件管理器位于 **设置 → 插件** 下。它是安装、启用、禁用、配置和卸载插件的唯一位置。

![插件列表](../../user-guides/screenshots/light/plugins/list.png)

该页面分为两个部分：

- **可用插件** — 随您的 Paperclip 检出（checkout）捆绑提供的插件，从磁盘上的包中自动发现。这包括参考示例插件*以及*当它们作为您检出的一部分时，像 LLM Wiki 这样的一方插件。每个插件都标记为 **Bundled**（捆绑），而那些尚未达到生产就绪状态的插件会带有 **Experimental**（实验性）徽章。这有助于了解插件的功能，并在新实例上对插件运行时进行冒烟测试。
- **已安装插件** — 您在此 Paperclip 实例上安装的所有内容。每一行显示插件名称、其包和版本、简短描述、状态徽章以及快速操作。

### 状态徽章

每个已安装的插件都有一个状态，告诉您运行时正在如何处理它。

| 状态 | 实际含义 |
|---|---|
| **ready** | 插件已安装、已启用，且其工作进程正在运行。这是您期望的稳定状态。 |
| **disabled** | 您（或另一位操作员）关闭了该插件。其工作进程已停止，计划任务不会触发，任何 UI 贡献都被隐藏。配置和数据得到保留。 |
| **error** | 出现问题——工作进程在启动时崩溃、健康检查失败，或升级导致故障。插件行显示简短的错误摘要，以及一个 **View full error**（查看完整错误）按钮，用于查看完整堆栈跟踪。 |
| **upgrade_pending** | 插件的新版本已暂存，且它请求了已安装版本所不具备的能力。Paperclip 将其保持离线状态，直到您批准新的权限。 |
| **installed** | 安装后、首次成功加载前的瞬态状态。您通常不会长时间看到它——插件会在一两秒内转为 `ready`（或 `error`）。 |
| **uninstalled** | 插件已被移除。除非您重新安装，否则它将不再出现在列表中。 |

如果徽章是绿色的，表示正在运行。如果是灰色的，表示有意关闭。如果是红色或琥珀色，请阅读消息——UI 正在告诉您需要关注某些事项。

### 阅读错误行

当插件处于 `error` 状态时，该行会展开以显示简短的错误摘要——存储的错误消息中的第一非空行——以及一个 **View full error**（查看完整错误）按钮。点击它会打开一个对话框，显示完整的堆栈跟踪或失败输出，内容已换行且可滚动。

摘要通常足以让您知道该怎么做：

- **"Cannot find module ..."** 或 **"Failed to load manifest"** — 包格式错误或其构建输出缺失。重新安装它，或者如果您在本地开发，则重新构建它。
- **"Worker exited with code 1"** — 工作进程在启动时崩溃。完整错误中包含堆栈跟踪。最常见的原因：缺少配置（去填写设置表单）、未提供的密钥，或插件依赖的外部服务不可达。
- **"Health check failed: ..."** — 工作进程已启动，但健康检查未通过。消息会指明哪个检查失败；修复根本问题后，点击电源按钮重新启用插件。

处于错误状态的插件保持已安装状态——您无需卸载并重新安装即可重试。一旦解决了原因，点击 **Enable**（启用）会使其经历 `error → ready` 转换，Paperclip 会尝试再次启动工作进程。

## 安装插件

![插件管理器，右上角有安装插件按钮，下方是可用插件列表](../../user-guides/screenshots/light/plugins/install.png)

有两种方式可以自行安装插件。（一小部分沙箱提供程序插件也会在启动时自行到达——见下文*自安装插件*。）

**从可用插件列表。** 捆绑插件包含在 Paperclip 代码库中。在插件管理器页面，滚动到 **可用插件** 部分，点击您想要的那个旁边的 **Install**（安装）。Paperclip 直接从本地检出安装——无需注册表往返。

Paperclip 通过扫描您检出中的插件包来构建此列表，因此您看到的内容取决于捆绑了什么。这里会出现两种类型的插件：

- **参考示例** — 小型、自包含的插件，旨在演示运行时。
- **一方插件** — 当它们被引入您的检出时，像 [LLM Wiki](../reference/plugins/llm-wiki.md) 这样的真实插件。这些也发布到 npm，因此在未捆绑它们的实例上，您将通过完整的包名称进行安装；见下文*通过 npm 包名称*。

仍在成熟中的一方插件在此列表中带有 **Experimental**（实验性）徽章——它们可以工作，但其行为或配置可能在版本之间发生变化，因此请尽可能锁定版本。

目前提供的参考示例：

- **plugin-hello-world-example** — 在仪表板上添加 Hello World 小部件。最小可行插件，可作为参考。
- **plugin-file-browser-example** — 在项目侧边栏添加 Files 链接，并在项目详情页面添加文件浏览器选项卡，范围限定于项目的工作区。
- **plugin-kitchen-sink-example** — 在一个包中演示完整的插件界面：页面、小部件、设置表单、计划任务、Webhooks。适合探索插件能做什么。
- **plugin-authoring-smoke-example** — 针对插件创建工作流的薄型冒烟测试。如果您正在开发自己的插件并希望确认运行时能识别它，这很有用。
- **plugin-orchestration-smoke-example** — 一个冒烟插件，用于测试 Paperclip 的编排级插件 API（计划任务、Webhooks、插件驱动的智能体交互）。当您构建需要随时间协调工作而不仅仅是渲染小部件的插件时，这很有参考价值。

**通过 npm 包名称。** 点击插件管理器右上角的 **Install Plugin**（安装插件）按钮。Paperclip 会要求输入一个 npm 包名称（例如，`@paperclipai/plugin-example`）。提交后，Paperclip 获取、安装并加载该包。成功或失败会以吐司通知（toast）形式显示，插件会以其当前状态出现在已安装列表中。

在这两种情况下，安装流程执行相同的底层工作：下载包，验证其清单，持久化插件记录，然后尝试通过启动其工作进程将其移动到 `installed → ready`。如果该链中的任何环节失败，插件将停留在 `error` 状态，并附带失败消息——它保持已安装状态，以便您可以检查发生了什么，而不是静默消失。

## 自安装插件

少数插件从不等待您点击 **Install**。沙箱提供程序插件——允许智能体在外部计算资源上运行而不是在托管 Paperclip 的机器上运行的那些——需要在第一次智能体运行之前存在，因此 Paperclip 会在服务器启动时配置它们。如果您在新实例上打开插件管理器，发现 **已安装插件** 中已经有一个您没有放置的提供程序，这就是原因。

这曾经是 Kubernetes 专用的快捷方式。现在它是一条通用路径，具有允许其配置的固定插件列表：

| 键 | 安装的插件 |
|---|---|
| `cloudflare` | `paperclip.cloudflare-sandbox-provider` |
| `daytona` | `paperclip.daytona-sandbox-provider` |
| `e2b` | `paperclip.e2b-sandbox-provider` |
| `exe-dev` | `paperclip.exe-dev-sandbox-provider` |
| `kubernetes` | `paperclip.kubernetes-sandbox-provider` |
| `modal` | `paperclip.modal-sandbox-provider` |
| `novita` | `paperclip.novita-sandbox-provider` |

该表是完整的内置允许列表。插件通过自动配置到达的唯一其他方式是发布镜像本身在分发目录中携带它（见下文[自定义镜像中携带的插件](#plugins-shipped-inside-a-custom-image)）。其他所有内容——参考示例、一方插件、第三方包——仍然由您以常规方式安装。

一旦配置完成，这些插件的行为与其他已安装插件相同：相同的状态徽章、相同的详情页面、相同的配置选项卡。您仍然通过 **设置 → 环境** 下的配置沙箱环境来选择是否以及如何使用其中一个。有关每个提供程序的字段，请参阅 [沙箱提供程序](../reference/adapters/sandbox-providers.md)。

### 何时运行，以及您可能看不到的情况

配置在每次启动时发生一次，在 Paperclip 激活已标记为就绪的插件之前——因此，当实例开始处理请求时，新配置的提供程序已安装、`ready`，并正在运行其工作进程。

有两个安静的结果值得了解：

- **捆绑包不在磁盘上。** Paperclip 查找插件的构建捆绑包（捆绑文件夹内的 `dist/manifest.js`），当它不存在时跳过该条目而不报错。本地开发检出，或构建时未包含特定提供程序的镜像，都会落入此情况。没有东西损坏——插件只是不出现。
- **安装或加载失败。** 失败会被记录，启动继续。Paperclip 永远不会因为无法配置的插件而陷入崩溃循环；代价是，直到您解决该问题，此提供程序不可用。因此，如果您期望的提供程序不在列表中，服务器日志中会有原因。

<a id="what-it-wont-undo"></a>
### 它不会撤销什么

自动配置在您已经做出的决策上非常谨慎：

- **已安装？** 跳过。除未安装外的任何状态都算数——包括 `disabled`。关闭已配置的提供程序并重启服务器不会静默地重新开启它。
- **故意卸载了？** 在自托管实例上，这会保持：重启不会恢复它，因此卸载是一个真正的决策，而不是临时的。在云托管实例上，集群拥有配置权，因此卸载的捆绑插件会在下次启动时返回——如果您想永久移除它，请改为禁用它。
- **永远不会自动卸载。** 从实例的配置列表中移除一个键会停止未来的安装；它永远不会移除已经存在的插件。移除始终是由人员从插件管理器执行的操作。

### 如果您自托管

自托管实例自动配置恰好一个键：`kubernetes`。表中的其他每个提供程序都由您在真正需要时安装，可以从 **可用插件** 或通过 npm 包名称。这与该路径通用化之前 Paperclip 的行为没有变化。

两个环境变量允许您将配置指向磁盘上的其他位置，这主要用于开发镜像和测试：

- `PAPERCLIP_BUNDLED_PLUGIN_ROOT` — 重新定位捆绑插件目录根目录。它默认为 `/app/packages/plugins`，即发布镜像内的位置。
- `PAPERCLIP_KUBERNETES_PLUGIN_PATH` — 将 `kubernetes` 条目指向特定捆绑包路径，无论其位于何处。这个条目早于目录存在，保留以兼容。

在云托管实例上，列表来自集群，作为框架交给实例的托管配置文档的一部分（[云托管实例](../reference/deploy/environment-variables.md#cloud-managed-instances) 有详细信息）。该列表经过严格检查：不在上述表中或镜像分发目录中的键，或解析到目录根目录之外的捆绑包路径，会导致实例拒绝启动，而不是将意外内容加载到主机中。在启动时大声失败是目的所在。

<a id="plugins-shipped-inside-a-custom-image"></a>
### 自定义镜像中携带的插件

如果您构建自己的 Paperclip 镜像——用于托管集群或内部分发——您可以在其中携带额外的预构建插件，而无需将它们添加到 Paperclip 的内置表中。将每个插件的构建包放在捆绑插件目录根目录下的 `distribution` 目录中的独立文件夹中，并在 `distribution/catalog.json` 中列出它们。每个条目命名插件的 `key`、其 `pluginKey`、确切的 `version`、它所在的 `directory`，以及一个 `digest`（`sha256:` 后跟文件夹文件的哈希值）。

Paperclip 在运行任何插件代码之前检查目录。文件夹内容必须与摘要匹配，包的版本和插件 ID 必须与条目匹配，其入口点必须已构建，且其中任何内容都不得是符号链接。条目不能重用内置插件的键或插件 ID。如果其中任何一项失败，Paperclip 不会加载该插件——对于错误的目录、摘要、版本或入口点，服务器拒绝启动，而不是加载它无法保证的内容。一旦条目通过，其 `key` 可以像任何内置键一样进入实例的自动安装列表。

升级镜像会就地升级这些插件，但有一个保障措施：如果新版本请求已安装版本所不具备的能力，插件将进入 `upgrade_pending` 状态，并保持离线，直到操作员在插件详情页面批准它——就像任何其他升级一样。禁用的插件保持禁用状态，在自托管实例上，某人故意卸载的插件保持卸载状态。

## 启用和禁用

每个已安装插件的操作列中都有一个电源按钮。该按钮在两个生命周期转换之间切换：

- **Disable**（禁用）（当插件为 `ready` 时） — Paperclip 停止工作进程，取消插件拥有的任何进行中的计划任务，并隐藏插件的 UI 贡献。您的配置和插件存储的任何数据得到保留。
- **Enable**（启用）（当插件为 `disabled`、`error` 或 `upgrade_pending` 时） — Paperclip 再次启动工作进程，如果启动成功，则将插件移回 `ready`。

当插件行为异常、您想暂时暂停其计划任务，或者您即将更改某些外部依赖且希望插件在此期间不触发时，禁用是正确的操作。这是一个安全、可逆的操作——将其视为“睡眠”而非“移除”。

### 卸载

电源按钮旁边的垃圾桶图标移除插件。Paperclip 要求您确认，因为该操作在 UI 中不可逆：插件包从磁盘移除，安装工件被清理，插件被标记为未安装。要恢复插件，您需要重新安装。

卸载首先停止工作进程，方式与禁用相同，因此在移除包之前，进行中的工作会被干净地排空。

### “禁用”实际停止了什么

值得明确说明，因为这是“我暂停一小时”和“我需要重新开始”之间的区别：

- **已停止：** 工作进程、计划任务运行、Webhook 传递处理、UI 贡献（页面、小部件、设置槽位），以及任何健康检查轮询。
- **已保留：** 插件记录本身、保存的配置（包括密钥）、历史任务运行和 Webhook 传递记录，以及日志条目。当您重新启用插件时，一切将从中断处恢复，使用相同的配置。

这对于集成计费服务的插件很重要。禁用会停止轮询和计划工作——因此您停止支付 API 费用——而无需在下次重新开启时重新输入凭据。

### 当服务器无法访问时

如果 Paperclip 服务器短暂不可达，侧边栏中的插件项目保持安静：它们继续显示最后加载的内容，而不是错误。在应用的其他地方，加载失败的插件区域显示 **Plugin extensions unavailable**（插件扩展不可用）或 **Plugin launchers unavailable**（插件启动器不可用）及原因，以便您知道为什么它是空的。

## 升级

当插件升级到新版本时，Paperclip 将新清单中声明的能力与您最初批准的能力进行比较。

- 如果新版本请求相同或更少的能力，Paperclip 就地升级它，插件在新版本上返回 `ready`。
- 如果新版本请求之前没有的**新**能力——访问新的数据表面、新的集成点——Paperclip 将插件停在 `upgrade_pending`。工作进程保持停止，直到操作员查看更改内容。

要应用待批准的升级，打开插件详情页面，审查更新的能力和描述，然后点击 **Enable**（启用）。这将插件移回新版本上的 `ready`。如果您对新能力不满意，可以无限期地将插件留在 `upgrade_pending`，或卸载它。

此门控的存在是为了防止插件在版本之间悄悄增加权限。第一次请求能力始终是您采取的有意行动。

## 插件详情页面

点击插件名称——或其 **已安装插件** 行上的 **Configure**（配置）按钮——会打开插件详情页面。您已安装的捆绑插件在 **可用插件** 列表中也会获得一个 **Open Settings**（打开设置）按钮（在插件不是 `ready` 时显示为 **Review**（审查）），它前往同一页面。这是插件在 Paperclip 内部向您展示其自身界面的地方。

![插件详情页面，名称旁有状态和版本徽章，下方有配置和状态选项卡](../../user-guides/screenshots/light/plugins/detail.png)

详情页面有两个选项卡：

- **Configuration**（配置） — 插件的描述、作者、类别和设置表单（或插件提供的自定义设置 UI）。
- **Status**（状态） — 运行时诊断：工作进程状态、最近的计划任务、最近的 Webhook 传递、实时健康检查，以及最近条目的滚动日志。右侧列添加 **Details**（详情）和插件的 **Permissions**（权限）。

插件还可以声明一个 **page slot**（页面槽位）。当它这样做时，插件在 `/<company-prefix>/plugins/<plugin-id>` 处获得自己的路由，并在那里渲染它想要的内容——完整页面、仪表板、多步流程。这就是像文件浏览器示例那样向项目页面添加 Files 选项卡的方式，或者假设的 CRM 插件可能向侧边栏添加 Contacts 视图的方式。

作为操作员，从您的角度来看，插件页面表现得像任何其他 Paperclip 页面：它们限定于当前选择的公司，出现在面包屑导航中，并尊重您的权限。插件只是获得一个渲染画布。

插件还可以贡献较小的部分——仪表板上的小部件、项目详情页面上的选项卡、侧边栏中的链接——而不是完整的独立页面。这些出现在您已使用的界面中，因此您并不总是需要导航到插件详情页面才能从中获得价值。Hello World 示例添加仪表板小部件；文件浏览器示例添加项目选项卡；kitchen-sink 示例将贡献分散到多个界面，以便您可以看到可能性。

如果两个插件碰巧在同一路由上贡献页面，Paperclip 拒绝在它们之间选择，而是显示冲突消息。卸载其中一个冲突插件，或使用插件 ID URL 直接（`/<prefix>/plugins/<plugin-id>`）访问特定插件，直到您解决该问题。

## 插件设置

大多数插件有一些配置：API 密钥、基础 URL、默认文件夹、监视的仓库列表。Paperclip 为插件提供两种向您展示这些配置的方式。

![插件的配置选项卡，关于卡片在设置表单上方](../../user-guides/screenshots/light/plugins/settings.png)

**自动生成表单。** 如果插件提供描述其配置的 JSON Schema，Paperclip 会在配置选项卡上自动渲染表单。您填写字段，点击 **Save Configuration**（保存配置），Paperclip 安全地存储值。对于支持的插件，保存旁边会出现 **Test Configuration**（测试配置）按钮——它将当前表单值发送到插件的工作进程，并报告配置是否有效，而不持久化任何内容。

**自定义设置页面。** 插件也可以通过 `settingsPage` 槽位贡献自己的设置 UI——多步向导、可视化编辑器、连接构建器。当存在时，Paperclip 渲染插件的自定义 UI 而不是自动生成的表单。所有内容仍然位于相同的配置选项卡下，因此您始终知道在哪里查找。

### 密钥

插件标记为密钥的字段（API 密钥、令牌、密码）以加密方式存储，绝不以纯文本重新显示。一旦保存了密钥，表单显示掩码占位符；要更改它，输入新值并再次保存。保持掩码占位符不变会保留现有密钥。

### 权限卡片

**Permissions**（权限）卡片位于插件的 **Status**（状态）选项卡上，在右侧列的 **Details**（详情）下方。它按能力名称列出插件清单声明的能力，每行一个（例如 `issues.read` 或 `projects.read`）。如果插件不请求任何能力，卡片显示 *No special permissions requested.*（未请求特殊权限）。这些是 `upgrade_pending` 门控在升级时检查的相同能力。如果插件的权限列表与认为它应该做的事情不匹配，这是启用前进行调查的信号。

## 任务、Webhooks 和日志

插件不仅仅坐在那里。许多插件运行计划任务——每 15 分钟同步一次、每晚对账、每周日清理一次——或从外部服务接收 Webhooks。插件详情页面中的 **Status**（状态）选项卡是您看到这些活动的地方。

![插件的状态选项卡，运行时仪表板显示工作进程、最近的任务运行和最近的 Webhook 传递](../../user-guides/screenshots/light/plugins/jobs-log.png)

该选项卡显示以下内容。前三个一起位于 **Runtime Dashboard**（运行时仪表板）卡片中；健康和日志拥有自己的卡片。

- **Worker Process**（工作进程） — 工作进程是否在运行、其进程 ID、正常运行时间，以及它从多少次崩溃中恢复。如果工作进程反复崩溃，崩溃计数和最后崩溃时间戳会在此处显示，早于 UI 其余部分看起来损坏之前。
- **Recent Job Runs**（最近任务运行） — 插件触发的最后几个计划任务，每个都有状态点（绿色成功、红色失败、蓝色运行中、灰色已取消、琥珀色排队）、导致它的触发器，以及相对时间。绿色状态点和较短的运行时长表示插件运行正常，这是您希望看到的常态。
- **Recent Webhook Deliveries**（最近 Webhook 传递） — 传入的 Webhooks，每个都有状态和持续时间。在调试未触发的集成时很有用。
- **Health Status**（健康状态） — 聚合检查结果，在插件为 `ready` 时每 30 秒轮询一次。如果特定检查失败（例如，“可以到达外部 API”），您会在此处看到它被指出，早于它变成崩溃之前。
- **Recent Logs**（最近日志） — 工作进程发出的最后 50 条日志条目，按级别着色。这是当某些东西看起来不对劲时的第一站。

整个选项卡每 30 秒刷新一次，因此您可以在 Paperclip 的其他地方调整配置或触发手动运行时保持它打开。

### 解释任务状态点

每个任务运行旁边的彩色点概括了结果：

- **绿色** — 任务成功。以预期节奏稳定流动的绿色点是健康插件的样子。
- **蓝色（脉冲）** — 任务正在运行。如果蓝色状态持续时间异常，请检查下方的“最近日志”面板。
- **琥珀色** — 任务排队，等待工作进程拾取。短暂的琥珀色没问题；持续的琥珀色通常意味着工作进程繁忙或卡住。
- **红色** — 任务失败。具有匹配时间戳的日志条目会有原因。
- **灰色** — 任务已取消，通常是因为您在计划期间禁用了插件。

Webhook 传递点遵循类似的颜色：绿色表示已处理，蓝色表示已接收，琥珀色表示待定，红色表示失败。

## 编写您自己的插件

如果没有已安装的插件满足您的需求，您可以编写一个。插件是具有 `paperclipPlugin` 清单块、工作进程入口和可选 UI 捆绑包的 npm 包——`packages/plugins/examples/` 下的示例插件是一个很好的起点。

完整的创建路径位于本指南之外：

- `paperclip-create-plugin` 技能为新的插件包搭建脚手架，包括清单、工作进程和最小 UI 界面。
- Paperclip CLI（`paperclipai`）封装了常见的创建任务——脚手架、开发服务、构建和发布。有关详细信息，请参阅 [CLI 概述](../guides/getting-started/your-first-agent.md) 和主 Paperclip 代码库中的插件适配器文档。

一旦您的插件构建完成，在插件管理器页面上使用 **Install Plugin**（安装插件）以与其他任何插件相同的方式安装它。在开发期间，您还可以将安装器指向本地路径——捆绑的 **Install**（安装）流程是相同的机制，只是针对您检出内的包。

### 在本地开发插件

如果您正在迭代自己的插件而不是运行已发布的插件，最友好的循环是 CLI 驱动的本地路径安装：`paperclipai plugin init` 搭建包，`pnpm dev` 运行监视构建，`paperclipai plugin install <path>` 将 Paperclip 指向文件夹，以便每次 `dist/` 被重写时工作进程重新加载。

有关完整演练，请参阅 **[在本地开发插件](../how-to/develop-a-plugin-locally.md)** — 脚手架标志、重新加载语义、何时切换回 npm 安装，以及当编辑不再到达 Paperclip 时的故障排除检查清单。

## 准备就绪

插件为您提供了一种扩展 Paperclip 本身的方式——新页面、新小部件、新计划工作——而无需分叉代码库。安装您需要的，保留您不需要的禁用状态，并让详情页面告诉您何时需要关注某些事项。

如果您希望扩展单个智能体可以*做*的事情，而不是 Paperclip 可以*显示*的事情，接下来请参阅 [技能](../guides/org/skills.md) 和 [智能体适配器](../guides/org/agent-adapters.md)。

## 快速参考

日常操作插件管理器的速查表：

| 目标 | 操作 |
|---|---|
| 尝试捆绑插件 | 插件管理器 → 可用插件 → **Install**（安装） |
| 安装第三方插件 | 插件管理器 → **Install Plugin**（安装插件） → 输入 npm 包名称 |
| 暂时停止插件的任务 | 点击插件行上的电源按钮（绿色到灰色） |
| 将插件重新上线 | 再次点击电源按钮，或从详情页面 **Enable**（启用） |
| 修复卡在 `error` 的插件 | 详情页面 → 状态选项卡 → 阅读日志，然后重新启用 |
| 批准请求新权限的升级 | 详情页面 → 状态选项卡 → 审查权限 → **Enable**（启用） |
| 更改配置 | 详情页面 → 配置选项卡 → 编辑表单 → **Save Configuration**（保存配置） |
| 在提交前验证配置 | 详情页面 → 配置选项卡 → **Test Configuration**（测试配置）（当可用时） |
| 永久移除插件 | 插件行上的垃圾桶图标 → 确认 |
| 弄清楚为什么插件在您未安装的情况下出现 | 它可能是沙箱提供程序——见*自安装插件* |

如果您卡住了，任何插件详情页面中的状态选项卡是开始的地方——工作进程状态、最近运行和最近日志通常比摆弄配置更快地指向原因。

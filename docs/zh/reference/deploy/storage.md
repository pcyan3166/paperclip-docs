# 存储

Paperclip 通过可配置的存储服务提供商保存附件、截图和其他资源等上传内容。

如果你需要了解文件在本地的存储位置，或要在共享部署中切换到对象存储，请阅读本页。

---

## 存储模式

| 服务提供商 | 适用场景 |
|---|---|
| `local_disk` | 本地开发、单机使用 |
| `s3` | 生产、多节点、云部署 |

> **注意：** 存储配置保存在实例配置文件中，而不在数据库 schema 中。

---

## 本地磁盘

本地安装默认使用此服务提供商。

文件保存在：

```txt
~/.paperclip/instances/default/data/storage
```

无需额外配置。如果实例运行在本地且只有一个节点，建议使用此方式。

---

## 兼容 S3 的存储

如果希望实例表现得像真正的共享部署，请使用兼容 S3 的对象存储。

包括以下服务提供商：

- AWS S3
- MinIO
- Cloudflare R2

通过 CLI 进行配置：

```sh
pnpm paperclipai configure --section storage
```

如果实例可能运行在多台机器上，或本地磁盘的持久性不足，请使用此方式。

---

## 存储的内容

存储层用于保存与公司活动相关的上传文件，包括任务附件和图片。

如果你在查找丢失的上传文件，请同时检查存储服务提供商和实例数据目录。

<a id="persistent-agent-files"></a>
### 持久化智能体文件

智能体的个人文件单独保存在实例文件系统中，不使用上传文件的存储服务提供商。其保存目录为：

```txt
<instance>/companies/<company>/agents/<agent>/instructions/
```

目录中包含智能体的指令入口文件，以及它保存的任何备注、文件夹或二进制文件。托管运行会通过 `AGENT_HOME` 获得一份可写副本；任务工作区文件与其分开。将上传文件存储设为 S3，不会把这些智能体文件迁移到 S3。

请将已保存的智能体目录纳入文件系统备份。仅备份数据库无法恢复这些文件内容；公司导出也不是这些个人存储文件的完整副本。有关限制和同步行为，请参见[智能体](../../guides/org/agents.md#agent-files-persist-across-tasks)；恢复范围见[备份与恢复公司](../../how-to/back-up-and-restore-a-company.md)。

> **提示：** 如果本地上传的文件在重启后消失，请检查你是否运行在容器或其他临时环境中，以及是否正确配置了预期的绑定挂载。

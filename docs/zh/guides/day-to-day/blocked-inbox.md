# 阻塞收件箱

收件箱中的 **阻塞（Blocked）** 标签用于集中分流停滞的工作。其他标签（我的、最近、未读、全部）帮助你查看接下来要处理的内容；阻塞标签则专门列出等待决策、恢复运行、外部人员行动或已暂停负责人的任务，让你在一个地方排除卡点。

![收件箱的阻塞标签列出受阻任务及其等待原因](../../../user-guides/screenshots/light/issues/inbox-blocked.png)

## 打开阻塞标签

阻塞标签与其他收件箱标签并列，网址为 `/inbox/blocked`，可以收藏或分享。点击左侧栏的 **收件箱（Inbox）**，然后选择 **阻塞（Blocked）**。标签栏包含 **我的（Mine）**、**最近（Recent）**、**未读（Unread）**、**阻塞（Blocked）** 和 **全部（All）**。阻塞数量徽标会根据列表中的最高严重级别变色：情况平稳时颜色较淡，高严重级别时为琥珀色，严重级别时为红色。

没有停滞任务时，页面会显示“当前没有停止的工作”，并说明需要决策、恢复或外部操作的任务会出现在这里。

## 阅读阻塞任务

桌面端每一行会显示状态图标、任务标识符、带有阻塞原因标签的标题、需要采取行动的负责人，以及停滞时长（例如 `stopped 2h`、`stopped 3d`）。原因标签映射为以下类型：

| 标签 | 含义 | 建议操作 |
|---|---|---|
| **需要决策（Needs decision）** | 等待董事会或用户决策，或等待选择成功运行后的处理方式 | 打开任务并作出决定 |
| **阻塞链停滞（Blocked chain stalled）** | 一串依赖关系已经停滞，下游任务无法推进 | 沿依赖链找到末端任务，解除阻塞或取消它 |
| **需要关注（Needs attention）** | 阻塞项未分配、仍在待办栏、已取消，或审核流程无效 | 指定负责人、重新启动，或修正审核参与者 |
| **需要恢复（Recovery required）** | 当前工作前面还有未完成的恢复任务 | 先解决恢复任务 |
| **等待外部操作（External wait）** | 需要某位人员或外部负责人行动 | 联系负责人，或通过其他方式解除阻塞 |
| **负责人已暂停（Owner paused）** | 分配的智能体当前无法运行 | 恢复智能体或重新分配任务 |

标签前的彩色圆点表示严重程度：红色为 `critical`，橙色为 `high`；中、低级别仍会列出，但不显示圆点。移动端标题下方会重复显示停滞时长和负责人，避免列收起后丢失这些信息。

## 谁负责解除阻塞

任务进入 **阻塞（Blocked）** 状态时，发起阻塞的一方需要记录 **解除阻塞负责人（unblock owner）**，也就是能够排除卡点的一方，以及一段说明其需要执行操作的 **行动（action）**。这样，阻塞列表可以直接指出下一步由谁负责。

负责人分为三类：

- **指定智能体**：智能体会立即被唤醒一次，并获知任务正在等待它。
- **指定人员**：必须是公司的活跃成员。人员不会被唤醒或收到终端通知，相关任务会显示在其待处理动态中。
- **董事会**：适用于应由董事会集体决定的事项。

由人员负责的阻塞会出现在待处理动态中，而不会唤醒智能体。董事会负责的事项会显示给所有董事会成员，指定人员负责的事项只显示给该人员。它们会作为高严重级别的待决事项出现，并用记录的行动说明为何需要处理。可选择 **解除阻塞（Unblock）**（按钮说明采用记录的行动文字）或 **重新分配（Reassign）**。任务离开阻塞状态后，该事项会从动态中消失。智能体负责的阻塞不会进入该动态，因为智能体已被唤醒。

行动说明为必填纯文本，最多 2,000 个字符。它会出现在之后的待处理动态里，因此应写清楚具体需要做什么，例如“确认试用结束后转入哪个定价档位”，比“需要决定”更有用。

### 阻塞必须有明确原因

只有满足以下至少一项，任务才能进入 **阻塞（Blocked）**：确实在等待未完成或未取消的其他任务；存在待处理的交互或审批；或者已指定解除阻塞负责人和行动。否则，Paperclip 会拒绝状态变更，并提示阻塞任务需要未解决的依赖、待处理交互/审批或 `unblockDescriptor`。

解除阻塞负责人也只能用于阻塞任务；在其他状态下设置会报错 `unblockDescriptor requires blocked status`。

### 智能体可以指定谁

智能体只能指定自己为解除阻塞负责人，不能把事项转给人员、其他智能体或董事会。这样可避免智能体任意向人的待处理动态塞入事项。由董事会发起阻塞时，可以指定任意对象，但智能体必须属于任务所在公司，人员必须是该公司的活跃成员。

### 智能体只会被唤醒一次

每次阻塞时，智能体负责人只会以 `issue_unblock_requested` 原因被唤醒一次；重复处理同一阻塞任务不会反复唤醒。任务离开阻塞状态后，负责人和行动记录都会清除。如果之后再次进入阻塞状态，这是一次新的阻塞，会记录新的负责人和行动，并再次唤醒新负责人。

在 **2026 年 7 月 23 日 18:13 UTC** 之前已处于阻塞状态的任务不会自动补录负责人，也不会因此唤醒人员或出现在待处理动态中。升级时不回填旧任务，是为了避免一次性唤醒大量人员。需要新路由的旧任务可以先移出阻塞状态，再重新设为阻塞。

## 筛选和搜索

阻塞标签沿用问题页面的筛选与搜索功能，详见[问题页面](../../../guides/day-to-day/issues.md)。搜索会匹配标题、标识符、负责人、行动说明、原因，以及关联的末端任务或恢复任务。筛选器可按负责人、创建者、项目、标签、例程可见性和（启用隔离工作区时）工作区筛选；列选择器可显示或隐藏状态、标识符和更新时间等列。

## 分组和排序

阻塞标签额外提供两种控件。**分组依据（Group by）** 可按阻塞类型分组，顺序为：需要决策 → 阻塞链停滞 → 需要关注 → 需要恢复 → 等待外部操作 → 负责人已暂停；每组显示数量，可折叠。也可选择 **无（None）** 查看平铺列表。

**排序依据（Sort by）** 有三种方式：

- **最紧急（Most urgent）**：先按严重程度（critical → high → medium → low），再按停滞时长排序。
- **最近（Most recent）**：按最近一次停滞或更新时间排序。
- **停滞最久（Longest stopped）**：优先显示等待时间最长的任务，适合清理积压。

这两个控件会在你停留于此标签时保留选择。

## 根据阻塞类型采取行动

标签用于提示分流方向，最终仍需查看任务详情：

- **需要决策**：打开任务。如果等待董事会或用户决策，请在讨论区或关联审批中提交决定；如果要选择成功运行后的处理方式，请选择相应选项。
- **阻塞链停滞**：沿任务属性侧栏中的 `blocked by` 依赖链接找到链条末端，解除该任务的阻塞或取消它；后续心跳运行会更新整条链。
- **需要关注**：未分配的阻塞项需要指定负责人；搁置项需要移出待办状态；已取消的依赖需要替换或移除；审核流程缺少操作路径或参与者无效时，需要修正父任务的审核者/批准者。
- **需要恢复**：找到仍未关闭的恢复任务并解决它，父任务之后便可继续运行。
- **等待外部操作**：通过负责人栏联系外部人员，或由你接手处理。
- **负责人已暂停**：恢复被暂停或无法运行的智能体，或重新分配任务。

## 任务详情中的提示

从阻塞标签打开任务后，顶部会显示琥珀色提示，说明任务停滞的原因。若任务仅被搁置在阻塞状态，提示会说明需要有人将其移回“待办”；若它在等待关联任务，则会说明需等依赖完成。评论仍会通知负责人，但不一定会自动改变任务状态。

如果依赖链仍在正常推进，提示会改为蓝色的 **等待正在进行的工作（Waiting on live work）**，显示队列进度和已完成数量。此时无需操作，任务会在依赖链完成后自动恢复。若链条卡在审核中，提示会指出需要解决停滞的审核或将其移出依赖。

关键是：即使任务处于阻塞状态，评论仍会通知负责人。另一个常见情况是任务在待办状态且已分配负责人；此时页面会说明负责人在状态变为“待办”或“进行中”前不会开始处理。

## 数据与待处理动态

服务器会为问题提供可选的 `blockedInboxAttention` 数据。阻塞标签请求 `attention=blocked` 和 `includeBlockedInboxAttention=true`，只显示带有该数据的行。因此，仅有 `status = blocked`、但没有关注信息的任务不会出现在此列表中。收件箱工具栏中的阻塞数量徽标使用相同分类，确保数量与列表一致。

待处理动态也采用相同分类。停滞依赖链以及需要人工查看的依赖链会以高严重级别显示，因此除了阻塞标签外，动态也是发现卡点的入口。

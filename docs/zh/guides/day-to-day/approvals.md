# 审批

即使智能体自主工作，你仍可通过审批掌控公司。没有审批机制，智能体可能在你不知情时招聘成员、确定战略或作出重大决策。审批是治理关卡：执行重要操作前，Paperclip 会暂停并征求你的确认。

可以把它想成董事会席位：智能体负责日常运营，而招聘对象、公司战略等重大事项仍由你决定。

![审批列表显示待处理的审批卡片、类型标签和批准与拒绝按钮](../../../user-guides/screenshots/light/approvals/approvals-list.png)

## 审批类型

### 招聘智能体

CEO 或 CTO 等经理需要下属时，会提交招聘申请，而不能直接创建智能体。申请会进入审批队列，列出拟聘智能体的姓名、角色、职称、能力与职责、所用 AI 适配器以及需要的技能。完整申请还可能包含适配器配置、月度预算和汇报对象；请展开 **查看完整申请（See full request）** 检查这些信息。

### CEO 战略

CEO 首次心跳运行后会制定实现公司目标的战略。开始据此分配任务前，必须先获批准。战略决定公司整体重点，因此请确认计划确实服务于目标。未批准战略时，CEO 不能把任务移至“进行中”；任务迟迟无人处理时，可以先检查审批队列。

### 预算覆盖

预算政策触及硬性上限、需要董事会介入才能继续工作时，你可能会看到预算相关审批。预算限制要在 **成本（Costs）** 页面处理，而不是在审批卡片上批准或拒绝。

## 打开审批页面

可从直接链接、仪表板上的待审批卡片，或收件箱中的审批项目进入审批页面。页面有两个标签：**待处理（Pending）** 显示仍需决定的项目；**全部（All）** 显示完整历史。处于 `revision_requested` 状态的项目仍可处理，也会计入待处理数量。

![审批页面的待处理标签展示 CEO 战略提案和董事会审批申请](../../../user-guides/screenshots/light/approvals/approvals-list.png)

各标签中的审批按创建时间从新到旧排列。卡片会显示类型、申请人、主题与创建时间、状态、申请摘要、可用操作和详情链接。待处理标签为空时，说明当前没有待你决定的申请。

![待处理和全部标签以及待处理数量](../../../user-guides/screenshots/light/approvals/queue-filters.png)

## 审查招聘申请

打开招聘申请详情后，可查看拟聘智能体的姓名、角色、职称、图标、能力说明、适配器类型和技能。展开 **查看完整申请（See full request）** 可检查摘要中未展示的适配器配置、月度预算和汇报关系。详情页下方的评论会在申请智能体下次运行时对其可见。

![招聘审批详情显示拟聘智能体资料](../../../user-guides/screenshots/light/approvals/hire-approval-detail.png)

决定前可以逐项考虑：公司当前是否需要这个岗位？能力是否符合工作？预算是否合理？环境变量和工作目录等适配器设置是否正确？

## 审查战略申请

战略详情包含战略标题、CEO 撰写的计划正文、关联任务（如果已经创建）以及可能附带的决策说明。批准战略不会关闭关联任务；申请智能体后续跟进并关闭前，任务仍保持打开状态。

![CEO 战略审批详情以及操作按钮](../../../user-guides/screenshots/light/approvals/strategy-approval-detail.png)

请结合公司目标检查计划是否切题、任务是否具体可执行、范围是否合理，以及是否遗漏明显的关键工作。如果需要调整，选择 **要求修改（Request revision）**，再在评论框中具体说明希望改变的内容；例如指出战略过度关注技术基础设施、缺少用户获取计划。

## 批准、拒绝或要求修改

![审批详情中的批准、拒绝和要求修改按钮](../../../user-guides/screenshots/light/approvals/approve-reject-revision-buttons.png)

- **批准（Approve）**：接受当前提案。招聘申请会创建并配置新智能体，并将其排入自动唤醒队列；战略申请会通知 CEO，后续运行通常会开始创建任务。审批状态变为 `approved`。
- **拒绝（Reject）**：明确否决提案。招聘岗位不会创建，战略会被弃置，申请智能体不会自动重试。拒绝招聘后，还可选择 **删除已否决的智能体（Delete disapproved agent）** 清理组织架构中的占位记录。
- **要求修改（Request revision）**：暂不接受，但也不否决。状态变为 `revision_requested`，请在评论中说明需要调整之处。申请者后续修改并重新提交后，审批回到 `pending`，供你再次审查。要求修改后，按钮会变成 **标记为已重新提交（Mark resubmitted）**；批准和拒绝仍然可用。

当提案方向正确、只需调整预算、汇报关系或战略范围时，通常选择要求修改更合适。只有提案根本错误或已无关紧要时才拒绝。修改循环没有次数限制：

```text
pending → approved
        → rejected
        → revision_requested → resubmitted → pending
```

![已批准审批显示确认提示与状态](../../../user-guides/screenshots/light/approvals/approved-approval.png)

预算审批比较特殊：审批列表和详情页不会显示批准、拒绝按钮。请前往 **成本（Costs）** 页面中的预算控件解决预算暂停；审批详情会提供跳转链接。

## 修订申请时留下评论

评论会保留在审批记录中，供申请者下次运行时查看。请写清楚需要改动什么。首次战略不必完美，可以反复要求修改，直到计划符合预期。

![审批评论框用于说明修改要求](../../../user-guides/screenshots/light/approvals/revision-request-input.png)

## 董事会的直接控制权

除了审批流程，你始终可以暂停或恢复智能体、终止智能体、重新分配任务，也可以绕过 CEO 的招聘流程直接创建智能体。终止会永久停止智能体，但保留其终止记录；删除才是破坏性操作。如果之后可能还要恢复该智能体，请先暂停。

审批队列适合定期查看。接下来可以阅读[成本与预算（Costs & Budgets）](../../../guides/day-to-day/costs.md)，了解 API 支出、限额和预算控制。

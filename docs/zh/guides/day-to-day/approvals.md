# 审批

审批机制让你在智能体自主工作的同时仍能掌控局面。没有审批，智能体可能在你不知情的情况下招聘团队成员、确定战略并作出重大决策。审批是治理层：任何智能体执行重要操作前，Paperclip 都会暂停并征求你的确认。

可以把它想成董事会席位。智能体负责公司的日常运营，但重大决策——招聘谁、采取什么战略——仍会交由你决定。

![审批列表页面显示待处理审批卡片、类型标签、申请摘要，以及内嵌的批准和拒绝按钮](../../../user-guides/screenshots/light/approvals/approvals-list.png)

---

## 审批类型

大多数人最先在 Paperclip 中遇到的审批类型如下：

### 招聘智能体

智能体（通常是 CEO 或 CTO 等经理）认为需要帮助并希望增加下属时，不能自行创建智能体，而是提交招聘申请——该提案会进入你的审批队列。

招聘申请会告诉你：

- 拟聘智能体的姓名、角色和职称
- 智能体将承担的能力和职责
- 为它提供动力的 AI 系统（适配器）
- 它需要的技能

完整申请还可能包含适配器配置、月度预算，以及新智能体将向哪位智能体汇报。这些内容不会显示在摘要中，因此请打开 **See full request** 查看。

你需要审查提案，判断公司是否确实需要这个岗位，以及拟议的配置是否合理。

### CEO 战略

首次心跳运行后，CEO 会创建一份战略计划，用于实现公司目标。它必须先获得你的批准，才能开始依据该计划分配任务。

这是你会遇到的最重要审批。CEO 的战略决定整个公司关注的重点；仔细审查可确保智能体把精力用在正确的事情上。

> **注意：**你批准战略之前，CEO 无法将任务移至 “in progress”（进行中）。如果任务似乎一直没有人接手，请先检查审批队列。

### 预算覆盖

预算政策触及硬性停止线、需要董事会采取行动才能继续工作时，你之后也可能看到预算相关审批。

## 打开审批页面

1. **打开审批页面。**

   你可以通过直接链接、仪表板上的待处理审批卡片，或收件箱中的审批相关项目打开该页面。页面包含两个标签：**Pending**（待处理）显示需要采取行动的项目；**All**（全部）显示完整历史记录。

   ![审批页面的 Pending 标签，列出 CEO 战略提案和董事会审批请求等待处理审批](../../../user-guides/screenshots/light/approvals/approvals-list.png)

   待处理审批带有黄色徽标。`revision_requested` 状态的项目在请求者跟进并重新提交之前，仍会被视为可处理项目。

---

## 队列筛选

审批页面顶部使用标签栏组织内容：

- **Pending**——所有仍等待你作出决定的项目。包括处于 `pending` 状态的审批，以及处于 `revision_requested` 状态的审批；后者是你此前退回修改、仍在等待请求者跟进的项目。两种状态都会计入标签旁的黄色数量标记。
- **All**——完整历史记录，包括已批准、已拒绝和已解决的项目，以及仍在等待处理的项目。可通过此标签查找以往决定，或确认某项审批何时解决。

![审批标签栏显示 Pending 和 All 标签，以及待处理数量标记](../../../user-guides/screenshots/light/approvals/queue-filters.png)

每个标签内的审批都按时间从新到旧排序。每项审批以卡片显示，其中包含：

- 类型标记（**Hire Agent**、**CEO Strategy**、**Budget Override** 或 **Board Approval**）；由智能体提交的申请还会显示带有智能体姓名的 **Requested by** 行。
- 申请主题及创建时间（例如 “Approval request created 16m ago”）。
- 状态标记，例如 **Pending** 或 **Approved**。
- 申请摘要，例如拟聘人员的姓名、角色和适配器，或董事会审批的摘要和建议操作。
- **Approve** 和 **Reject** 按钮，让你可以直接在列表中处理仍可操作的项目（预算覆盖是例外，见下文）。
- **View details** 链接，可打开后续章节介绍的审批详情。

> **提示：**如果 Pending 标签为空，说明当前待办已处理完；仪表板上的收件箱卡片也会显示待处理审批数为零。

## 招聘审批详情

点击招聘申请会打开详情页，页面分为三个部分：

1. **页眉**：包含审批类型图标、类似 “Hire Agent: Senior Engineer” 的标题、当前状态标记和审批 ID（在评论或联系支持人员时可引用）。如果申请由智能体提交，页眉还会显示 **Requested by** 行并注明申请者。
2. **提案摘要**：显示申请中的结构化字段。招聘申请包括：
   - 拟聘智能体的 **Name**、**Role**、**Title** 和 **Icon**。
   - **Capabilities**——对智能体工作内容的自由格式说明。
   - **Adapter**——将为智能体提供运行能力的适配器类型。
   - **Skills**——招聘申请要求分配的技能。
3. **See full request** 展开项：展开后可查看原始 JSON 载荷。摘要不会显示适配器配置、申请的月度预算或汇报关系，因此决定前请展开检查。

**Approve**、**Reject** 和 **Request revision** 按钮位于卡片下方。卡片下方的 **Comments** 区域可用于留言或提出澄清问题。下次唤醒申请智能体时，它可以看到审批评论。

![招聘审批详情显示拟聘智能体的姓名、角色、职称、图标、能力和适配器类型](../../../user-guides/screenshots/light/approvals/hire-approval-detail.png)

<a id="reviewing-a-hire-request"></a>
### 审查招聘申请

1. **点击待处理的招聘审批。**

   这会打开招聘申请详情，显示智能体提交的完整提案。

2. **仔细阅读提案。**

   问问自己：

   - 公司现在确实需要这个岗位吗？
   - 拟议的能力适合要完成的工作吗？
   - 申请的预算合理吗？（新建的工作者智能体通常比管理者智能体需要更少预算。）请在 **See full request** 中查看预算。
   - 适配器配置是否正确——环境变量看起来合适吗，工作目录是否合理？这些内容也在完整申请中。

3. **作出决定。**

   ![审批详情中的 Approve、Reject 和 Request revision 按钮](../../../user-guides/screenshots/light/approvals/approve-reject-revision-buttons.png)

   - **Approve**——继续招聘。系统会创建并配置新智能体，然后将其加入队列以便自动唤醒。
   - **Reject**——拒绝招聘。系统会通知申请智能体；除非你另行指示，否则它不会再次提交。
   - **Request revision**——暂不批准当前版本，但也不拒绝。智能体会修改提案并重新提交。

> **提示：**如果招聘方向基本合理、但提案还需调整，通常应选择 Request revision，而不是拒绝。例如预算过高、适配器配置不正确，或角色说明过于含糊。请在评论中具体指出需要修改的内容。

## 战略审批详情

战略审批详情页布局与招聘审批相同，但内容不同。主要内容不是结构化招聘提案，而是 CEO 的**战略计划提案**。具体包括：

- **Title**——战略名称。
- **计划正文**——以纯文本显示在可滚动框中，内容与 CEO 撰写的完全一致。
- **Linked Tasks**——如果 CEO 已创建与战略关联的任务，这些任务会以可点击列表显示在计划下方。批准战略不会关闭这些任务；它们会保持打开，直到申请智能体跟进并关闭。
- **Decision note**——审批附带说明时显示。

![战略审批详情显示 CEO 的计划提案，以及 Approve、Reject 和 Request revision 按钮](../../../user-guides/screenshots/light/approvals/strategy-approval-detail.png)

### 审查战略审批

1. **点击战略审批。**

   战略详情会显示 CEO 的计划提案——通常包含数段文字，概述目标、优先事项和计划创建的初始任务。

   ![战略审批详情显示 CEO 提出的战略计划](../../../user-guides/screenshots/light/approvals/strategy-approval-detail.png)

2. **结合公司的目标阅读战略。**

   战略应当是实现你设定的公司目标的可信计划。检查以下事项：

   - 计划是否真正回应了公司的目标，还是 CEO 已偏向无关方向？
   - 拟议任务是否具体且可执行？
   - 工作范围是否合适——有挑战性，但并非不切实际？
   - 是否存在明显缺口（显然需要完成却未提及的事项）？

3. **批准或要求修改。**

   如果战略看起来合理，请点击 **Approve**。CEO 会立即开始根据计划创建任务。

   如果存在问题，请点击 **Request revision**，然后在 **Comments** 框中说明需要修改的内容。尽量具体，例如：“战略过于关注技术基础设施，而没有充分考虑用户获取——请修改并加入分发计划”，这样 CEO 才能据此采取行动。

   ![审批中的 Comments 框，可用于说明修改要求并点击 Post comment 发布](../../../user-guides/screenshots/light/approvals/revision-request-input.png)

> **提示：**如果首次战略不够完善，不必担心——批准前可以按需多次要求修改。要求修改会改变审批状态，并留下清晰说明供请求者处理；请求者跟进并重新提交后，你会看到更新后的提案。

## 批准、拒绝或要求修改

每项待处理审批的详情卡片都在提案下方显示相同的三个按钮。（要求修改后，**Request revision** 会替换为 **Mark resubmitted**，而 **Approve** 和 **Reject** 仍然可用。）请谨慎使用：每个按钮对申请智能体都有不同含义。

![审批详情中的 Approve、Reject 和 Request revision 按钮](../../../user-guides/screenshots/light/approvals/approve-reject-revision-buttons.png)

- **Approve**（绿色）——接受当前提案。对于招聘，系统会创建并配置智能体，然后将其加入自动唤醒队列。对于战略，系统会通知 CEO，并在它下次运行时开始创建任务。详情页会出现 **Approval confirmed** 横幅，列表中的审批状态变为 `approved`。
- **Reject**（红色）——彻底拒绝提案。招聘职位不会创建，战略会被丢弃，申请智能体也不会再次尝试，除非你另行指示。如果拒绝的是招聘申请，还会出现 **Delete disapproved agent** 按钮，可清除组织架构中的占位记录。
- **Request revision**（描边按钮）——不接受当前版本，但也不拒绝。审批会进入 `revision_requested` 状态。请求者会在之后的运行中修改并重新提交；随后审批会带着更新的载荷回到 `pending`，供你再次审查。请在审批上留言，具体说明需要修改的内容，以便智能体得到明确指引。

> **提示：**如果提案方向正确但需要微调，几乎总是应该选择 Request revision，例如调整预算、更改汇报关系或缩小战略范围。只有提案根本错误或已不再相关时才拒绝。

**预算审批**稍有不同：无论审批列表还是详情页都不会显示 Approve 和 Reject 按钮。预算停止应通过 **Costs** 页面中的预算控件解决；详情页会提供跳转链接。

## 作出决定后会发生什么

**批准时：**

- 操作会立即继续。
- 对于招聘：系统会创建新智能体，并将其排入自动唤醒队列。
- 对于战略：Paperclip 会将申请者加入自动唤醒队列，因此批准后通常很快会出现后续运行。
- 列表中的审批状态变为 “approved”。

**拒绝时：**

- 操作会被彻底拒绝。
- 对于招聘：不会创建该职位，并会通知申请智能体。
- 对于战略：CEO 必须从头制定新战略；系统不会自动重试。
- 只有提案根本错误时才应拒绝，而不应仅因提案不够完善就拒绝。

**要求修改时：**

- 审批会进入 “revision_requested” 状态。
- 你的评论会保留在审批上，供请求者处理。
- 智能体会在之后的运行中修改提案并重新提交，审批状态随之回到 “pending”。
- 下次打开审批时会看到更新后的提案。

![已批准的审批显示 Approval confirmed 横幅、approved 状态标记和 Back to approvals 按钮](../../../user-guides/screenshots/light/approvals/approved-approval.png)

完整的修改循环如下：

```
pending → approved
        → rejected
        → revision_requested → resubmitted → pending (again)
```

修改循环没有次数限制。可以反复要求修改，直到提案符合你的实际要求。

<a id="board-override-powers"></a>
## 董事会的直接干预权限

除了审批队列，你始终可以直接控制公司的各个方面。无需等待审批流程即可：

- **暂停任何智能体**——阻止它运行，直到你恢复它。
- **恢复任何智能体**——重新启动已暂停的智能体。
- **终止智能体**——永久停止它，并将其从组织中移除。

> **危险：**终止和删除是不同操作。终止会永久停止智能体，但保留其终止记录；删除才是破坏性操作。如果以后可能还想恢复该智能体，请改为暂停。

- **重新分配任何任务**——随时将任务从一个智能体转给另一个智能体。
- **直接创建智能体**——你可以自行招聘智能体，无需经过 CEO 的招聘流程。

之所以提供这些干预权限，是因为自主智能体偶尔会偏离方向、陷入停滞或产生意外结果。你始终可以介入处理。

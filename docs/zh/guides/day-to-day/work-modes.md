# 工作模式

在智能体开始工作前，先选择你想要的结果：完成工作、先审阅计划，或在讨论串中得到回答。Paperclip 为这三种目标提供**自动模式（Auto）**、**计划模式（Plan）**和**提问模式（Ask）**。

## 背景

任务从一种工作模式开始；你也可以在消息编辑框中为每条后续消息单独选择模式。这样，你可以针对正在进行的项目提问、审阅计划，然后授权实施，无需为每次交流另建任务。

模式在发送消息时生效。只更改模式标签不会中断当前正在运行的工作。

## 模式说明

| 模式 | 你希望得到什么 | 示例 |
|---|---|---|
| **自动模式（Auto）** | 已完成的工作及其结果。API 中对应 `standard`。 | “撰写发行说明并附上草稿。” |
| **计划模式（Plan）** | 实施前供你审阅的方案。API 中对应 `planning`。 | “先规划登录功能的修改，再编辑代码。” |
| **提问模式（Ask）** | 一个不涉及实现的回答。API 中对应 `ask`。 | “哪些适配器支持此运行环境？” |

自动模式是默认值。计划模式会让智能体专注于澄清目标并撰写计划文档。提问模式会将请求限制为只读，适合查找信息、比较选项或解释问题。

## 使用方式

在新建任务或任务编辑框中点击 **+** 菜单，选择 **Plan mode（计划模式）** 或 **Ask mode（提问模式）**。当前模式会显示在加号按钮旁。点击模式标签可切回自动模式，也可以选择另一种模式来替换当前模式。输入框获得焦点时，还可以使用 **⌘+.**（Windows 和 Linux 上为 **Ctrl+.**）或 **Shift+Tab** 切换模式。

智能体、模型和思考强度需单独选择。这些设置决定由谁回答以及模型如何运行；工作模式则决定你请求的结果类型。完整控制项布局见[任务对话编辑框](../../experimental/task-chat.md#the-composer)。

待处理问题和确认请求会显示在编辑框上方，直到你回复或请求自身的过期规则生效。选择自动模式或发送新消息不会自动接受计划。请使用确认卡片上的选项作出决定。

无论选哪种模式，任务都会保留原有负责人、优先级、项目、讨论串和状态。预算、审批和公司边界也仍然生效。工作模式会改变智能体的任务指令和可用操作。

实现参考：[编辑框模式选择](https://github.com/paperclipai/paperclip/blob/a6306ba606eb87c89b9ef0344e9fe8e0025580f9/ui/src/components/task-chat/TaskChatComposer.tsx)和[模式标签](https://github.com/paperclipai/paperclip/blob/a6306ba606eb87c89b9ef0344e9fe8e0025580f9/ui/src/lib/work-mode-meta.ts)。

## 你要查看回答还是交付物？

如果只需要快速解释或判断，请选择提问模式。若要先审阅方案再实施，请选择计划模式。若需要报告、代码修改、配置更新或其他交付物，请选择自动模式。

研究类请求可以使用提问模式，也可以使用自动模式。快速问一句“这里的代码库做了什么？”可以直接得到回答。如果调查需要保存报告和支持文件，请使用自动模式，以便之后审阅这些工作成果。

# 问题

Paperclip 中的工作以**问题（issue）**表示：智能体领取、执行并完成的一项具体任务。每个问题都能追溯到公司目标。产品界面常称其为“任务（task）”，任务页面使用 `/issues` 路由，API 也称其为 issue。

CEO 通常会根据已批准战略自动拆分并分配工作。只有当你有策略中未涵盖的具体请求、需要处理紧急事项、要开展一次性实验，或想把卡住的任务拆小/改写时，才需要手动创建。其他情况可让 CEO 管理任务，通过仪表板和审批查看进展。

## 打开问题页面

从侧栏选择 **任务（Tasks）**。默认按最近更新时间显示当前公司的问题。工具栏可按状态、优先级、负责人、创建者、项目和标签筛选，也可按标题、标识符、描述或评论内容搜索；网址中的 `?q=` 会保留查询，便于分享。工作区不再单独作为筛选项，可点击工作区名称或按工作区分组。

列表可按状态、负责人、项目、工作区、父任务分组；也可切换父子任务嵌套，并选择显示负责人、发起人、项目、工作区、父任务、标签和更新时间等列。视图设置会保留。正在由智能体运行的任务会显示实时指示器，无需刷新页面。

## 创建任务

点击 **新建任务（New Task）**，或不在输入框中时按 `C`。在对话编辑器中清楚说明目标、限制和完成标准；标题可从描述生成。选择项目（也可选“无项目”），选择 **自动（Auto）**、**计划模式（Plan mode）** 或 **提问模式（Ask mode）**，再选择负责人、模型和推理强度。默认情况下会沿用本公司上次使用的负责人和强度；不可用时回退到 CEO。可以在加号菜单中附加文件或图片。点击 **创建任务（Create task）** 或按 ⌘+Enter（Windows/Linux：Ctrl+Enter）。

任务创建后，在 **属性（Properties）** 面板调整状态、父任务、项目、审查者和批准者。新建对话框不会设置这些字段或任务看护器；暂停状态的负责人可以接收任务，但恢复之前不会启动。

创建子任务时，编辑器会显示 **父任务（Sub-task of）** 并使用 **创建子任务（Create sub-task）**。若项目支持隔离工作区，可选择新建或复用 Git worktree；详见[执行工作区](../projects-workflow/workspaces.md)。

### 私有任务

薪酬审查、公告草稿等敏感工作可在保存前从加号菜单选择 **私有任务（Private task）**。锁定标签可切换为公开；若已有个人私有项目且尚未选择项目，Paperclip 会将任务放入该项目。私有任务的子任务和私有项目内任务会继承私有状态，锁定且不能自行公开；界面会说明继承原因。如果无法检查父任务权限，Paperclip 会先等待检查完成。

## 跟踪进度、评论与完成

打开任务详情查看说明、当前状态和评论历史。智能体会在评论中说明已完成内容、发现、下一步或阻塞原因。你可以随时回复问题或补充背景；评论会在下次心跳时被读取，按需唤醒可用的智能体会收到相应通知。反馈应具体，例如指出语气、受众和需要改写的部分。

智能体通常会把任务移至 **已完成（done）**，或在配置审查时移至 **审查中（in_review）**。检查产出后可留言要求修改；满意后，`done` 即为终态，工作记录会永久保留。

## 状态说明

- **待办池（backlog）**：已登记但未优先安排；移至 `todo` 后智能体才会领取。
- **待办（todo）**：准备开始，已分配智能体等待下次心跳领取。
- **进行中（in_progress）**：智能体已领取并在工作；同一时间只有一个智能体可持有该任务。
- **审查中（in_review）**：工作已完成，等待签核。
- **已完成（done）**：任务完成；后续新工作可以重新打开，历史仍保留。
- **阻塞（blocked）**：无法继续，通常需要补充信息、决策、重新分配或拆分任务。
- **已取消（cancelled）**：不再需要执行的终态。

完整状态转换和 `executionState` 说明见[问题生命周期参考](../../../reference/api/issues.md#issue-lifecycle)。

## 收件箱

收件箱是面向人员的分流入口，只展示当前需要你关注的事项；问题页面则是全公司的完整索引。默认导航包含 **我的（Mine）**、**最近（Recent）**、**未读（Unread）**、**阻塞（Blocked）** 和 **全部（All）**。开启实验性“合并收件箱与任务列表”后，这些视图会移至 **任务 → 视图**。

- **我的**：分配给你或由你创建、且仍处于活动状态的问题和审批，也包括你负责的失败运行；没有待办时显示 Inbox zero。
- **最近**：你近期参与、评论、被提及或曾负责的问题。
- **未读**：最近项目中有新活动的子集，蓝点表示未读；标为已读后指示会消失。
- **阻塞**：等待决策、恢复、外部行动或暂停负责人的任务，带有原因和严重程度标签，详见[阻塞收件箱](./blocked-inbox.md)。
- **全部**：公司范围内可进入收件箱的事项，可按最近问题、加入请求、审批、失败运行和警报分类；审批可进一步按需处理或已解决筛选。

每个标签有独立网址 `/inbox/<tab>`，可直接收藏。仅“我的”支持归档：归档只从你的个人列表隐藏，不会改变任务或审批状态。出现 **全部标为已读（Mark all as read）** 时，可清除当前标签可见项目的未读标记；它不会归档或更改状态。收件箱提供搜索、筛选、分组、列选择和父子任务折叠；启用隔离工作区时可按工作区分组。问题看板支持卡片密度、冷列折叠和每列初始显示数量，设置会保存在浏览器。

## 任务详情侧栏

属性面板用于编辑任务字段并查看相关信息。标签可能包括属性、产出、文档、成果、聊天和活动；实际可用项取决于界面模式和任务类型。**产出（Output）** 显示正式提交的结果；键控文档可持续修订并供任务引用。任务成果见[成果指南](./artifacts.md)。

任务可关联 GitHub 问题和拉取请求。Paperclip 会在内容中识别外部引用并显示链接标签与状态；若任务等待你的 PR 审查，可从相关引用打开 GitHub 并查看筛选标记。

### 聊天与运行

新任务界面的聊天区将消息和实时运行信息放在同一会话；经典任务界面则使用 **聊天（Chat）** 标签。编辑器可选择模式、模型和推理强度、上传文件，并提交问题。计划模式用于先形成计划再执行，提问模式用于回答而不更改文件。一次运行期间提交的操作或交接会与触发它的运行关联，避免混淆运行 ID。

### 活动

活动标签提供任务状态与属性变化的只读记录。包括由谁、以何种权限修改了字段、修改前后值等；更广范围的公司事件可在[活动日志](./activity-log.md)查看。

## 外部引用和任务共享

评论或说明中出现 GitHub issue/PR 引用时，页面会识别并展示关联状态；标签可用于筛选带外部引用的任务。任务可设为私有或公开。私有任务通常仅创建者、负责人、授权人员及其上级可见；具体范围还受公司权限和项目隐私限制。可通过任务分享操作授予其他成员访问权，也可撤销分享。把公开任务改为私有前，请先检查相关人员是否仍需访问。

## 智能体在其他任务上写入

智能体可能会对其并非负责人的任务发表评论、修改字段、添加子任务或重新分配。前提是智能体能查看该任务，且代表其行动的责任人员也获准执行该写入；公司边界和低信任限制始终生效。

评论会标出智能体代表的**责任用户**；字段变更会记录修改前后值及许可理由；被拒绝时会说明触发的权限边界及可采取的正确路径。单次心跳最多可对唤醒任务以外的问题进行 20 次评论和字段修改（写入次数计数，不是任务数）；目前先记录，之后会执行硬性限制。公司隔离和审计记录会保留代表行动的责任链。

任务交互卡（确认、问题、建议任务）可指定另一智能体作答，也可指定董事会人员。每张卡都会显示谁能解决：公司任何成员、除创建者外的任何人，或仅限人员。默认开放；公司设置中的 **交互治理（Interaction governance）** 可按交互类型配置默认范围及更严格的上限，策略只会缩小响应人范围，不会扩大请求本身允许的范围。

你可以在智能体运行期间回答交互卡。点击后答案会排在编辑器上方，并锁定选项和内容。可等待当前运行结束后交付、在支持时选择 **引导（Steer）** 注入当前运行，或使用 **中断（Interrupt）** 停止并以新运行处理。待处理的答案不会被普通消息覆盖；在答案处理前，Paperclip 会保持任务负责人不变。

## 停止、恢复和恢复操作

运行期间，空编辑器会显示 **停止（Stop）**。暂停父任务也会暂停其子树；暂停后草稿仍保留，可选择恢复任务或恢复整个子树。若中断运行的结果不确定，Paperclip 会阻止立即唤醒；先检查运行和恢复说明。`Model unavailable` 表示提供方拒绝模型，请换用支持的模型或清除覆盖后重试。若提供方要求重新登录，先完成认证。

若任务运行结束时没有选择下一步，或分配任务失去有效执行路径，Paperclip 会在源任务上建立**恢复操作**，记录类型、负责人、证据、再次唤醒策略和解决结果。自动重试只在安全时进行；不会自动接管或重新分配任务。重试耗尽后，任务可能进入 `blocked`，并显示“没有活动执行路径”。

解决结果包括：`restored`（恢复正常执行）、`blocked`（确有结构化阻塞项）、`cancelled`（操作不再适用）和 `false_positive`（无需干预）。若要以 `blocked` 关闭恢复操作，请先在 **被阻塞（Blocked by）** 字段添加真实依赖；普通评论不够。

## 任务看护器

任务看护器是附加到任务的监控智能体。当任务子树没有活动运行、待处理交互或进展时，它会检查卡住的子任务，并可留言、创建子任务、升级给其他智能体或采取适当行动。新任务创建后有短暂宽限期；每个任务同一时间最多配置一个看护器，替换时先移除旧看护器。结果会显示在任务聊天中。它不同于单个运行的静默监控，后者只在运行摘要中显示可疑或严重级别，不会单独创建恢复操作或评论。

## 浏览子任务

详情页底部的上一项/下一项导航先按工作流顺序遍历同一父任务下的同级任务，再从最后一个同级任务继续到当前任务的第一个子任务。隐藏任务会跳过；依赖和状态顺序会影响排列。隐藏的当前任务不显示导航。

## 快速理解

- **问题页面**：全公司工作索引，可筛选、分组和看板浏览。
- **收件箱**：人员分流队列；“我的”是个人待办。
- **属性面板**：编辑负责人、标签、父子关系、依赖、审查参与者和工作区。
- **任务会话**：查看评论、运行并提交新指示。
- **活动记录**：检查系统操作和成本。

## 附录：智能体开发者的问题工作流

### 领取任务

工作前必须原子化领取任务：

```http
POST /api/issues/{issueId}/checkout
{ "agentId": "{yourId}", "expectedStatuses": ["todo", "backlog", "blocked", "in_review"] }
```

并发竞争时仅一个智能体成功，另一个收到 `409 Conflict`。不要重试 409，应选择其他任务；已持有任务时重复领取是幂等操作。

### 工作并更新

过程中及时写评论和进度，完成时一并提交状态和总结：

```http
PATCH /api/issues/{issueId}
{ "status": "done", "comment": "实现已完成，验证通过。" }
```

状态变更必须带 `X-Paperclip-Run-Id` 请求头。部分进展也应说明尚未完成的工作和后续计划。

### 阻塞

无法继续时不要静默等待：将状态设为 `blocked`，写清阻塞原因并升级给合适负责人。需要依赖时建立结构化阻塞关系。

### 委派

经理应把工作拆成子任务，并保留父子层级；适用时填写 `goalId`。执行某任务的运行中新建任务，若省略 `parentId`，默认会作为当前任务的子任务。若要创建顶层任务，显式传入 `"parentId": null`；CLI 可用 `issue create --standalone`。

### 释放任务

若任务应由其他人负责，调用 `POST /api/issues/{issueId}/release`，并留言说明原因。

### 单次个人贡献者心跳示例

```text
GET /api/agents/me
GET /api/companies/company-1/issues?assigneeAgentId=agent-42&status=todo,in_progress,in_review,blocked
GET /api/issues/issue-101
GET /api/issues/issue-101/comments
# 优先继续进行中的工作，完成后领取下一项
POST /api/issues/issue-99/checkout
{ "agentId": "agent-42", "expectedStatuses": ["todo", "backlog", "blocked", "in_review"] }
PATCH /api/issues/issue-99
{ "comment": "JWT 签名已完成；还需实现令牌刷新，将在下次心跳继续。" }
```

# 技能

如果要智能体遵循代码审查清单、部署手册或客户回复模板，可以将指令写进智能体配置；但多个智能体共用流程时，使用**技能（skill）**更合适。技能是可按需加载的指令文档，存放在公司技能库中。智能体开始任务时先读取技能简介，判断是否相关，再按需加载完整内容。这样可让基础上下文更小，降低 token 费用，并让指令更聚焦；更新一次即可惠及所有使用它的智能体。

## 技能文件结构

技能是包含 `SKILL.md` 的文件夹，文件由简短的前置元数据和指令正文组成，可附带参考资料：

```text
skills/
└── code-review/
    ├── SKILL.md
    └── references/examples.md
```

前置元数据中的名称和描述是智能体最先看到的内容。描述应写成判断规则，例如“审查拉取请求时使用；从头编写新代码时不要使用”。若任务符合描述，智能体才会加载完整技能。

## 添加技能

在公司级 **技能（Skills）** 页面管理技能。侧栏包含 **已安装（Installed）**、**发现（Discover）**、**来源（Sources）** 和作者区域中的 **我的技能（My Skills）**。已安装视图可搜索、排序和扫描工作区，也可新建文件夹或点击 **新建（New）**。添加方式包括从头创建、浏览技能、从 GitHub 导入、管理来源、从路径或网址导入，以及从项目导入。

### 从 GitHub、Gist 或本地导入

推荐在 **技能 → 来源** 中关联 GitHub 仓库：从 **新建 → 从 GitHub 导入（Import from GitHub）** 选择仓库及技能。来源会固定到具体提交，之后可检查更新并升级固定版本。也可用 **从路径或网址导入（Import from path or URL）** 粘贴 GitHub 仓库、文件夹或 `SKILL.md` 地址；GitHub 来源会获得相同的刷新控制。

Gist 可通过同一对话框导入，适合分享单个流程。也可输入 Linux、WSL 或 Windows 本地路径，Paperclip 会搜索 `SKILL.md`。出于安全考虑，本地路径必须位于公司管理的技能目录、项目工作区或 Paperclip 管理的项目检出目录中；其他路径会被拒绝。

[skills.sh](https://skills.sh) 是社区技能目录。将条目提供的安装命令粘贴到路径/网址导入框，可连同来源信息一起导入。项目导入则会扫描指定项目的工作区，按工作区和文件夹展示发现的技能；可搜索并选择导入。若短名称冲突，可指定新的 URL 安全短名称。导入结果会汇总新增、更新和跳过数量。

项目导入的技能是**直接引用工作区中的文件**，不是复制品；在技能工作室编辑会直接写回项目文件。若需要独立副本，应先复制到 Paperclip 管理的位置再导入。

### 从头创建与内置目录

选择 **新建 → 创建新技能（Create new skill）** 会打开技能工作室，依次填写 **基础信息（Basics）**（名称、可选的 `kebab-case` 短名、使用场景描述）、**设计（Design）**（颜色与分类）、**内容（Content）**（指令）和 **审查（Review）**（组织或私有共享范围）。描述应写清“何时使用/何时不要使用”。创建后，技能会成为可编辑的 Paperclip 管理项目。

内置目录提供常见工作流程技能，例如维护文档、分流问题、规划任务、QA 验收和 GitHub PR 流程，也包含可选的浏览器操作、发布公告、设计评审、近期网络研究等技能。安装只会把技能加入公司库，不会自动分配给智能体。部分技能来自固定版本的外部仓库，Paperclip 会记录版本，支持检查更新、审查内容和重置。

### GitHub 同步来源

在 **来源（Sources）** 中添加 GitHub 仓库并导入需要的技能。之后可检查来源更新并同步。同步导入的技能为只读，不能在 Paperclip 中直接改写上游文件；请在仓库中编辑并重新同步。

## 文件夹与技能工作室

可用文件夹组织技能库，并在已安装视图中按文件夹浏览。技能工作室包含概览、文件树和编辑区：可创建或编辑 `SKILL.md` 及 `references/` 中的支持文件，保存后可运行测试，检查技能是否能解决预期任务。创建技能向导也会引导填写名称、描述、颜色、分类、内容和共享范围。

智能体执行任务时也可以创建或改进技能。若允许智能体编辑现有技能，应明确范围并审查变更；可通过技能详情页查看由谁使用。

## 编辑权限、文件清单与信任

并非所有技能都可直接编辑。Paperclip 管理的技能可在工作室修改；项目工作区或 GitHub 来源技能应在来源仓库修改，避免本地编辑被同步覆盖。详情页会显示文件清单和来源。

技能来源标签说明信任边界：

- **Paperclip 管理**：在 Paperclip 中编写，可控性最高。
- **本地文件夹**：来自项目工作区，信任程度取决于该目录。
- **GitHub / skills.sh**：固定到某个提交或版本，更新前可检查差异。
- **Gist / URL**：外部内容的导入快照，应像第三方代码一样先审阅。

在将技能分配给 CEO、财务智能体或能访问机密的高信任角色前，请完整阅读 `SKILL.md`。详情页的 **使用者（Used by）** 列表可检查哪些智能体已获得该技能。

## 技能详情与智能体同步

技能详情页显示描述、来源、版本、文件、使用者、代理器同步方式和信任信息。技能更新可影响所有使用者；同步失败、技能缺失或代理器拒绝文件时，页面会显示警告。

不同代理器应用技能的方式不同：

- **保留在工作区（persistent）**：技能文件写入工作区并跨运行保留。
- **下次运行时应用（ephemeral）**：每次运行时临时生成文件，之后清理；沙盒代理器常用此模式。
- **仅跟踪（unsupported）**：Paperclip 只记录分配关系，需到远程运行时管理技能。

无论同步方式如何，分配关系都会保存。智能体的 **技能（Skills）** 标签显示启用数量、搜索框，以及“已启用”“技能库可用”“自动/检测到（只读）”分组。切换开关会自动保存，智能体下次运行时采用新列表。也可从技能详情页 **添加到智能体（Add to agent）**，选择多个智能体和版本。若技能不在可用列表，先将它加入公司技能库。

新手流程创建的 `first-task` 技能会指导首个智能体如何回应入职问题、提出计划或任务并等待批准；它只用于该入职任务，不会自动分配给其他智能体。

## 固定 Paperclip 技能的测试版

内置 `paperclip` 技能是智能体每次运行都会采用的基础流程，默认使用持续更新的版本。若要固定某个智能体使用历史快照，可启用实验性 **测试版技能（Beta skills）**，再在该智能体技能标签中选取版本。该选项默认关闭；启用路径为 **设置 → 实验性**。

**默认 — 当前版本（推荐）** 会持续获取更新；冻结版本则不会改变，但也不会获得此后改进。选择版本立即保存，并显示 Beta 标签。关闭 Beta skills 不会删除已保存的固定版本，但会暂时忽略它们，让所有智能体恢复使用实时默认版本；重新启用后固定设置会再次生效。API 在开关关闭时拒绝保存版本固定。

## 编写好技能的建议

- 将描述写成使用路由规则，明确“何时使用”和“何时不要使用”。
- 使用具体、可执行的步骤和检查清单，避免含糊指令。
- 必要时加入示例、代码和前后对照。
- 一个技能聚焦一个用途；支持材料放进 `references/`。
- 把通用技能放在公司技能库，让多个智能体复用；更新一次即可让所有使用者受益。

## 通过 API 管理技能

可用 REST API 查询智能体技能：`GET /api/agents/{agentId}/skills`。使用 `POST /api/agents/{agentId}/skills/sync` 和 `desiredSkills` 同步，`mode` 可为 `add`（添加）、`remove`（移除）或 `replace`（完全匹配）。创建智能体时也可在 `POST /api/companies/{companyId}/agents` 中传入 `desiredSkills`。技能必须先安装到公司级技能库。

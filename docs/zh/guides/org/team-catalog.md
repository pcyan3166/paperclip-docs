# 团队目录

从空白页面开始设置公司，需要作出许多决定：聘用哪些智能体、谁向谁汇报、要创建哪些项目、安排哪些定期工作，以及每位智能体需要什么技能。**团队目录**可以帮你跳过这些起步工作。它提供一组现成的入门团队——包含智能体、项目、任务和技能的小型工作组——你可以浏览并一步安装到公司中。

[技能](../../../guides/org/skills.md)是单项可重复使用的流程；而*团队*是一整套人员与工作。安装团队后，智能体、组织结构、项目、定期任务和所需技能都会一并就位，就像一个已经开始工作的团队。

---

## 内置团队与可选团队

目录中的团队分为两类，两者使用相同的安装流程：

- **内置团队**随应用一起发布，是日常工作的起点。它们依赖 Paperclip 已经知道的技能，因此可以直接安装。例如：**核心管理团队**（包含 CEO、CTO、QA、入门项目和定期 CEO 心跳任务）、**产品工程小组**（包含 CTO、高级程序员、QA 和每周工程同步），以及**产品设计团队**（包含 UX 设计师、`wireframe` 和 `design-critique` 技能，以及每周设计评审）。
- **可选团队**适合在遇到特定需要时安装。例如，内容团队自带内容日历技能和每周内容评审例程。有些可选团队需要从外部来源（GitHub、URL 或 skills.sh）获取技能，因此安装时会要求你明确同意这些来源。

“内置”不代表强制安装。你仍然可以自行浏览、选择并安装想要的团队；安装之前，任何团队都不会出现在公司中。

---

## 为什么要使用团队目录

从目录安装团队，是让公司最快开始处理实际工作的方式：

- **从合理的默认配置开始。** 核心管理团队体现了许多公司最终会采用的结构：一位领导者、一位执行者和一位检查者。你可以立即开展工作，不必逐个聘用智能体。
- **一次添加完整能力，而非仅添加一个智能体。** 需要工程能力时，安装产品工程小组，就能一并获得角色、汇报关系、项目、每周同步和适用技能，而不必再单独配置一位智能体。
- **保留组织架构。** 将团队安装到已有人员的公司时，可以指定团队负责人向现有经理汇报，让新团队加入现有组织架构，而不是孤立存在。

## 在应用中浏览和安装

打开 **Team Catalog（团队目录）** 页面可查看可用团队，按内置或可选类型筛选，并在安装前查看团队详情。选择团队后，会看到其中的智能体、即将创建的项目和任务，以及所需技能；CLI 的 `inspect` 命令显示同样的信息。如果团队已安装在当前公司中，目录会标记其安装状态；若已安装版本落后于目录中的新版，也会特别标出。

安装分为预览和确认两步。首先选择**预览**：Paperclip 会在服务器上模拟导入，并说明将创建哪些内容、需要准备哪些技能，但不会实际写入任何数据。确认方案符合预期后，选择**安装**，系统便会在公司中创建团队的智能体、项目、任务和技能。

安装时需要作出以下选择：

- **汇报对象。** 可以让团队的顶层智能体向现有经理汇报，使新团队加入现有组织架构。
- **每位智能体使用的运行环境。** 目录团队有意不预先固定适配器，因此安装时你可以选择本地 Claude、Codex 等运行环境，而不会被某一种方案限制。
- **外部技能来源。** 若可选团队声明需要 GitHub、URL 或 skills.sh 技能，安装时需明确同意使用这些来源。只使用目录内置技能的内置团队无需额外同意。
- **机密信息。** 若团队智能体需要机密值（例如 API 密钥），安装流程会以机密环境变量输入的方式收集。

## 安装时会创建什么

安装团队是一次操作，可以同时创建以下多项内容：

- **智能体**——创建团队定义的每位智能体，设置角色、简短的 `AGENTS.md` 角色描述和组织层级。你可以在每位智能体的[说明标签页](../../../guides/org/agents.md#instructions-tab)扩展角色描述。团队的顶层智能体可以独立存在，也可以向你选择的经理汇报。
- **项目**——创建团队工作所需的项目和工作区，为智能体提供执行工作的地方。
- **任务**——包括团队附带的定期例程，例如 CEO 心跳或每周同步；导入这些例程时会采用 Paperclip 处理例程的标准流程。
- **技能**——在公司技能库中准备好团队所需技能：目录技能会自动安装，外部来源技能则会在你批准来源后导入。

每个目录团队都带有版本号，因此 Paperclip 知道你安装的是哪个版本。发布新版后，目录会标记过时团队；准备好时，你可以重新安装更新版本。

---

## 权限说明

安装团队需要创建智能体，因此需要相应权限。如果你或代表你操作的智能体没有该权限，安装操作可能会转为**董事会审批请求**，而不是直接失败，之后由董事会负责人审阅并批准。你提供的任何机密值都会从审批请求中移除，不会泄露。

## 在终端中安装

CLI 也支持上述全部功能，适合通过脚本配置已知的公司结构，或在其他环境中重新创建团队。

```sh
# 浏览和检查团队
paperclipai teams browse --kind bundled
paperclipai teams inspect core-exec-team

# 先预览，再安装到指定公司
paperclipai teams preview core-exec-team --company-id <company-id>
paperclipai teams install core-exec-team --company-id <company-id>
```

完整命令、参数和权限回退行为见 [Teams CLI 参考](../../../reference/cli/teams.md)。

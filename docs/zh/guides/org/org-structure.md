# 构建组织结构

每家公司都会从一位 CEO 智能体开始，但大多数有意义的工作都需要团队。Paperclip 的组织结构是一套汇报层级，告诉每位智能体谁是经理、谁会向它委派工作，以及遇到阻塞时应向谁升级。正确设置组织结构，就能把单个 AI 智能体变成协调工作的团队。

---

## 为什么组织结构很重要

CEO 将公司目标拆解为任务时，不是随意列出一份清单，而是会根据智能体的角色和汇报关系来分配工作。工程任务会分给 CTO 或后端工程师；内容任务会分给营销智能体。层级关系帮助 CEO 知道该找谁。

没有明确的组织结构，所有工作都会落到 CEO 身上，团队也无法扩展。有了组织结构后，CEO 可以把完整工作流交给经理，经理再向自己的下属委派任务。

---

## 运作方式

Paperclip 强制使用严格的树状结构。除 CEO 外，每位智能体都恰好有一位经理，也就是它的汇报对象。CEO 位于顶层，向你（董事会）汇报。

几条规则：

- 不允许循环：智能体不能成为自己的经理，也不能间接管理自己的上级。
- 只有一位直接上级：每位智能体恰好有一位直接经理。
- 可以跨团队分配任务；如果任务受阻，由接收任务的智能体自己的经理负责升级处理。

---

## 常见组织结构

### 单人 CEO（起步阶段）

刚创建的公司通常是这样：

```
CEO
```

学习 Paperclip 的运作方式时，这样完全没问题。CEO 会独自处理所有事情。准备扩大规模时，再添加经理。

### 小型团队

添加一两位经理层级智能体后，CEO 就可以委派完整的工作流：

```
CEO
├── CTO
└── CMO
```

CEO 将工程任务分配给 CTO，将营销任务分给 CMO。策略审批完成后，委派会自动进行；你只需和 CEO 沟通。

### 扩展后的团队

在经理名下添加执行人员，让 CEO 可以继续向下委派：

```
CEO
├── CTO
│   ├── Backend Engineer
│   └── Frontend Engineer
└── CMO
    └── Content Writer
```

CEO 将高层级任务交给 CTO 和 CMO；他们再为各自下属创建子任务。每个层级都能处理自己的职责，不必把所有事项都上报给 CEO。

> **建议：** 不必一开始就建好所有层级。可以先从小团队开始，看看 CEO 创建了哪些工作，之后再根据团队能力空缺添加智能体。

## 添加经理

经理层级智能体（例如 CTO、CMO、设计主管）直接向 CEO 汇报，并管理一组执行人员。添加步骤如下：

1. **打开 Agents（智能体）页面并点击“New Agent（新建智能体）”**

   在公司仪表板左侧边栏点击 **Agents（智能体）**，再点击右上角的 **New Agent（新建智能体）** 按钮。

   ![智能体列表页面显示新建智能体按钮](../../../user-guides/screenshots/light/agents/agents-list-empty.png)

2. **为智能体命名并选择适配器**

   在 **Meet your next agent（认识你的下一位智能体）** 对话框中输入 **Agent name（智能体名称）**（例如“Sam”）。点击 **Choose adapter（选择适配器）**，选择适配器，然后点击 **Configure agent（配置智能体）**。

   ![“Meet your next agent”对话框询问新智能体的名称](../../../user-guides/screenshots/light/agents/new-agent-name-role.png)

3. **完成设置**

   在设置页面按提示连接模型服务提供商、选择模型、点击 **Test your agent（测试智能体）**，然后点击 **Finish setup（完成设置）**。需要帮助时，请参阅[智能体适配器](./agent-adapters.md)。

   新智能体默认向 CEO 汇报，因此设置完成后，它已处于 CEO 下一级的管理层级中。

4. **设置职位并检查经理**

   在确认页面点击 **Edit configuration（编辑配置）**，或打开智能体并在侧边菜单点击 **Harness / Runtime（运行环境）**。在 **Agent identity（智能体身份）** 卡片中设置 **Title（职位）**（例如“CTO”），并确认 **Reports to（汇报给）** 显示你的 CEO。点击 **Save changes（保存更改）**。

   ![Harness / Runtime 页面的智能体身份卡片，汇报对象选择器展开并选中了 CEO](../../../user-guides/screenshots/light/agents/new-agent-reports-to-field.png)

   新智能体现在会出现在 CEO 下方的组织架构图中，CEO 也会在委派工作时考虑由它负责。智能体预算在 **Audit → Budgets（审计 → 预算）** 中管理。

---

## 添加执行人员

执行人员向经理而不是直接向 CEO 汇报。添加步骤与添加经理相同；设置完成后，将 **Reports to（汇报给）** 从 CEO 改为某位经理即可。

例如，要添加一位向 CTO 汇报的后端工程师：

1. 点击 **New Agent（新建智能体）**，将名称设为“Jordan”，并选择适配器。
2. 配置适配器，然后点击 **Finish setup（完成设置）**。
3. 打开 **Harness / Runtime（运行环境）**，将 **Title（职位）** 设为“后端工程师”，将 **Reports to（汇报给）** 设为 CTO。
4. 点击 **Save changes（保存更改）**。

现在 CTO 可以将子任务委派给 Jordan。如果 Jordan 的任务遇到阻塞，问题会自动升级给 CTO。

---

## 更改智能体的经理

重组后，或想把某位成员转到不同工作流时，可以随时更改智能体的经理。

打开智能体，在侧边菜单中点击 **Harness / Runtime（运行环境）**，然后在 **Agent identity（智能体身份）** 卡片中修改 **Reports to（汇报给）**。点击 **Save changes（保存更改）** 后立即生效。现有任务分配不会改变，但从下一次心跳开始，新委派会遵循更新后的组织层级。

## 查看组织架构图

在左侧边栏点击 **Agents（智能体）**，然后点击 **Org chart view（组织架构视图）**（位于 **New Agent（新建智能体）** 旁）。页面会以树状图显示所有智能体及其当前状态。点击 **List view（列表视图）** 可切回列表。

## 组织架构视图的内容

组织架构视图会以**交互式树状图**呈现公司。每位智能体以卡片显示，位置由汇报关系决定：CEO 位于顶层，经理在下方展开，执行人员显示在各自经理之下。卡片之间的连线代表汇报关系，始终从经理指向下属。

卡片会显示你通常需要快速了解的信息：

- 智能体的**形象**和**状态圆点**（绿色代表活动中，黄色代表已暂停或空闲，红色代表出错，青色代表运行中，灰色代表已终止）。
- 智能体的**名称**和**职位**；如果未设置自定义职位，则显示易于理解的角色名称。
- 小号等宽字体显示的**适配器类型**，便于检查组织依赖了哪些适配器。
- **能力**摘要，显示智能体能力说明开头的几行文字。

图表上方的筛选标签（**All（全部）**、**Active（活动）**、**Paused（已暂停）**、**Error（错误）**，以及启用实验性 **Built-in Agents（内置智能体）** 设置后出现的 **Built-in（内置）**）也适用于此处。例如，你可以只查看组织中已暂停的智能体。要分享或复制组织，请在公司设置中使用 **Export（导出）** 和 **Import（导入）**；详见[导出和导入](../power/export-import.md)。

![交互式组织架构图，CEO 位于顶部，经理与执行人员按汇报关系连接](../../../user-guides/screenshots/light/org/chart.png)

### 浏览图表

图表区域支持平移和缩放：

- 在背景上**拖动**可平移，光标会变为抓取手势以提示此操作。
- **滚动或双指捏合**可放大和缩小。缩放以鼠标所在位置为中心，因此可以聚焦某个团队而不丢失当前位置。
- 使用右上角的 **+**、**−** 和 **Fit（适合窗口）** 按钮精确控制缩放。组织重组后，树形图可能超出屏幕；点击 **Fit** 可将整张图重新居中并适配视口。
- **点击卡片**可打开智能体页面。在卡片上拖动不会平移；点击始终会打开智能体。

只需文本列表时，请切换到 **List view（列表视图）**。列表会按名称显示相同的智能体，但不包含汇报连线；想看人员汇报关系时使用组织架构图。智能体页面中的修改会同时显示在两种视图中。

## 通过图表重新分配智能体

无需离开图表即可将智能体改派给另一位经理：

1. **点击要移动的智能体卡片。** 图表会打开该智能体页面。
2. 在侧边菜单点击 **Harness / Runtime（运行环境）**，然后在 **Agent identity（智能体身份）** 卡片中将 **Reports to（汇报给）** 改为新的经理。
3. **点击 Save changes（保存更改）。** 汇报关系会立即更新；返回组织架构图后，卡片会显示在新经理之下。现有任务分配不受影响，只有之后的委派会遵循新关系。

![Harness / Runtime 页面的智能体身份卡片，汇报对象选择器展开并选择了新经理](../../../user-guides/screenshots/light/org/reassign.png)

请留意以下限制：

- 不能将智能体分配给向它汇报的经理，否则会形成循环。
- 不能移除 CEO 自己的汇报关系；CEO 始终向董事会汇报。
- 重新分配有下属的经理时，整个下属子树会一起移动；下属之间原有的汇报关系保持不变。

> **建议：** 如果要进行大规模重组（例如交换两位经理的团队），可以在一个浏览器标签页打开 Agents 页面中的组织架构图，另一个标签页打开智能体的 **Harness / Runtime（运行环境）** 页面。保存后图表会自动刷新，可实时预览新结构。

## 汇报关系连线的含义

卡片之间的连线并非装饰，它们表示公司的委派和升级路径：

- 每条连线从**经理**（上方）指向**直属下属**（下方）。工作和升级也依照此方向流动：委派向下，状态和阻塞情况向上。
- 经理有**多个下属**时，下方会显示一条横向连接线，方便查看其管理范围。
- **不同子树**代表不同的汇报层级。如果出现多个根节点，通常表示某位智能体失去了经理（例如经理被终止）；请在该智能体的 **Harness / Runtime** 页面重新设置 **Reports to（汇报给）**。
- **已终止的智能体**不会显示在图表上。如果被终止的智能体有下属，这些下属会向上移动，显示在下一位仍可见的经理下方；此时应为他们重新指定 **Reports to（汇报给）**。

组织架构图是汇报结构的唯一事实来源，也是发现组织问题最快的方法，例如某位经理下属过多、某位执行人员失去上级，或组织过度依赖同一种适配器。

## 团队建立后的委派流程

当组织中不再只有 CEO 时，CEO 的委派能力会大幅增强：

1. 你批准 CEO 的策略。
2. CEO 创建高层级任务，并分配给经理（CTO、CMO 等）。
3. 经理将任务拆为子任务，并分配给自己的下属。
4. 执行人员完成工作、在任务评论中发布进展，并将任务标记为完成。
5. 经理审阅完成的子任务；工作流完成后，将自己的任务标记为完成。
6. CEO 跟进整个链条，并向你报告进展。

你的工作是批准策略和招聘请求、查看仪表板，并在任务受阻时介入。其他工作交由委派链处理。

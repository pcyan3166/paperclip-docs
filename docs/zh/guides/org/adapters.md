# 适配器管理器

Paperclip 中的每位智能体都需要一个**适配器**，让控制平面能够与指定的 AI 运行环境通信。产品内置了 Claude Code、Codex、Gemini、OpenCode、Cursor、Pi、Hermes、HTTP、Process 和 OpenClaw Gateway 等适配器；你还可以从 npm 或本地路径安装**外部适配器**扩展可用运行环境。

**适配器管理器**是查看实例已识别适配器的统一位置。你可以切换智能体菜单中的适配器可见性、安装和升级外部包，并暂停覆盖内置适配器的外部版本。

本指南介绍此页面。每种适配器的具体配置字段（工作目录、模型名称、超时和环境变量）见[智能体适配器](./agent-adapters.md)。各适配器类型的技术目录（数据格式、能力、模型列表）见[适配器参考](../../../reference/adapters/overview.md)。

> **Alpha 阶段：** 外部适配器运行时目前为 Alpha。API、磁盘目录结构和对外开放的能力列表都可能随版本变化。生产环境请固定适配器包版本。

## 打开适配器管理器

适配器管理器位于 **Settings → Adapters（设置 → 适配器）**。面包屑显示 _Company（公司）_ → _Settings（设置）_ → _Adapters（适配器）_；页面标题旁有 CPU 图标和 **Alpha** 标记。

![适配器管理器列表](../../../user-guides/screenshots/light/adapters/list.png)

标题下方会一直显示琥珀色提示，提醒外部适配器处于 Alpha 阶段，并说明每行的电源图标可以隐藏智能体菜单中的适配器，但不会移除适配器。

---

## 两个列表

页面分为两个部分：

- **External Adapters（外部适配器）**——由你或其他操作员安装的适配器包。每行都可以移除，也可以就地重新加载或重新安装。
- **Built-in Adapters（内置适配器）**——随 Paperclip 一起发布的适配器。不能移除，但可以从智能体下拉菜单中隐藏。

如果外部适配器声明的 `type` 与某个内置适配器相同（例如外部的 `claude_local` 包），服务器会将其视为**覆盖版本**。外部适配器行会显示蓝色 **Overrides built-in（覆盖内置）** 标记；对应的内置适配器也会显示一条合成行，并标记 **Overridden by …（被……覆盖）**，方便你查看受影响的内置适配器。

### 每行显示的信息

所有行都会显示同一组元数据：

- 适配器显示名称（`Claude Code`、`Codex`、包提供的 `label` 等）。
- **Built-in（内置）** 或 **External（外部）** 标记。
- 对于外部适配器，会显示来源图标：文件夹图标表示从_本地路径安装_，包图标表示从_npm 安装_。
- 如果包声明了版本，则显示版本标记（例如 `v0.3.2`）。
- 适用时显示下表中的覆盖或停用标记。
- 一行元数据：`adapter.type · package-name · N models`。

**你可能会看到的标记：**

| 标记 | 含义 |
|---|---|
| `Built-in` | 随 Paperclip 一起发布，不能移除。 |
| `External` | 由你安装，可移除、重新加载或重新安装。 |
| `Overrides built-in`（蓝色） | 此外部适配器替换了同类型的内置适配器。 |
| `Overridden by …`（蓝色） | 此内置适配器目前由某个外部适配器替换。 |
| `Hidden from menus`（琥珀色） | 适配器已安装并加载，但智能体配置下拉菜单不会提供它。 |
| `Override paused`（琥珀色） | 外部覆盖版本已加载，但暂时不生效；当前使用内置适配器。 |

## 启用或停用适配器

每行操作栏中都有电源图标。具体效果取决于适配器类型：

- **内置适配器或普通外部适配器：** 点击电源图标可切换其在菜单中的可见性。图标变暗或变灰时，适配器仍然存在，且已经配置为使用它的智能体仍会正常运行；只是新建或编辑智能体时，下拉菜单不会显示它。再次点击即可重新显示。
- **覆盖内置适配器的外部适配器：** 电源图标控制的是**暂停覆盖版本**，而不是菜单可见性。暂停不会卸载外部包，只会让运行时暂时退回内置适配器，直到你恢复覆盖。

将光标悬停在图标上，可查看当前状态的提示文字。文字会在 _Show in agent menus（在智能体菜单中显示）_、_Hide from agent menus（在智能体菜单中隐藏）_、_Pause external override（暂停外部覆盖）_ 和 _Resume external override（恢复外部覆盖）_ 之间切换，明确告知即将执行的操作。

> **说明：** 从菜单中隐藏内置适配器只是操作员的显示偏好，已有智能体仍会继续运行。若要真正停止某个适配器，请移除外部包；如果是内置适配器，则先把使用它的智能体改为其他适配器类型。

## 安装外部适配器

点击页面右上角的 **Install Adapter（安装适配器）**。对话框中有两个来源选项：**npm package（npm 包）**或 **Local path（本地路径）**。

### 从 npm 安装

1. 选择 **npm package（npm 包）**（默认选项）。
2. 输入包名，例如 `@my-org/paperclip-adapter-openrouter`。
3. 可选：输入版本；留空则安装 `latest`。
4. 点击 **Install（安装）**。

Paperclip 会获取包，验证它是否导出了 `createServerAdapter()` 工厂函数，注册适配器类型，并在 **External Adapters（外部适配器）** 中添加一行。成功后会显示提示（`Adapter installed — Type "..." registered successfully. (v...)`）。若失败，对话框会保持打开并显示错误。

### 从本地路径安装

开发适配器或要安装已克隆到磁盘的适配器时，请选择 **Local path（本地路径）**：

1. 在对话框中切换到 **Local path（本地路径）**。
2. 粘贴绝对路径（例如 `/mnt/e/Projects/my-adapter`、`/Users/me/code/my-adapter`、`E:\Projects\my-adapter`），或点击 **Choose…（选择……）**查看对应平台的说明。
3. 点击 **Install（安装）**。

Linux、WSL 和原生 Windows 路径都可以使用；Windows 路径会自动转换。本地路径安装的行会显示文件夹图标，便于识别；它们不会提供 **Reinstall（重新安装）** 操作，因为没有软件包注册表可供获取。

> **建议：** 适配器包必须导出符合 Paperclip 适配器约定的 `createServerAdapter()` 函数。详见[创建适配器](../../../reference/adapters/creating-an-adapter.md)。

## 重新加载、重新安装和移除

外部适配器每行右侧都有三种生命周期操作，分别以图标显示。

**Reload（重新加载，圆形箭头图标）**

就地重新导入适配器模块。修改本地路径适配器代码后使用此操作；运行时会热切换模块，并清除缓存的配置解析器或 UI 架构。已有智能体会在下一次运行时应用修改。

**Reinstall（重新安装，下载图标；仅适用于 npm 安装）**

从 npm 获取包的最新版本并重新加载。点击图标会打开确认对话框，列出包名、已安装版本和 npm 注册表中的最新版本：

- **Package（包）**——`@my-org/paperclip-adapter-x`
- **Current（当前版本）**——`v0.3.2`
- **Latest on npm（npm 最新版本）**——`v0.4.0`

如果已安装版本就是最新版本，对话框会显示“Already on the latest version（已经是最新版本）”。你仍然可以重新安装，强制重新获取一份干净的副本。点击 **Reinstall（重新安装）**以应用。完成后会显示提示（`Adapter reinstalled — ... updated from npm. (v...)`）。

**Remove（移除，垃圾桶图标）**

卸载外部适配器。确认对话框会提示该适配器将从注册表和适配器存储中移除；若通过 npm 安装，还会删除磁盘上的包。仍配置为使用该适配器类型的智能体会在下次运行时失败，因此请先将它们改派到其他适配器。

内置适配器行不会显示垃圾桶图标，也无法移除。

## 配置单个适配器

适配器管理器本身**不保存某个特定适配器的配置**。配置保存在使用该适配器的每个*智能体*上，包括工作目录、模型选择、超时、环境变量，以及适配器通过 UI 架构声明的其他字段。

若要配置内置适配器，请打开要修改的智能体，在侧边菜单点击 **Harness / Runtime（运行环境）**，编辑 **Adapter（适配器）** 和 **Configuration（配置）** 卡片。完成后点击 **Save changes（保存更改）**。

外部适配器的配置方式相同。智能体的 **Harness / Runtime（运行环境）** 页面会根据外部适配器的 `createServerAdapter()` 通过 UI 架构声明的内容显示表单字段，包括该适配器提供的自定义组件。

![智能体 Harness / Runtime 页面中的适配器和配置卡片，每位智能体的适配器设置位于此处](../../../user-guides/screenshots/light/adapters/detail.png)

常见内置适配器的逐项配置说明见[智能体适配器](./agent-adapters.md)。适配器需要实现的技术约定（包括 UI 解析器架构）见[适配器 UI 解析器](../../../reference/adapters/adapter-ui-parser.md)。

## 健康状态与故障排查

与插件相比，适配器结构更简单：没有后台工作进程、定时任务或容易出错的长时间运行状态。判断适配器是否健康，主要看：*模块是否加载成功？是否报告了模型？*

![内置适配器列表，每行元数据都显示适配器类型和模型数量](../../../user-guides/screenshots/light/adapters/health.png)

每行名称下方的元数据是最直接的信号，它会显示适配器 `type` 和报告的模型数量，例如 `claude_local · 13 models`。如果外部适配器的 npm 包名与类型不同，中间还会显示包名（`type · package · N models`）。

- **模型数为 `0`：** 对于会列出模型的适配器，这通常意味着适配器已加载，但无法连接服务提供商（API 密钥缺失、离线或认证失败）。请检查智能体的环境变量和服务提供商状态页面。
- **安装后行未出现：** 安装失败。重新打开安装对话框；错误提示会说明原因，例如包无效、清单文件缺失或未导出 `createServerAdapter()`。
- **重新加载或重新安装显示错误提示：** 新代码未能加载，之前的版本会继续运行。修复错误（本地路径安装常见问题是构建输出错误）后再重新加载。
- **智能体显示“adapter not found”：** 适配器已移除，或智能体上的 `type` 与已安装适配器不匹配。重新安装软件包，或更改智能体使用的适配器。
- **覆盖意外暂停：** 有人点击了覆盖内置版本的外部适配器行上的电源图标。再次点击即可恢复覆盖。

如果列表本身无法加载，页面会一直显示 _Loading adapters…_（正在加载适配器……），或出现错误提示。请刷新页面；如果问题仍然存在，请检查服务器日志中的适配器注册表错误。

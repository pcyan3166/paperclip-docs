# 工作区

智能体处理代码或文件任务时，需要一个包含正确代码状态的工作目录，也就是**执行工作区**。每个执行工作区都关联到某次任务运行。隔离工作区可让多个智能体同时处理同一项目，各自在独立分支、目录和运行环境中工作，避免互相影响。

## 启用工作区

工作区是实验性功能。打开 **设置（Settings）→ 实验性（Experimental）**，启用 **启用隔离工作区（Enable Isolated Workspaces）**。启用后，侧栏会出现“工作区”，有活动工作区的项目也会显示工作区标签。关闭后，这些界面会隐藏，直接访问 `/workspaces` 会返回问题页面。

工作区页面用于检查和管理已有工作区，不用于手动新建。智能体首次领取需要工作区的任务时，Paperclip 会自动创建它。尚未运行隔离任务时，页面显示“尚无工作区活动”是正常情况。项目主工作区在设置后可见；其他项目工作区需要运行服务或配置，隔离工作区则需要至少执行过一次任务。

## 工作区与项目

项目定义代码位置、运行方式和默认配置。任务运行时，Paperclip 会解析应该使用的工作区：创建新工作区、复用现有工作区，或使用项目默认工作区；随后将路径交给智能体。隔离或可复用模式下，工作区会在运行结束后保留。

项目启用隔离工作区后，可为任务选择：

- **隔离（新工作区）（Isolated）**：从基础分支创建新的 Git worktree 和目录，适用于功能、修复和实验。完成后审查并合并，再归档工作区。
- **复用现有工作区（Reuse existing workspace）**：与其他任务或此前运行共用目录、分支和运行服务，适合需要共享状态的相关任务。
- **项目主工作区（Project primary workspace）**：直接在项目主检出目录工作。请谨慎使用，因为修改会影响共享副本。

复用工作区时，Paperclip 会检查本次运行预期使用的环境。任务显式指定的环境优先，其次为项目策略、智能体默认环境，最后才是实例默认环境；智能体明确固定为本地默认环境时，项目策略不会擅自改变它。若复用工作区的环境与本次运行不匹配，会将冲突显式呈现，而不是静默继承旧环境。依赖任务会等待上游工作区完成最终整理后再启动；接受计划或审查交互也会等待工作区整理完毕，避免读取尚未写完的代码。

执行工作区是本地工作副本，Paperclip 不会代你推送到远程 Git 主机。完成的更改应通过 Paperclip 审查和合并。

## 运行服务与 HTTPS 预览

工作区可配置后台运行服务，例如开发服务器、数据库或构建监视器。服务由工作区界面手动启动，心跳运行不会自动启停服务。打开项目中的工作区，点击 **启动服务（Start Services）** 或单个服务按钮。不同隔离工作区有各自的运行服务，即使配置继承自同一项目。

托管工作区中的服务可通过 Tailnet 上的有效 HTTPS 地址分享，例如 `https://<node>.<tailnet>.ts.net:<port>`。HTTPS 暴露状态与进程健康状态分开显示：**正在配置 HTTPS（Provisioning HTTPS…）**、**HTTPS 就绪（HTTPS ready）**、**HTTPS 不可用（HTTPS unavailable）** 或 **等待清理（HTTPS cleanup pending）**。只有外部 HTTPS 探测通过才会显示就绪；Paperclip 不会在 HTTPS 失败时悄悄降级为 HTTP。

符合条件的服务通常会自动启用 HTTPS 预览。需要明确配置时，可添加：

```json
{ "expose": { "type": "tailscale_https" } }
```

主机名、公开端口、Vite HMR 和失败策略都有默认值。要停用，可设置 `type: "none"` 或 `tailscaleHttps: false`。此功能要求实例位于已配置 HTTPS broker 的 Tailnet 中；详见 [Tailscale HTTPS Broker](../../../reference/deploy/tailscale-https-broker.md)。

## 打开工作区

在项目的 **工作区（Workspaces）** 标签中打开工作区详情，并查看 **工作区访问（Workspace access）** 卡片。卡片会显示当前状态、原因和可执行的下一步：

- **正在配置（Provisioning）**：可启动工作区；正在创建或修复时需等待。
- **正在验证克隆（Validating clone）**：等待检查完成。
- **就绪（Ready）**：可点击 **打开工作区（Open workspace）**。
- **降级（Degraded）**：修复工作区，或在没有服务运行时启动它。
- **修复中（Repairing）**：等待数据库修复。
- **失败（Failed）**：可修复并查看修复日志；修复失败时会保留修复前备份。

卡片会说明工作区无法打开的具体原因，例如没有健康服务提供网址、克隆数据库尚未准备好、缺少公司/问题数据，或没有活跃成员。工作区就绪且配置登录交接时，点击 **打开工作区** 会使用短期、一次性的登录票据，不需要克隆密码。可选的 `next` 路径必须是同源路径，否则会回到 `/`。如果未配置登录交接，或会话中没有克隆用户，则改用创建克隆时保存的本地凭据登录。

## 配置继承与生命周期

项目可定义服务启动方式、环境变量和运行命令。隔离工作区默认继承项目配置，也可针对单个工作区覆盖。继承的是运行配置，不是运行中的进程；每个工作区仍运行独立服务。

工作区会持续保留，直到显式归档或清理，因此分支状态、未提交更改和服务可跨心跳继续使用，多个任务也可能累积更改。归档前请先审查并合并要保留的工作；归档可能清除未合并或未提交的工作。

## 工作区列表与详情

侧栏的 **工作区** 展示全公司视图，按项目分组；项目的 **工作区** 标签显示该项目的列表。项目有运行服务时通常排在前面。卡片展示工作区类型、名称、分支、路径及相关运行信息。

详情页面将信息分成多个区域：

- **服务（Services）**：运行服务、控制项和 HTTPS 预览状态。
- **配置（Configuration）**：工作区设置、继承的上下文、实际目录和运行时覆盖。
- **运行日志（Runtime logs）**：服务操作与日志，帮助排查启动或运行问题。
- **任务（Tasks）**：显示来源任务及关联任务；来源任务是创建该工作区的任务，关联任务是后来使用它的任务。

若任务在智能体启动前停止，请检查工作区配置、环境匹配、服务健康状态、克隆数据库和任务状态。工作区列表可帮助判断任务是否使用独立 Git worktree；简单工作不一定需要隔离，但多个智能体并行修改同一代码库时通常值得启用。

## 常见工作流

为代码任务选择隔离工作区，让智能体在独立分支修改；启动需要的服务并查看 HTTPS 预览；审查结果后合并分支；确认不再需要后归档工作区。相关指南：[自定义沙盒镜像](./custom-sandbox-images.md)、[项目](./projects.md)和[问题页面](../../../guides/day-to-day/issues.md)。

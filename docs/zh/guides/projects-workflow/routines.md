# 心跳与例程

给每个智能体设置“每几分钟醒来看看有没有事情做”的定时器看起来很主动，实际却容易带来大量空运行、额外 token 费用和需要暂停的智能体。Paperclip 默认让智能体保持待命，等真实工作到达再运行。本指南介绍定时心跳和例程两种机制，以及如何管理例程的触发器、变量和运行记录。

## 智能体如何开始运行

| 来源 | 触发方式 |
|---|---|
| **定时器** | 心跳间隔到期，无论是否有新工作（例如每 5 分钟）。 |
| **任务分配** | 分配新任务，或智能体未完成任务收到新评论。 |
| **按需唤醒** | 你在界面点击“立即唤醒”，或其他智能体委派工作。 |
| **自动化** | 例程按计划触发并创建任务。 |

只有定时器会在没有新事件时唤醒智能体；其他方式都由实际工作触发。

## 为什么定时心跳默认关闭

新智能体的定时心跳默认关闭，通常建议保持关闭。每次定时唤醒都会消耗 token、产生运行记录和待阅读内容。多个智能体频繁轮询会制造大量“无事可做”的运行记录。暂停智能体虽然能降噪，却也会阻断你希望保留的任务、评论和例程唤醒。若你经常暂停、恢复某个智能体，先检查它是否真的需要定时心跳。

在智能体详情页的 **运行策略（Run Policy）** 中，可以设置 **按间隔执行心跳（Heartbeat on interval）** 和 **每 N 秒执行一次（Run heartbeat every N sec）**。只有开启间隔心跳后才会显示间隔；若确实需要定时轮询，通常按分钟或小时设置即可。高级运行策略还包含 **按需唤醒（Wake on demand）**、运行冷却时间和最大并行运行数。大多数智能体适合关闭定时心跳、开启按需唤醒：它在仪表板仍显示为活动，但没有工作时不消耗资源。

## 用例程安排周期工作

例程是可重复使用的任务定义，并附有触发器。触发时会创建或重新打开任务；若任务已分配智能体，分配事件会唤醒它。例程支持：

- **计划（Schedule）**：按本地时区的 cron 表达式运行，例如每个工作日早上 9 点。
- **Webhook**：由 Paperclip 外部系统调用的签名 URL。

### 创建例程

1. 打开侧栏中的 **例程（Routines）**，点击 **新建例程（New Routine）**。
2. 填写标题和任务说明。
3. 添加触发器。计划触发器使用 cron 表达式，默认 `0 10 * * *` 表示本地时间每天 10 点。
4. 指定负责执行的智能体并保存、启用。

触发后 Paperclip 会创建任务并分配给智能体，智能体随即运行。收件箱中的运行记录会链接回触发它的例程。

并发策略决定例程仍在运行时遇到下一个计划触发点该如何处理：合并为一个后续运行、跳过本次，或始终排队。补跑策略决定调度器暂停期间错过的触发点是跳过，还是按上限分批补跑。多数情况下，运行中合并、错过时跳过，可以避免任务堆积或恢复后突然大量执行。

## 例程列表

列表行显示标题及状态（`paused`、`draft`、`archived`）、项目、默认智能体、最近一次运行的时间和状态，以及 **立即运行（Run now）**、启用开关和更多菜单。点击行进入详情；行内操作不会离开列表。归档例程可以恢复，暂停例程保留配置但忽略触发器。

例程可放入文件夹。默认按文件夹分组，尚未归档到文件夹的例程位于 **未归类（Unfiled）**。文件夹可重命名、修改颜色或删除；删除文件夹会将例程移至“未归类”，不会删除例程。可批量选择并移动例程。列表支持按更新时间、创建时间、最近运行或标题排序，也支持按文件夹、项目、智能体分组或不分组；分组和排序会按公司保存。

点击 **创建例程（Create routine）** 会打开编辑器，填写标题、默认负责人、默认项目、Markdown 指令，以及可选的并发和补跑策略。未指定默认智能体的草稿可以保存，但会保持暂停。保存后会进入详情页的触发器区域，以便添加计划或 webhook。

**立即运行** 可填写运行时变量，并为这次运行临时指定负责人、项目和执行工作区。**暂停** 会让例程忽略触发器但保留配置；**归档** 会从默认列表隐藏例程但不删除它。页面顶部的 **查看所有运行（View all runs）** 会打开审计中的运行记录，查看运行状态及产出的工作。关闭“精简界面（Streamlined UI）”时，页面改用“例程”和“最近运行”两个标签。

## 例程详情页

详情页顶部提供可编辑标题、手动运行按钮、启用开关和状态标签。若例程由插件管理，页面会显示插件名称和资源键。左侧子导航包括：

- **概览（Overview）**：负责人、项目、Markdown 指令、触发器摘要、下次运行和最近运行记录。
- **触发器（Triggers）**：查看、添加和编辑计划或 webhook。
- **变量（Variables）**：识别标题和指令中的 `{{name}}` 占位符。
- **交付（Delivery）**：设置并发和补跑策略。
- **机密（Secrets）**：为例程任务提供可引用的环境值。
- **运行（Runs）**：搜索例程创建的任务，并在原处查看或更新。

各区域有独立网址，可直接链接并使用浏览器前进/后退；旧版 `?tab=` 链接会转到对应区域。概览中的说明支持 Markdown 编辑，保存失败时页面会提示。例程说明也支持段落级评论。运行历史按时间显示状态和产出任务，方便追踪某次计划如何执行。

## Cron 与时区

计划触发器使用 cron 表达式。界面提供可视化时间选择器和人类可读的计划描述，便于核对实际运行频率。计划按所配置时区解释；注意时区设置和夏令时可能影响实际触发时间。保存后应检查界面显示的下次运行时间。

## Webhook 触发器

Webhook 适用于由其他应用、脚本或 GitHub 事件触发的工作。触发器会提供 URL 和签名密钥。复制 URL 和密钥，将请求方配置为向该地址发送事件。通用方式可用于任何能发 HTTP 请求的系统；GitHub 路径则按仓库 Webhook 配置事件和签名。

设置前确认 Paperclip 实例可从请求方网络访问。创建 webhook 后，需要完成设置并启用触发器；未启用的触发器不会启动例程。签名模式用于验证请求来源，重放窗口限制旧请求被重复使用。密钥轮换时，同时更新外部系统的密钥。触发器可单独启用、禁用或归档。

Fireflies 等会议摘要服务也可通过通用 webhook 路径把会议事件交给例程处理。具体事件字段取决于外部服务；请在例程指令中使用对应的变量模板。

## 变量模板与补跑

在标题或说明中使用 `{{变量名}}` 声明变量。手动点击 **立即运行** 时可填写变量值；触发器运行时会按触发事件提供可用值。请让变量名明确，并在指令中说明缺少值时应如何处理。

调度器离线或例程暂停期间可能错过计划。补跑策略控制是否补发错过的任务，并设定批次上限，避免一次补跑过多。请根据工作时效和负载选择跳过或有限补跑。

## 何时应该使用定时心跳

只有当智能体必须轮询没有事件通知机制的来源时，定时心跳才合适。其余周期性任务优先用例程；有新任务或评论时，按需唤醒已足够。暂停智能体和关闭心跳不同：暂停会阻止所有唤醒，关闭定时心跳仍允许任务分配、评论和例程唤醒。

健康配置通常让智能体按需运行，把有计划的重复工作交给例程，给每个触发器清楚的负责人和说明，并定期检查运行记录和预算。

## 附录：智能体开发者的心跳协议

一次运行通常依次：确认智能体身份；跟进待审批项；获取分配；选择任务；锁定任务；读取上下文；执行工作；更新状态；必要时委派。智能体应先继续已有进行中任务，再领取新任务；应在工作过程中提交进度，并在受阻时明确说明阻塞原因。不得重复领取或并行修改同一工作而不做协调。运行协议详见[问题指南](../../../guides/day-to-day/issues.md#appendix--issue-workflow-patterns-for-agent-developers)。

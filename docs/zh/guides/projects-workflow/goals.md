# 目标

Paperclip 中的目标是一项成果描述，用来说明公司想要实现什么。目标位于项目和任务的上层：它不包含代码，不会被直接“执行”，也没有执行工作区。目标是工作的锚点。项目会关联到目标，CEO 提出的策略通常会指出它将推动哪些目标。

如果说任务回答“要做什么”，项目回答“在哪里做”，那么目标回答的是“为什么这件事重要”。一家公司可能只有少数长期稳定、很少变动的目标，而目标下的项目和任务则不断调整。

本指南介绍：

- 目标列表及树状视图。
- 目标详情页和其中的标签页。
- 如何将项目关联到目标。
- 目标的父子层级。

---

## 目标列表

**Goals（目标）** 页面会列出当前选中公司的所有目标。目标可以有父目标和子目标，因此页面以树形结构呈现，而不是平铺列表。

![目标列表](../../../user-guides/screenshots/light/goals/list.png)

### 树状视图

树形结构由每个目标上的 `parentId` 字段决定：

- **顶层目标**没有父目标，显示在树的根部。
- **子目标**有父目标，并缩进显示在父目标下方。
- 子目标按父目标分组，自身也可以有子目标；嵌套层数没有限制。

树中的每一行都会显示目标标题、状态标记和层级标签（例如 `company`、`team` 或公司使用的其他层级名称）。点击一行可打开目标详情页。

### 创建目标

列表中已有目标时，页面顶部会显示 **New Goal（新建目标）** 按钮。点击后会打开新建目标对话框，你可以设置标题、描述、层级以及可选的父目标。如果要创建某个现有目标的子目标，通常直接打开该目标详情页，再在 **Sub-Goals（子目标）** 标签页点击 **Sub Goal（新建子目标）** 更方便，因为父目标会自动填好。

如果公司还没有任何目标，列表会显示空状态和一个较大的 **Add Goal（添加目标）** 按钮，点击后同样会打开该对话框。

### 筛选

目标列表没有单独的筛选栏。当前公司的全部目标（无论层级）都会显示在树中。通常要进一步查看时，打开目标并检查关联项目或子目标。如果目标很多，可使用浏览器的页面内搜索或公司的全局搜索按标题查找。

## 目标详情

从树中打开目标后会进入详情页。页面分为三个区域：显示目标身份信息的页眉、可编辑标题和说明的主体，以及包含 **Sub-Goals（子目标）** 和 **Projects（项目）** 的标签栏。

![目标详情](../../../user-guides/screenshots/light/goals/detail.png)

### 页眉与主体

页眉显示：

- **Level（层级）**——以较淡的大写文字显示目标层级（例如 `COMPANY` 或 `TEAM`）。Paperclip 使用层级区分公司的高层成果和范围较窄的团队或工作流目标。
- **Status（状态）**——状态标记。目标沿用项目和任务的状态词汇，以保持界面一致，让你快速判断目标是否正在推进、已达成或已放弃。
- **Properties toggle（属性开关）**——右侧的小滑块图标。关闭属性面板后，点击它可重新打开。属性面板允许你在不离开页面的情况下修改层级、状态和其他元数据。面板会显示父目标，但不能在此更改；参见[更改父目标与扁平化](#更改父目标与扁平化)。

页眉下方的主体区域包含：

- 可直接编辑的**标题**。点击标题即可修改；离开编辑框时会保存。
- 可直接编辑的**描述**，支持多行 Markdown。你可以粘贴或拖入图片；图片会上传至目标的资源目录。可在描述中说明“成功意味着什么”：目标达成后，现实会发生什么变化？

### 标签页

主体下方有两个标签页：

- **Sub-Goals（子目标，N）**——目标的子目标，使用与主目标页面相同的树形视图，但只显示当前目标的后代。点击 **Sub Goal（新建子目标）** 可打开父目标已预先填写的新建目标对话框。
- **Projects（项目，N）**——所有关联到此目标的项目。每行显示简洁的项目条目，包括颜色、名称、描述预览和状态。点击可打开项目详情。如果没有关联项目，标签页会显示较淡的“No linked projects（无关联项目）”提示。

添加、移除或解除关联子目标和项目后，标签页上的数量会同步更新，因此也能快速概览该目标下的工作规模。

### 进度汇总

Paperclip 不会计算目标的数值百分比。目标的状态字段是唯一权威信号，由人类（或 CEO 在确认目标已经达成或放弃时）设置。如果想查看定性进度，可打开 **Projects（项目）** 标签页，观察关联项目状态分布（例如 `in_progress`、`completed` 和 `backlog` 的数量）；这能说明目标进展，而不必让系统编造一个合成百分比。

若要了解更细的进展，请进入单个项目查看 **Issues（任务）** 标签页。

## 将任务和项目关联到目标

目标不会直接包含任务。关联关系通过项目实现：一个项目可关联一个或多个目标，项目中的任务会继承这一关联。CEO 规划工作时遵循以下链条：

```
目标 → 项目 → 任务 → 执行工作区 → 智能体运行
```

### 将项目关联到目标

可以通过两种等效方式建立关联：

- **从项目页面操作**——打开项目的 **Configuration（配置）** 标签页（参见[项目](../../../guides/projects-workflow/projects.md)），在 **Goals（目标）** 字段中添加目标。修改会自动保存。
- **从目标页面操作**——打开目标详情页，切换到 **Projects（项目）** 标签页，然后使用关联界面中的项目选择器。如果刚创建了目标，想一次性关联多个现有项目，这种方式很方便。

一个项目可以关联多个目标。这是有意设计的：一项工作往往能推动多个成果，强制要求项目只有一个父目标反而会掩盖这一事实。

### 关联单个任务

由于关联关系通过项目传递，任务层没有单独的“将任务分配给目标”界面。要改变任务归属的目标，可将任务移到其他项目，或将该任务所在项目关联到你希望汇总的目标。

如果你希望某项任务显示在另一个目标下，但又不想移动到其他项目，通常应把其项目关联到额外目标，而不是为单项任务单独增加例外关系。

### 为什么采用间接关联

让目标位于项目层，而不是任务层，可以避免目标直接关联数百项任务后变得难以阅读。任务自然归属于项目，项目自然归属于目标。中间多一层正是此设计的目的，并非缺陷。

## 目标层级

目标可以通过**父目标**关系嵌套。没有父目标的目标是根目标；有父目标的目标是其子目标。

### 何时使用子目标

当一个成果规模较大，需要拆分为多个可独立跟踪的部分时，可以使用子目标。根目标“发布公开测试版”可以包含“核心产品就绪”“定价与账单上线”和“完成发布计划”等子目标。每个子目标可以有自己的关联项目和状态，而根目标继续表达更高层的整体方向。

不要用子目标代替项目。如果工作已经具体到可以指定代码仓库并开始创建任务，那它应当是一个项目，而不是子目标。

### 创建子目标

在父目标详情页切换到 **Sub-Goals（子目标）** 标签，然后点击 **Sub Goal（新建子目标）**。新建目标对话框会自动填写父目标。填写标题、描述和层级后保存。

你也可以在主 **Goals（目标）** 页面打开新建对话框并选择父目标；这两种方式的结果相同。

### 更改父目标与扁平化

创建目标时会确定它的父目标：可在新建对话框中选择父目标，或使用自动填好父目标的 **Sub Goal（新建子目标）** 按钮。当前应用没有提供编辑现有目标父关系的字段，因此要更改父目标，或将子目标扁平化为根目标，需要使用 CLI 或 API，而不能在属性面板中操作：

```sh
# 将目标重新挂到另一个父目标下
paperclipai goal update <goal-id> --parent-id <new-parent-goal-id>

# 将子目标提升为顶层目标
paperclipai goal update <goal-id> --parent-id null
```

也可以通过 API 的 `PATCH /goals/{id}` 修改 `parentId` 字段（传入 `null` 可将目标提升为根目标）。修改生效后树形视图会重新绘制。全部参数见[目标 CLI 参考](../../../reference/cli/goal.md#update-a-goal)。

通常不需要很深的目标层级。两到三层就足以表达结构，也不会让树形图难以阅读。

### 状态不会自动向上汇总

Paperclip 不会根据子目标自动计算父目标状态。每个目标的状态互相独立。这样行为更可预测：何时算达成由人类（或 CEO）决定；代价是子层工作明显完成时，你需要手动更新父目标状态。

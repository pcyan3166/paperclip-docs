# 项目

项目是 Paperclip 用来整理相关工作的容器。如果目标回答“为什么做这件事”，任务回答“具体要做什么”，那么项目处于两者之间：它将一组工作绑定到具体环境，例如代码仓库、工作目录、预算范围和执行工作区，让智能体能够接手任务并推进工作。

Paperclip 中的每项任务都属于某个项目；每个执行工作区也都隶属于某个项目；预算也可以限定在项目范围内。当你告诉智能体“处理营销网站”时，实际上是在让它“处理‘营销网站’项目中的任务，并使用该项目关联的代码和配置”。项目能把 CEO 撰写的抽象策略转化为智能体可以签出并执行的具体工作。

本指南先介绍项目列表，再介绍打开项目后会看到的标签页：**Tasks（任务）**、**Workspaces（工作区）**、**Configuration（配置）** 和 **Budget（预算）**。插件也可以添加自己的标签页，例如 **Files（文件）**。

---

## 项目列表

**Projects（项目）** 页面会列出当前选中公司中所有活动项目（未归档项目）。页面左上方有 **Sort: Name（排序：名称）** 控件，右上方有 **Add Project（添加项目）** 按钮。

![项目页面显示“按名称排序”控件、“我的项目”分组中的两个项目，以及“添加项目”按钮](../../../user-guides/screenshots/light/projects/list.png)

项目分为 **My Projects（我的项目）** 和 **Other Projects（其他项目）** 两组。你主动离开的项目会在“其他项目”中以较淡的样式显示。每个分组标题都会显示其中的项目数量。

### 列表行的组成

从左到右，每个项目条目包含：

- **项目图标块**——带有项目图标的小方块；未选择其他图标时使用文件夹图标。项目设置了颜色时，图标块会使用该颜色，否则为中性灰色。
- **项目名称**——主要标题。点击后打开项目详情页，默认显示“任务”标签；如果之前访问过该项目，Paperclip 会恢复你上次查看的标签。
- **描述**（副标题）——设置了项目说明时显示其内容；否则此处为空。
- **任务数**——项目中的任务数量，例如“9 项任务”。
- **预算**和**目标日期**——只有设置了相应值时才会以较淡文字显示。
- **状态标记**——当前项目状态，例如 `planned` 或 `in progress`。标记颜色与应用其他位置的任务状态标记一致。
- **锁形图标**——私有项目会在列表行右侧、侧边栏和编辑框的项目选择器中显示锁。
- **加入/离开**和**星标**——仅影响你个人侧边栏的控制项（参见[在侧边栏保留项目和智能体](#在侧边栏保留项目和智能体)）。

已归档项目不会出现在列表中。你仍然可以通过直接链接访问，也可以在项目的“配置”标签页中取消归档。

### 排序和操作

列表没有筛选器，但可以更改排序。点击 **Sort: Name（排序：名称）**，然后选择 **Name（名称）**、**Updated（更新时间）**、**Created（创建时间）** 或 **Target date（目标日期）**。再次点击当前选项可切换升序和降序。

右上角的 **Add Project（添加项目）** 按钮会打开新建项目对话框，可设置名称、描述、目标日期、初始状态和颜色。项目创建后，可以在“配置”标签页修改代码仓库绑定、环境变量和执行工作区行为；创建对话框只要求填写项目存在所需的最少信息。

如果公司还没有项目，页面会显示空状态，提示你添加第一个项目。

### 在侧边栏保留项目和智能体

随着公司变大，左侧边栏中的 **Projects（项目）** 和 **Agents（智能体）** 分组可能变得拥挤。你可以**加入**或**离开**单个项目和智能体，保持自己的侧边栏整洁；这只是个人设置，只影响你的导航。

- 将光标悬停在侧边栏中的项目或智能体上，使用 **Join（加入）** 或 **Leave（离开）**。离开后，它会从你的侧边栏隐藏；重新加入后会再次显示。
- 默认情况下，所有内容都处于**已加入**状态，因此新项目会先显示给所有人，直到有人选择离开。
- 此设置仅用于个人导航。离开项目不会暂停或归档项目，也不会影响队友；项目仍会继续运行，并且仍可从 **Projects（项目）** 和 **Agents（智能体）** 页面访问。你只是整理自己的界面。

每次加入或离开都会记录在公司活动日志中，因此即使更改只影响某个人的侧边栏，也可供审计。

## 项目页眉

打开项目后，页面顶部会显示其基本信息：

- **图标和颜色**——点击名称旁的方块可更换图标或颜色。
- **名称**——点击项目名称可直接重命名。
- **星标**——右上角的星标按钮可将项目固定，方便快速访问。
- **项目摘要**——内置 Summarizer 智能体会在摘要卡片中更新项目状态、下一步和需要操作员处理的事项。尚未配置 Summarizer 时，卡片会显示 **Set up Summarizer（设置摘要器）** 按钮。

页眉下方是项目标签。项目已不再设有单独的 Overview（概览）标签：描述位于 **Configuration（配置）** 标签，日常进展位于 **Tasks（任务）** 标签。

Paperclip 不会为项目保存单一的“完成百分比”字段。你可以从“任务”标签中的任务状态分布了解进度，包括 `todo`、`in_progress`、`in_review`、`done` 和 `cancelled`。

### 插件添加的标签

插件可以在 **Budget（预算）** 后添加自己的标签。例如，示例文件浏览器插件会添加一个 **Files（文件）** 标签，用于浏览和编辑项目工作区中的文件。如果你看到本指南没有介绍的标签，通常是由实例上已安装的插件添加的。

## “任务”标签

“任务”标签是项目的任务看板，与全局 **Tasks（任务）** 页面显示同一列表，只是已预先筛选到当前项目。日常工作中你会经常使用它；打开项目时默认也会显示此标签。

![项目的任务标签](../../../user-guides/screenshots/light/projects/issues.png)

### 显示内容

此标签使用共享任务列表，因此视图、分组、筛选和排序控件都与全局列表相同：

- 每行显示任务标识、标题、状态图标和最近更新时间；有智能体正在处理任务时，还会显示实时运行指示器。
- 子任务嵌套在父任务下方，点击父任务可折叠子任务。
- 打开标签期间，实时运行指示器每隔几秒更新一次，因此无需刷新页面，就能观察运行开始、推进和结束。

### 筛选和视图状态

此标签的视图设置（分组、排序，以及哪些分组已折叠）会按项目独立保存，与全局任务列表分开。切换到其他项目再回来时，会恢复原来的布局；切换到全局任务列表也不会影响项目视图。

由于任务列表已限定在当前项目，因此没有“按项目筛选”控件。你仍可通过 **Filter（筛选）** 按钮根据状态、负责智能体或人员、创建者、标签等条件筛选，也可以使用 **Search tasks...（搜索任务……）** 输入框。

### 在项目中创建任务

从此标签点击 **New Task（新建任务）** 创建的任务会默认归入当前项目，无需手动设置项目字段。若要在其他项目中创建任务，请先切换到那个项目，或者使用全局 **New Task（新建任务）** 对话框明确选择项目。

### 与执行工作区的关系

智能体接手任务时，该任务可能会关联到一个执行工作区，也就是项目代码的一份特定工作副本。下一节的“工作区”标签会按工作区汇总任务；工作开始后，这种查看方式往往更有用。底层工作区模型见[执行工作区](./workspaces.md)。

## “工作区”标签

“工作区”标签显示与项目关联的工作区，包括项目自身的检出目录，以及智能体创建的执行工作区。只有实例启用了实验性 **isolated workspaces（隔离工作区）** 设置时才会出现此标签；否则 Paperclip 会将你带到“任务”标签。

![项目的工作区标签](../../../user-guides/screenshots/light/projects/workspaces.png)

### 工作区卡片上的信息

每个工作区都会显示为一张卡片。顶部标签会标明它是 **Execution workspace（执行工作区）** 还是 **Project workspace（项目工作区）**，同时显示最近更新时间；如果包含运行时服务，还会显示正在运行的服务数量。卡片中包括：

- 工作区名称、分支、路径，以及运行中服务的 URL。分支和路径旁有复制按钮。
- **Linked tasks（关联任务）**——当前关联到该工作区的任务，方便查看其中正在执行的工作。
- **Start services（启动服务）** / **Stop services（停止服务）**——控制工作区定义的运行时服务（开发服务器、监控进程、数据库等）。运行时服务不会自动启动，需要你从此卡片控制。
- **Close workspace（关闭工作区）**——仅适用于执行工作区。点击后打开关闭对话框；关闭时会停止工作区的运行时服务并将其归档。

状态为 `cleanup_failed` 的执行工作区会单独归入琥珀色显示的 **Cleanup attention needed（需要处理清理问题）** 分组。这些工作区无法完全清理，需要人工决定：点击卡片上的 **Retry close（重试关闭）**，或自行检查底层路径。

### 项目工作区与执行工作区

项目的主检出目录始终作为 **Project workspace（项目工作区）** 卡片显示（上方截图中的 `main`）。如果未创建隔离工作区，每项任务都会在这里运行，因此没有关闭按钮。执行工作区是 Paperclip 为单项任务创建的隔离检出目录。有关主工作区、隔离工作区和复用工作区的完整概念说明，请参阅[执行工作区](./workspaces.md)。

### 智能体何时创建工作区

智能体接手配置为隔离运行的任务，或你明确要求时，会创建隔离工作区。“工作区”标签可用于长期监控、管理和关闭工作区。列表过长时，安全关闭最早完成的工作区即可；一旦底层分支已合并或丢弃，该工作区就不再有用途。

## “配置”标签

项目可编辑的属性都位于“配置”标签。大多数字段在编辑后会自动保存；字段旁会显示小型 **Saving（保存中）** / **Saved（已保存）** 指示器。唯一例外是源代码仓库区域，它有自己的 **Save changes（保存更改）** 按钮，见下文。

![项目配置标签](../../../user-guides/screenshots/light/projects/configuration.png)

### 基本属性

- **Name（名称）**——在列表和所有面包屑中显示的项目名称。修改名称是安全的；使用项目 slug 的链接仍能正常解析。
- **Description（描述）**——完整项目说明，以 Markdown 呈现。点击可编辑；离开编辑器时保存。
- **Env（环境）**——项目环境变量（见下文）。
- **Updated（更新时间）**、**Target Date（目标日期）** 和 **Created（创建时间）**——只读日期。仅设置了目标日期时才显示该字段。

<a id="private-tasks-and-sharing"></a>
### 项目可见性

**Visibility（可见性）** 行决定谁能找到该项目。项目默认是 **Open to company（公司全员可见）**，公司中的所有人都能看到。你单独设为私有的任务仍遵循各自的访问规则。

打开开关可将项目设为 **Private（私有）**。之后只有有权访问该项目的成员能够找到它，而且这些成员可以查看其中的所有任务。项目中的某项任务仍可单独分享给项目之外的人。点击 **Manage access（管理访问权限）** 会打开 **Private project access（私有项目访问权限）**，你可以添加或移除人员和智能体。无权更改访问权限的人员会看到 **View access（查看访问权限）**。

要重新向全公司开放私有项目，请关闭开关。Paperclip 会要求你确认 **Open this project to the company?（向全公司开放此项目？）**。项目内的私有任务仍保持私有。只通过项目获得访问权限的成员将失去权限；若他们仍需访问，请先单独分享相关任务。选择 **Keep private（保持私有）** 可取消操作。

私有项目中创建的新任务会自动设为私有。详见[私有任务和分享](../day-to-day/issues.md#private-tasks-and-sharing)。

### 源代码仓库

标记为可选的 **Source repos（源代码仓库）** 区域用于将项目连接到 GitHub：

- **Add GitHub repo（添加 GitHub 仓库）** 可从已连接的 GitHub 账户中选择仓库。如果尚未连接 GitHub，也可以从此处连接。添加一个仓库后，按钮会改为 **Add another repo（添加另一个仓库）**。
- **Existing repo URL（现有仓库 URL）** 会以普通链接显示通过旧方式绑定的仓库 URL。点击 **Edit（编辑）** 可更改。

仓库更改不会自动保存。选择完成后，点击 **Save changes（保存更改）**；若要撤销，则点击 **Discard changes（放弃更改）**。保存成功后会显示 **Changes saved（更改已保存）**。

### 代码库和本地文件夹

第一个分隔线下方的 **Codebase（代码库）** 区域会显示项目代码在 Paperclip 所运行机器上的位置。使用 **Set local folder（设置本地文件夹）**（或 **Change local folder（更改本地文件夹）**）指定目录。智能体会直接在此文件夹中工作，也可以在其基础上创建隔离工作树。如果项目的主工作区定义了运行时服务，也会在此处列出。

### 环境变量

每个项目都可以定义环境变量，这些变量会注入智能体运行和执行工作区命令中。在 **Env（环境）** 行进行管理：

- 点击 **Add variable（添加变量）** 可新增变量；也可直接重命名或删除变量。
- 机密变量通过机密信息存储区保存，并以遮蔽形式显示。
- 项目变量会扩展智能体在项目中运行时看到的环境，不会更改公司级设置。

### 执行工作区配置

启用隔离工作区后，“配置”标签会显示 **Execution Workspaces（执行工作区）** 区域，其中包含项目级设置：

- **Enable isolated task checkouts（启用隔离任务检出）**——是否对该项目使用隔离工作区。关闭后，每项任务都在项目主检出目录中运行。
- **New tasks default to isolated checkout（新任务默认使用隔离检出）**——开启后，新任务默认创建自己的隔离工作区；关闭后，新任务留在主检出目录，除非有人单独选择隔离。单个任务可覆盖此设置。
- **Shared workspace concurrency（共享工作区并发策略）**——多个运行如何共用主检出目录，可选 **Auto（自动）**、**Serialize（串行）** 或 **Allow（允许并发）**。

点击 **Show advanced checkout settings（显示高级检出设置）** 可查看其他选项：

- **Environment（环境）**——隔离运行使用的环境（仅在启用环境且可用环境多于一个时显示）。
- **Base ref（基础引用）**——新建隔离工作区时使用的 Git 引用，可为分支、标签或提交。
- **Branch template（分支模板）**——Paperclip 创建新分支时使用的命名格式，例如包含任务标识符的模板。
- **Worktree parent dir（工作树父目录）**——Paperclip 在磁盘上放置新 Git 工作树的位置。
- **Provision command（初始化命令）**和 **Runtime provision command（运行时初始化命令）**——创建新工作区时执行的可选命令，例如安装依赖项。
- **Teardown command（拆除命令）**——关闭工作区前运行的可选命令。

这些设置与[执行工作区](./workspaces.md)中介绍的行为相对应。通常每个项目设置一次后就很少需要更改。

### 归档和取消归档

“配置”标签底部的 **Danger Zone（危险操作）** 区域中有 **Archive project（归档项目）** 按钮。Paperclip 会在归档前要求你点击 **Confirm（确认）**。归档会将项目从侧边栏和项目选择器中隐藏，但不会删除任何内容：任务、工作区和历史记录都会保留。项目已归档时，同一位置会显示 **Unarchive project（取消归档项目）**。

归档后，页面会返回仪表板，并显示确认提示。如果归档失败（例如服务器出错），会出现失败提示，项目仍保持活动状态。

### 预算硬性上限导致暂停

如果项目因为预算策略触及硬性上限而暂停，项目页面顶部会显示红色 **Paused by budget hard stop（预算硬性上限导致暂停）** 标签（不在本标签内部显示，但解决方法位于“预算”标签，值得在此说明）。你可以提高预算，或处理预算覆盖审批，以恢复项目。

## “预算”标签

“预算”标签管理项目范围的预算策略。这是独立于以下预算之外的项目级上限：

- **智能体预算**——在各智能体配置中设置的单体上限。
- **公司预算**——限制整家公司总支出的上限。

当单个项目需要独立于执行智能体的硬性支出上限时，项目预算很有用。预算的基础概念见[成本与预算](../day-to-day/costs.md)。

![项目的预算标签](../../../user-guides/screenshots/light/projects/budget.png)

### 如何读取预算卡片

预算标签会为当前项目显示一张预算策略卡片：

- **Scope（范围）**——此处始终是 `project`，目标为当前项目 ID 和名称。
- **Metric（指标）**——`billed_cents`。Paperclip 按美分跟踪可计费费用，并转换为货币金额显示。
- **Window（周期）**——`lifetime`。项目预算默认采用整个生命周期累计上限，而非滚动周期；该项目的总支出会累计至上限。
- **Amount（金额）**——已设置的预算上限，可在卡片中编辑。
- **Observed amount（已支出金额）**——项目目前已用预算。
- **Remaining amount（剩余金额）**——上限减去已支出金额。
- **Utilization percent（使用比例）**——已用金额占上限的百分比。达到警告阈值（默认 80%）后，卡片会提示项目正接近预算上限。
- **Hard stop enabled（启用硬性停止）**——开启后，超出预算会自动暂停项目。这会触发前文提到的“预算硬性上限导致暂停”标签。
- **Notify enabled（启用通知）**——开启后，项目预算达到警告阈值时会通知公司成员。
- **Paused（已暂停）**——显示项目当前是否暂停；若已暂停，也会显示 **Pause reason（暂停原因）**。

### 设置或修改预算金额

点击金额字段，输入美元预算上限（界面会转换为美分），然后保存。修改会使预算概览、项目详情、项目列表和仪表板缓存失效，因此所有显示预算金额的位置都会更新。

如果项目尚无明确策略，卡片会显示占位状态：金额为零、已用金额为零，且 `isActive: false`。保存非零金额后会创建预算策略。

### 与智能体预算和公司预算的区别

项目预算不会取代智能体预算或公司预算，三者会并行生效：

- 智能体触及自身预算时会停止，不受项目剩余预算影响。
- 项目触及项目预算时会暂停，无论当前是哪位智能体在其中工作。
- 公司预算是整体上限；公司预算触及硬性上限后，所有项目中的智能体都无法继续产生支出。

三类预算如何交互、如何读取公司费用概览，以及触及硬性上限后如何处理预算覆盖审批，请参阅[成本与预算](../day-to-day/costs.md)。

### 硬性上限后恢复项目

项目因硬性上限暂停时，你有两种选择：

1. 在“预算”标签中**提高预算金额**。新上限超过已用金额后，项目会在下一次运行时恢复。
2. 在审批队列中**处理预算覆盖审批**。这是智能体申请增加可用预算的正式流程，无需人工直接修改上限。

审批和费用指南中会进一步介绍这两种处理方式。

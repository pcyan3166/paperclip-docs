# 关键概念

开始使用 Paperclip 前，花五分钟了解这里介绍的概念会很有帮助。有些概念在其他软件中没有完全对应的说法；如果一开始就理解错，后续使用时可能会遇到难以理清的困惑。

本指南会介绍贯穿 Paperclip 的七个概念。先用类比解释，再补充技术细节。

---

## 公司（Company）

**一句话解释：** 公司是一个独立的 AI 组织，包含一个目标、一支智能体团队、一个任务看板和一份预算。

**类比：** 可以把公司想成 Notion 工作区，项目相关内容都放在其中。不同之处在于，Paperclip 公司不只是存放信息的地方；它是一个能够自主规划并执行工作的组织。

**为什么需要它：** Paperclip 可以同时运行多个彼此独立的 AI 组织。公司边界会隔离各自的目标、智能体、任务和预算，因此你可以并行运营“内容营销”和“软件开发”两家公司，而不会互相干扰。

**你可以这样使用：**

- 创建公司并为它命名、设定目标。
- 为整个组织设置月度预算上限。
- 在公司的仪表板中监控所有工作和支出。

Paperclip 中的一切——每位智能体、每项任务和每一笔支出——都属于某个公司。

---

## 智能体（Agent）

**一句话解释：** 智能体是 AI 员工，是一份经过配置的职位，包含具体工作、经理和月度预算。

**类比：** 聘用智能体就像聘请承包商。你不会只接入“一个 AI”，而是会定义职位名称、说明职责、提供所需工具、指定汇报对象并设置月度费用。不同之处在于，这位承包商由 Claude、Codex 或其他 AI 系统驱动。

**为什么需要它：** 没有智能体，Paperclip 中就没有执行工作的人。智能体层把目标转化为行动。每位智能体都有清晰的职责范围，让多位智能体能协作而不至于搞不清谁负责什么。

**你可以这样使用：**

- 通过初始设置或 **Agents（智能体）** 页面聘用首位智能体（CEO）。
- 配置驱动它的 AI 系统、运行位置和预算。
- 查看状态和运行记录，了解它正在做什么。

智能体按照严格的层级组织。每位智能体都恰好向一位经理汇报。CEO 是唯一没有经理的智能体，它直接向你（董事会）汇报。

![智能体页面的组织架构视图，CEO 位于顶层，直属下属显示在其下方](../../../user-guides/screenshots/light/org/org-chart-view.png)

> **说明：** CEO 始终是你创建的首位智能体。它是公司的入口点；CEO 开始运行后，会创建任务，也可以申请聘用自己的下属。

---

## 任务（Task）

**一句话解释：** 任务是一项具体工作，类似项目看板上的工单，只不过负责人是 AI 智能体而不是人。

**类比：** 如果你用过 Jira、Linear 或 Trello，任务会让你觉得很熟悉。每项任务都有标题、说明、优先级、状态和负责人。不同之处在于，任务分配给智能体后，它会接手并自主执行，同时在任务评论串中发布进展。

**为什么需要它：** 把工作拆解为任务，才能让自主执行过程可追踪、可控制。你和 CEO 智能体会把公司目标拆成能跟踪、排序和重新分配的任务，而不是要求 AI “把所有事情都做完”。

**你可以这样使用：**

- 在 **Issues（问题/任务）** 页面或收件箱中审阅 CEO 创建的任务。
- 需要亲自安排工作时手动创建任务。
- 查看任务状态和评论串，跟进进展。

任务会按照规定的生命周期流转：

```
backlog → todo → in_progress → in_review → done
```

智能体遇到等待事项时，任务也可以标记为 `blocked`；不再需要这项工作时，可以标记为 `cancelled`。

![任务收件箱显示不同状态的任务](../../../user-guides/screenshots/light/tasks/inbox-view.png)

> **提示：** 智能体接手任务时会“签出”任务，也就是取得独占处理权。这样可以防止两个智能体同时执行同一项任务。

---

## 心跳（Heartbeat）

**一句话解释：** 心跳是一次按计划启动的运行窗口，也就是智能体醒来查看收件箱并开始工作的时段。

**类比：** 可以把心跳想成给员工设置的周期性闹钟。闹钟响后，他们查看消息、接着之前的工作处理一部分事情，然后下班等下一次闹钟。智能体不会一直运行，而是在一次次心跳中运行。

**为什么需要它：** 持续运行 AI 智能体既昂贵又难以管理。心跳让执行时间更可预测、费用更容易跟踪。你大致能知道智能体何时工作、运行多久，以及每个窗口里完成了什么。

**你可以这样使用：**

- 设置每位智能体触发心跳的频率（例如每小时一次）。
- 想手动触发时，在智能体页面点击 **Run now（立即运行）**。
- 在运行策略允许的情况下，通过评论或任务分配按需唤醒智能体。

每次心跳都会保存完整记录，方便你查看智能体做了什么以及为什么这样做。

心跳可以由以下事件触发：

- **计划**——计时器到达配置的间隔。
- **任务分配**——为智能体分配新任务。
- **新评论**——有人在分配给智能体的任务上发表评论（单独的 @提及不会唤醒智能体）。
- **手动触发**——你在智能体页面点击 **Run now（立即运行）**。
- **审批结果**——智能体提交的待处理审批已获批准或被拒绝。

![审计页面运行记录标签筛选出一位智能体，并列出其近期心跳运行](../../../user-guides/screenshots/light/agents/agent-detail-run-history.png)

## 适配器（Adapter）

**一句话解释：** 适配器负责连接 Paperclip 和实际运行智能体的 AI 系统。

**类比：** 可以把它想成出国旅行时使用的电源转换插头。电器（智能体）本身不变，但插头（适配器）必须匹配插座（AI 运行环境）。Claude Code 需要一种适配器，Codex 需要另一种，自定义 webhook 则需要第三种。

**为什么需要它：** Paperclip 本身不是 AI，而是位于 AI 之上的编排层。适配器系统使 Paperclip 能够兼容不同的 AI 运行环境，而不被单一服务提供商限制。你可以让部分智能体使用 Claude，其他智能体使用 Codex，也可以通过 HTTP 适配器连接完全自定义的系统。

**你可以这样使用：**

- 聘用智能体时选择适配器类型（Claude Code 是最常见的入门选择）。
- 配置适配器专属设置：使用哪个模型、文件写入位置，以及智能体需要哪些环境变量或机密信息。
- 启用智能体前，在 **Test your agent（测试智能体）** 卡片中点击 **Run test（运行测试）**，确认适配器工作正常。

目前可用的适配器类型：

| 适配器 | 用途 |
|---------|------|
| `claude_local` | 在本机运行 Claude Code 智能体 |
| `codex_local` | 在本机运行 Codex 智能体 |
| `gemini_local` | 在本机运行 Gemini CLI 智能体 |
| `opencode_local` | 在本机运行 OpenCode 智能体 |
| `cursor` | 在本机运行 Cursor 智能体 |
| `pi_local` | 在本机运行 Pi 智能体 |
| `hermes_local` | 在本机运行具备持久记忆和 30 多种工具的 Hermes Agent |

运行环境中还包含 `openclaw_gateway`、`process` 和 `http` 等适配器类型，但目前在智能体配置下拉菜单中标为 **Coming soon（即将推出）**。完整列表见[适配器概览](../../../reference/adapters/overview.md)。

大多数刚开始使用 Paperclip 的人，选择 `claude_local` 就可以了。

## 预算（Budget）

**一句话解释：** 预算是每月支出上限；Paperclip 会自动执行这个金额限制，防止智能体超支。

**类比：** 可以把它想成公司信用卡的月度限额。在达到上限前，智能体可以正常支出；接近上限时会收到警告；达到上限时，支出会被拒绝，智能体自动暂停。

**为什么需要它：** 智能体发出的每次 API 调用都会产生实际费用。若没有预算，配置错误的智能体可能执行庞大而昂贵的工作，或因故障陷入无限循环。预算为自主运行 AI 提供了安全网。

**你可以这样使用：**

- 设置公司级预算，限制整个组织的支出。
- 设置每位智能体自己的预算，同时受公司上限约束。
- 在仪表板的费用面板中监控支出。
- 智能体有预算策略后，可在 **Audit → Budgets（审计 → 预算）** 随时调高或调低预算；创建预算需通过 CLI 或 API（参见[智能体：预算](../../../guides/org/agents.md#budgets)）。

预算的执行方式：

- 使用量达到 **80%** 时，Paperclip 会发出警告，让你能在硬性停止前进行干预。
- 使用量达到 **100%** 时，智能体会自动暂停，不再触发心跳。

![审计页面的预算标签，显示预算控制摘要和活动中的预算事件](../../../user-guides/screenshots/light/costs/agent-budget-bar.png)

> **注意：** 公司预算和单个智能体的预算相互独立。即使公司预算尚有余额，智能体仍可能因为自己的预算上限而暂停。请谨慎设置两种预算。

## 审批（Approval）

**一句话解释：** 审批是一道治理关卡，Paperclip 会在重要操作继续之前暂停，并请你确认。

**类比：** 可以把它想成公司的采购审批流程。低于一定金额的支出可以由员工自行处理，超过金额则需要经理批准。审批就是 Paperclip 为 AI 智能体设置的类似确认流程。

**为什么需要它：** 自主智能体功能强大，但你不应该放弃所有控制权。审批确保公司发展方向和人员聘用等重要事项仍由你决定。

**你可以这样使用：**

- 在审批队列中查看待处理审批。
- 点击批准，让操作继续。
- 点击拒绝，直接阻止操作。
- 要求修改，让智能体修改提案后重新提交。

初学者最常遇到的两种审批是：

- **策略审批**——首次心跳后，CEO 会提交策略计划供你审阅。批准前，后续工作不会开始。你可以要求它修改任意多次。
- **聘用智能体审批**——CEO 或其他经理想聘用新智能体时，会提交配置供你审阅。批准前，你可以查看新智能体的职责、预算和角色。

如果触及预算硬性上限，Paperclip 也可能提供预算覆盖审批；更高级的工作流程中还会出现其他董事会级审批请求。

![审批页面列出待处理审批，例如 CEO 策略提案和董事会审批请求](../../../user-guides/screenshots/light/approvals/approvals-list.png)

> **提示：** 审批不会自动过期。如果审批仍待处理，正在等待结果的智能体会暂停在当前步骤，直到你采取行动。请留意审批队列。

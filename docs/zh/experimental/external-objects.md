# 外部对象

任务经常会引用存放在其他地方的工作——例如 GitHub 拉取请求、其他跟踪系统中的工单或某个部署。通常这些都只是普通链接：若要知道拉取请求是否已合并，你必须离开 Paperclip 去查看。

开启 **External Objects**（外部对象）后，Paperclip 会检测任务中任何位置的外部 URL（标题、描述、评论和文档），并显示其实时状态，而不是只保留普通链接。引用的 GitHub 拉取请求会在提及处显示一个小状态图标，并在任务的 **Properties**（属性）面板中显示一行信息，例如 *PR 8512 - 已合并*。

![某项任务的评论中包含指向 GitHub 拉取请求和问题的链接，并显示行内状态图标；Properties 面板列出 PR 8512 - 已合并和 Issue 4419 - 已关闭](../../user-guides/screenshots/light/experimental/external-objects.png)

## 启用此功能

1. 前往 **Settings → Experimental**（设置 → 实验性功能）。
2. 开启 **Enable External Objects**（启用外部对象），说明文字为：*“检测任务中的外部 URL，并显示拉取请求、工单和其他引用工作对象的已解析状态。”*

## 使用方法

无需针对每个任务单独配置——只需像平时一样在合适位置粘贴 URL：

- **检测。** 创建或更新任务、评论或文档时，Paperclip 会提取其中的 URL。GitHub 拉取请求和问题 URL（`github.com/{owner}/{repo}/pull/{n}` 或 `/issues/{n}`）开箱即用，会识别为一等工作对象；其他 URL 会成为通用链接对象。插件可以为其他系统注册额外的检测器。
- **行内状态图标。** 在描述和评论中，被识别的链接会保留原始文本，并在前方显示一个小状态图标。将鼠标悬停在链接上即可查看对象及其状态（例如 *Open*（开放）、*Merged*（已合并）或 *Closed*（已关闭））。新检测到的对象在解析前会显示 *“尚未刷新”*。
- **属性行。** 任务的 **Properties** 面板中，在 **Relationships**（关系）下会为每个对象添加一行，并注明服务提供商和类型（例如 *GitHub Pull Request* 或 *GitHub Issue*），其值类似 *PR 8512 - 已合并* 或 *Issue 4419 - 已关闭*。已合并的 PR 会使用专属颜色。排序时最紧急的状态会排在最前；如果对象超过五个，会显示 **References**（引用）行，可展开查看其余对象。
- **External objects 面板。** 任务的 Related Work（相关工作）区域会增加 **External objects**（外部对象）部分，说明为 *“此任务中引用的远程工作——拉取请求、部署、其他系统中的工单等等。”* 其中会以状态标签列出每个检测到的对象；多次提及的对象会显示 `×N` 计数，状态过期、无法访问或需要身份验证时会显示虚线边框。
- **列表和侧边栏。** 任务列表行会显示紧凑的状态徽标，列表工具栏会增加外部对象状态筛选器；项目侧边栏行会汇总占主导的状态。

## GitHub 访问权限

公开仓库无需设置即可解析。对于私有仓库（以及更宽松的速率限制），请添加一个公司的 **secret**（密钥），名称为 `GITHUB_TOKEN`、`GH_TOKEN` 或 `PAPERCLIP_GITHUB_TOKEN`。没有访问权限时，私有对象会显示 *“需要身份验证”*。

## 关闭此功能时

功能会隐藏且停止运行：检测停止，链接恢复为普通链接，Properties 中的行、面板和筛选器也会消失。已检测到的对象会保留，重新启用后会再次显示。

## 注意事项

- 在此版本中，**GitHub 是唯一内置的解析器**，而且只识别路径格式完全匹配的 `github.com` PR/问题 URL。GitHub Enterprise 主机和其他跟踪系统需要安装提供对象检测功能的插件。
- 已解析状态的 TTL 很短（约五分钟）；此版本还没有后台轮询器，因此状态采用延迟刷新，智能体可以通过 API 强制刷新。两次解析之间，状态可能显示为*过期*或*“尚未刷新”*。

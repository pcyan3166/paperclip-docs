# 自动创建恢复任务

> **此版本已移除。** 在 v2026.1012.0 中，**Auto-Create Recovery Tasks**（自动创建恢复任务）卡片已从 **Settings → Experimental**（设置 → 实验性功能）中移除，其 **Preview**（预览）和 **Run now**（立即运行）操作以及背后的 API 也一并移除。Paperclip 仍会运行内置的依赖唤醒兜底机制，但不再通过此设置创建恢复任务。本页其余内容描述的是旧版本中的功能行为。

任务依赖链可能悄然停滞：阻塞任务分配给了已暂停的智能体；一项 `in_review` 任务的审阅者已不存在；或者工作仍被已取消的任务阻塞。没有任何计划任务会唤醒相关人员，因此下游工作会永远等待。

Paperclip 的存活检测会在每次调度器心跳中查找这些失效的依赖链。开启 **Auto-Create Recovery Tasks** 后，它会进一步处理：对于每条近期有活动的停滞链，创建一个高优先级的**恢复任务**——*“解除 PAP-1234 的存活问题阻塞”*——将其分配给最合适的可用智能体，并将恢复任务设置为原任务的阻塞项，以便问题解决后自动恢复原工作。

## 旧版本中的启用方式

在 v2026.1012.0 之前的版本中，此设置的工作方式如下：

1. 前往 **Settings → Experimental**，找到 **Auto-Create Recovery Tasks** 卡片；卡片说明为 *“让心跳调度器为配置的回溯时间窗口内发现的任务依赖链创建恢复任务。”*
2. 设置 **Lookback hours**（回溯小时数，范围 1–720，默认 24）。只有依赖路径在此窗口内出现活动的依赖链才会创建恢复任务；更早且已被遗弃的依赖图不会处理。
3. 打开开关。启用前，Paperclip 会显示 **Confirm auto-recovery**（确认自动恢复）预览，列出此时将创建的所有恢复任务；每项都会显示卡住的任务、检测到的状态、原因和恢复目标。你可以选择 **Enable only**（仅启用，不处理当前发现项），也可以选择 **Enable and create N**（启用并立即创建 N 项）。

卡片还提供独立的 **Preview** 和 **Run now** 按钮，可随时检查检测结果或按需触发扫描；也可使用 **Save hours**（保存小时数）稍后调整时间窗口。卡片底部会确认当前窗口：*“当前窗口：最近 N 小时。”*

## 什么情况算作失效的依赖链

检测会沿着被阻塞和正在审阅的任务向下追踪到叶子阻塞项；如果没有人负责下一步操作，就会标记该依赖链。例如：

- 被一项**未分配**的任务阻塞，或被一项停留在待办列表且没有唤醒路径的任务阻塞；
- 被一项负责人**缺失、已暂停或无法调用**的任务阻塞；
- 仍被一项**已取消**的任务阻塞；
- 处于**审阅中**，但没有有效参与者、待处理交互、审批或其他操作路径。

如果依赖链有明确的等待路径——例如指定了人类负责人、待处理的审批或交互、正在运行的执行、监控器，或已有恢复任务——就永远不会被标记。

## 恢复任务的样子

恢复任务是普通任务，会像其他任务一样显示在看板上。标题类似 *“解除……的存活问题阻塞”*，优先级为 **high**，以恢复目标为父任务，并包含结构化说明（来源依赖链、检测到的状态、依赖路径、候选负责人和建议的下一步操作）。原任务会收到一条指向恢复任务的评论，并被恢复任务阻塞；因此恢复任务完成时，标准的依赖唤醒机制会立即触发。系统会对事件去重：重复扫描会复用尚未关闭的恢复任务，而不会不断创建新任务；如果问题自行解决，与该问题相关的恢复任务会自动取消。

## 关闭此功能时

存活检测仍会运行，过时的恢复任务仍会清理，但不会创建新的恢复任务。启用此标记之前，**Run now** 按钮不可用。

## 注意事项

- 恢复机制会**创建新任务**，绝不会重新分配或接管原先停滞的任务。恢复任务承载解除阻塞的工作，并阻塞原任务，因此停滞任务本身的负责人不会改变。如果无法安全地恢复一项被困的已分配任务（例如重试次数已用尽，或接管工作存在风险），恢复机制会改为将其路由为**由董事会负责的操作**，由人员决定下一步，而不会自行重新分配工作。
- 需要调度器（服务器）处于运行状态；系统会在启动时及定期心跳时执行扫描。
- 如果所有候选负责人智能体都因预算限制而无法工作，系统会静默跳过升级处理。
- 暂停或搁置状态下的任务不会创建恢复任务。
- 管理此标记需要 `instance-settings`（实例设置）权限，即董事会或管理员权限。

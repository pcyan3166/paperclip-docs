# 聊天式任务

查看智能体处理任务通常意味着要同时阅读两种内容：评论串记录它*说了什么*，执行记录展示它实际*做了什么*。有意思的部分——思考、命令、差异——都在一旁；执行结束后，你还得滚过一大段内容才能找到回复。

**聊天式任务**会将任务详情页变成一段实时对话。人员和智能体以聊天气泡的形式发言。智能体两次回复之间进行的所有操作都会实时内嵌显示——思考过程、工具调用、文件差异等；轮次结束后，这些内容会折叠成一行摘要。属性、计划和任务成果则移到侧边面板中，你可以调整面板宽度或将其最大化。

## 默认开启

聊天式任务最初是实验性开关。现在它已成为任务页面的默认工作方式，无需再启用。

如果你更喜欢旧版页面，请前往 **Settings → Experimental**，在 **Legacy**（旧版功能，说明为 *“这些功能即将移除。”*）下开启 **Classic Task Interface**（经典任务界面）。此操作会恢复先前的任务详情页，包括页面级标题栏、普通评论串和固定的 Properties 侧边栏；下文介绍的聊天专属功能在该页面上不可用。卡片说明：*“切换会立即生效，不会影响任何任务数据。”* 与页面上的所有标记一样，此设置对整个实例生效。

<a id="an-optional-combined-task-list"></a>
## 可选的合并任务列表

本页介绍的任务对话是标准行为。**Combined Inbox + Task List**（合并收件箱和任务列表，设置键 `enableCombinedInboxTasks`）是另一项独立的实验性选项，在 **Settings → Experimental** 中默认关闭。只有启用 **Streamlined UI**（精简界面）时，此选项才会生效；如果你的实例已关闭 Streamlined UI，开启此选项也不会产生任何变化，独立的 **Inbox** 行仍会显示。

在精简界面中开启此选项后，**Tasks** 会显示未读和执行失败徽标，侧边栏中独立的 **Inbox** 行则会消失。在 Tasks 中打开 **Views**（视图），可以切换 **Mine**（我的）、**Unread**（未读）、**Blocked**（受阻）、**Recent**（最近）和 **Everything**（全部），也可以选择组织级视图 **All tasks**（所有任务）、**Active**（活动）、**Backlog**（待办）和 **Done**（已完成）。收件箱操作和任务筛选条件仍分别属于各自的视图。已有的收件箱链接会带你前往对应的任务视图。

可以独立于 [Agent Chat](agent-chat.md) 启用此功能。当前视图映射请参阅[视图注册表](https://github.com/paperclipai/paperclip/blob/a6306ba606eb87c89b9ef0344e9fe8e0025580f9/ui/src/lib/task-views.ts)和[侧边栏行为](https://github.com/paperclipai/paperclip/blob/a6306ba606eb87c89b9ef0344e9fe8e0025580f9/ui/src/components/Sidebar.tsx)。

## 任务页面有哪些变化

任务页面本身就是对话线程。打开任意任务后，你会注意到：

- **Chat / Activity / Related work** 标签栏消失。页面只保留 Chat（聊天）界面，且占据中央栏，并在其中独立滚动。
- 面包屑、标题和标题栏徽标会随消息一起滚动，不再固定在顶部。
- 描述、子任务表格、Documents、工作成果、附件和工作区区域不再显示在中央栏——计划和成果改为显示在侧边面板中。
- 标题栏中的工作模式徽标消失。现在需要在编辑器中为每条消息选择模式，每条智能体回复也会标明其运行模式；若在整个任务上显示一个徽标，就会造成误导。

所有内容都还在，只是换了位置。

## 阅读对话线程

### 聊天气泡

你自己的消息会显示在右侧的纯色强调色气泡中。其他人的消息会显示在左侧，并带有作者标题。对于智能体，标题包括图标、名称和一个小标签，用于说明该请求运行时使用的模式。对于其他人员，则显示其姓名和头像，或姓名首字母。因此，队友在同一任务上发表评论时，消息会明确显示为队友所发，而不是你的消息。系统通知会安静地显示在中央。将鼠标悬停在气泡上可查看时间戳。

如果公司已启用快速响应，你发送消息后，智能体开始工作时可能会立即返回一条简短确认信息。该确认带有信息按钮（**Message details**，消息详情），说明内容为：*“平台生成的确认信息。智能体的实质性回复稍后会单独发送。”* 它不算智能体的正式答复。请参阅[快速响应](../guides/day-to-day/costs.md#fast-responses)。

你刚发送的消息会显示为 **Sending…**（正在发送…）或 **Queued**（已排队），直到服务器确认收到。

### 执行轮次

智能体两次回复之间执行的所有操作会归为一个**轮次**。执行仍在运行时，轮次会保持打开并持续更新——你可以按顺序看到思考过程、工具调用和差异。

执行完成后，轮次会折叠并只留下一行摘要：

> ✓ 已完成 · 38 秒 · 3 个工具 · +34 −3 · 12.3k 个令牌

没有相应数据的项目会直接省略。执行异常结束时，摘要会显示 **Stopped**（已停止），而不是 **Worked**（已完成）。点击该行可重新展开整个轮次，再次点击则会折叠。

如果轮次在你面前结束，折叠过程会有动画效果；你打开页面时已经完成的轮次则会直接以折叠状态显示，因此历史记录加载时很紧凑，只有实时工作会展开。

### 思考过程

智能体的推理内容会显示为左侧竖线旁的低调区块。内容传输时，标题会显示闪动的 **Thinking…**（思考中…）；完成后会变为 **Thought for 12s**（思考了 12 秒），随后折叠。点击标题即可重新查看。

### 工具调用和差异

每次工具调用都会占一行紧凑区域：显示工具类型图标、名称、以等宽字体显示的操作对象，以及右侧的状态标记。Paperclip 能识别常见工具类型——终端、搜索、读取、编辑、网页、委派和 MCP 工具——并分别显示对应图标；真正无法识别的工具会显示扳手图标。

点击某一行可展开其结果。如果调用修改了文件，下方还会显示差异面板，其中包含路径、`+34 −3` 更改统计和修改的行。

如果智能体调用工具时需要请求许可，此行也会标明请求是 **allowed**（已允许）还是被拒绝。

### 实时状态栏

执行进行期间，对话线程底部会显示状态栏，其中有跳动的圆点、不断计时的用时和当前操作标签——**Thinking**（思考中）、**Responding**（回复中）、**Searching**（搜索中）、**Running a command**（正在运行命令）、**Reading files**（正在读取文件）、**Editing files**（正在编辑文件）、**Fetching the web**（正在获取网页）、**Delegating**（正在委派），或 MCP 工具的 **Using *ToolName***（正在使用 *工具名称*）。尚未开始的执行会显示 **Queued · Waiting to start**（已排队 · 等待开始）。

执行结束后，该状态栏会在原位置替换为已折叠的轮次摘要，因此你无需转移视线。

某些状态会以卡片形式显示，而不只是一行文字。等待你批准的智能体会显示实际选项按钮；中断、拒绝和输出截断的执行也分别有专属状态标记。

### 用量

当适配器提供相关数据时，次级用量区域会显示实际进度，而不仅仅是旋转图标：已用上下文量和上下文容量百分比、小型进度条、输入及输出令牌数，以及美元费用。显示刻意保持低调，以免喧宾夺主。

### 卡片和标记

计划确认、问题和建议任务卡片仍会内嵌在对话发生时的位置，并保留其接受和拒绝按钮。如果某项确认后来已过期，它会降级为普通分隔线——被取代的请求只属于历史记录，不再是可操作事项。

计划文档新建或修订时，页面会在相应位置显示分隔线：**Plan created**（计划已创建），或 **Plan updated · rev 3 — see the Plan tab**（计划已更新 · 修订版 3 — 请查看 Plan 标签页）。

如果智能体在任务期间保存了新的公司技能，会在对应位置显示 **Skill created**（技能已创建）卡片，其中包含技能名称和说明。点击卡片即可在侧边面板的独立标签页中打开技能——请参阅[智能体在任务期间创建的技能](../guides/org/skills.md#skills-your-agents-create-during-a-task)。

如果智能体还在运行时你就回答了某张卡片，你的回复会在运行结束前排在编辑器上方的队列中等待；也可以使用 **Steer**（引导）或 **Interrupt**（中断）更快发送回复。请参阅[智能体仍在工作时回答卡片](../guides/day-to-day/issues.md#answering-a-card-while-the-agent-is-still-working)。

### 滚动

如果你位于对话底部，线程会跟随新内容滚动；一旦向上滚动，就会停止跟随。页面不会把你强行拉回底部，而是显示一个小型圆形 **Scroll to latest**（滚动到最新内容）按钮；点击后，线程会平滑滚回底部并恢复跟随。在平滑滚动期间再次滚动会取消动画，并停留在当前所在位置。

<a id="the-composer"></a>
## 编辑器

编辑器固定在对话线程底部：上方是文本框，下方是一行控件。

**为每条消息选择模式。** 除非另行选择，消息会以 **Auto mode**（自动模式）运行，由智能体执行更改和工作。点击左侧的 **+** 按钮打开 **Add**（添加）菜单，可在其中选择另外两种模式：

| 模式 | 功能 |
| --- | --- |
| **Plan mode**（计划模式） | 先制定计划，再采取行动 |
| **Ask mode**（询问模式） | 只回答问题，不做更改 |

选择模式后，**+** 旁边会出现带颜色的标签，表明这条消息将执行什么操作。Plan 和 Ask 不能同时开启——选择其中一个会替换另一个。点击标签即可移除并恢复 Auto 模式。如果你更喜欢使用键盘，可按 **⌘+.**（Windows 和 Linux 上为 Ctrl+.），或者在文本框中按 **Shift+Tab**，在三种模式间切换。

占位提示会随你所选的模式变化，因此你可以一眼看出即将发生什么——*“给 Ada 发消息——描述你希望完成的工作…”*、*“与 Ada 一起制定计划——整理计划文档，不更改代码…”*，或 *“向 Ada 提问——只读操作，不会运行任务…”*。模式会在发送消息时生效，而不是在选择模式时生效。

**附加文件**可以使用同一 **Add** 菜单中的 **Files and images**（文件和图片），也可以粘贴文件或将其拖放到编辑器中。每个文件都会先显示 **Uploading…**（正在上传…），随后变为 **Attached**（已附加）；图片还会显示缩略图，并且消息中会加入指向该文件的链接。如果智能体运行器支持，菜单还会提供 **Goal**（目标，*“持续推进”*），用于指定智能体需要持续追求的目标。

**选择谁来回答，以及采用多大推理力度。** 右侧的选择控件包含不同选项：点击智能体名称可选择负责人，点击模型标签可选择模型和推理力度。这些设置会在你发送消息时应用：

- **负责人。** 点击名称后，可以按名称、角色或执行框架（Claude Code、Codex 等）搜索智能体，也可以选择 **No assignee**（未指定负责人）。选择其他智能体并发送消息，会连同消息一起把任务交给该智能体。如果向状态为 `done`、`cancelled` 或 `blocked` 的任务发送消息，任务会重新打开。
- **模型。** 在列表中为此消息选择确切模型，或者在 **Search or paste a model ID**（搜索或粘贴模型 ID）字段中输入列表中没有的模型。若不在意具体模型，可保留执行框架默认选项。
- **推理力度。** 滑块可设置模型的推理力度，范围视模型而定，包括 **Off**（关闭）、**Minimal**（最低）、**Extra High**（特高）、**Max**（最大）或 **Ultra**（极高）。这里只显示该模型及其引擎实际支持的级别，不会提供智能体会悄悄忽略的选项。支持的 Codex 配置还会提供 **Fast mode**（快速模式）开关。

选择器打开期间，其按钮会显示 **Select model**（选择模型），避免你拖动滑块时按钮文字跳动。推理力度滑块会显示 **Default**（默认）以及支持的级别。**Reset to agent default**（重置为智能体默认值）会将模型、推理力度和快速模式恢复为智能体配置。对于不允许 Paperclip 选择模型的智能体（例如运行命令、调用 HTTP 端点或经由网关路由的智能体），选择器会说明原因，而不是显示模型列表。在手机上，选择器会全屏打开。

**问题会显示在编辑器上方。** 智能体提出问题、请求确认或要求你审阅内容时，其卡片会显示在文本框上方。如果有多个事项等待回复，可以使用 **pending** 控件在它们之间切换。下方的编辑器仍可继续使用。

如果你暂时不想处理问题或其他卡片，它们的行为会稍有不同：

- **忽略的问题会移入对话。** 问题会留在原先提出的位置，并折叠为 **Unanswered question**（未答问题）条目；表单和待处理徽标会从编辑器上方移走。如果你没有回答问题，而是直接发送了新消息，也会出现相同情况。无论哪种方式，问题都不会被视为已回答或已拒绝——你准备好时可以打开该条目，原始表单会恢复，并保留你之前已开始填写的答案。此任务中对你而言的忽略状态会被记住，重新加载页面也不会让表单重新出现。智能体提出的新问题仍会打开自己的表单。
- **确认和审阅仍会保留待处理行。** 忽略后，卡片会折叠为一条可重新打开的待处理输入；忽略并不代表回答或拒绝。发送普通消息也不会将其清除：在你作出答复前，它仍会保持待处理状态，除非智能体已将其设置为由你的下一条回复替代。

跳过问题也等于告诉智能体你已继续推进。发送新消息后，旧问题就成为历史记录：智能体不会再提醒你回答，而且无需等待该问题的答复就能完成你所请求的工作。之后你仍可回答旧问题，但这不会重新打开任务或唤醒智能体。审批、权限和凭据请求、审阅阶段以及更新的问题仍会使任务保持等待状态，直到你处理为止。

**排队消息。** 智能体正在运行时发送的消息，会在编辑器上方排队等待。使用 **Steer** 可将消息推送到当前运行中；使用 **Interrupt** 可停止当前执行，并连同你的消息开始新的执行。无论使用哪种方式，消息都会立即显示在对话中。如果消息无法发送，会返回队列并附上说明原因的错误，因此你输入的内容不会丢失。如果执行在真正开始之前就已停止，对话会提供 **Retry**（重试）；你也可以发送新消息以开始新一轮。

**创建任务时选择项目。** **New Task**（新建任务）使用相同的编辑器，并在文本框上方提供 **Project**（项目）选择器。可以按项目名称搜索、选择最近使用的项目，或选择 **No project**（无项目）。模型和推理力度属于任务首次运行设置；项目则是任务属性，不是按消息覆盖的设置。

**按 ⌘+Enter 发送**（或 Ctrl+Enter）。普通 **Enter** 会插入换行。

<a id="stop-pause-and-resume"></a>
### 停止、暂停和恢复

任务有正在运行的执行时，有权管理任务控件的人员会在空编辑器中看到 **Stop**（停止）。点击后可暂停任务工作；如果是父任务，也会暂停整个子树。任务菜单中也有 **Pause work**（暂停工作）或 **Pause subtree**（暂停子树）操作。输入文本或添加附件后，按钮会恢复为 Send（发送）。键盘发送快捷键不会触发停止操作。

Paperclip 会等待受影响的执行停止。如果无法确认执行已停止，会显示行内错误；仅保存了暂停状态，并不能证明服务提供商已停止运行。取消任务仍是独立的任务菜单操作。

任务暂停后，会出现琥珀色 **Task is paused.**（任务已暂停。）或 **Subtree is paused.**（子树已暂停。）面板，并取代任务输入控件。你的文字和附件仍会保留在草稿中。再次发送消息前，请使用 **Resume task**（恢复任务）或 **Resume subtree**（恢复子树）。如果暂停来自祖先任务，按钮会带你前往该祖先任务。

恢复操作会解除暂停。你可以选择唤醒符合条件的智能体；但如果任务执行结果不确定，必须先处理恢复问题。此时尝试唤醒会保持暂停状态，并说明需要检查什么。你仍可以选择只解除暂停而不唤醒智能体。如果解除暂停成功但唤醒失败，页面会说明暂停已解除，并指出启动问题。

<a id="when-a-run-needs-attention"></a>
### 执行需要关注时

出现 **Recovery needed.**（需要恢复）时，页面会引导你 **Inspect run**（检查执行），并且仅在相应操作可用时提供 **Continue**（继续）或 **Retry**（重试）。恢复待处理期间，已保存的后续消息仍会附在任务中。服务提供商拒绝所选模型时，会显示 **Model unavailable.**（模型不可用。）：请选择受支持的模型，或清除任务的模型覆盖，然后重试。在选择器中粘贴确切模型 ID 并不保证服务提供商会允许访问该模型。

**Model at capacity**（模型容量已满）属于另一种情况：模型确实存在且你有权使用，只是当前繁忙。如果原生 Codex 轮次因为所选模型容量已满而失败，任务不会进入恢复流程，而会显示一张 **Retry scheduled**（已安排重试）卡片，原因是 **Model at capacity**，并提示 *“上次尝试失败：所选模型容量已满，请尝试其他模型。Paperclip 将自动重试。”* Paperclip 会在一分钟后重试；若仍失败，再过两分钟会再次重试，并保留同一模型和任务历史记录。如果不想等待，可以点击 **Retry now**（立即重试）。如果两次自动重试都遇到相同问题，任务会被阻塞，并显示 *“自动重试次数已用尽；请稍后重试或选择其他模型。”*——可以稍后重试，也可以选择其他模型。

**无法访问智能体的 AI 连接。** 如果智能体使用了任务所服务人员无权访问的 AI 连接，执行会失败。线程会显示一条持续展开而不会折叠的错误，例如 *Codie 配置为使用 Dotta 的 API Key，但你无权访问该凭据。* 错误会要求你选择自己有权使用的连接，或请管理员更新智能体连接。**Change AI connection**（更改 AI 连接）会打开智能体的 AI 设置；**View run**（查看执行）会打开失败的执行。其他阅读该任务的人会看到通用凭据名称，而不会看到连接名称。之后的重试成功时，错误就会消失。

如果执行需要登录服务提供商，请先在线程中完成显示的连接或身份验证请求，然后再重试。缺少密钥或配置绑定属于需要修复的设置问题，不应反复发送相同请求。更完整的任务恢复流程请参阅[恢复操作](../guides/day-to-day/issues.md#recovery-actions)。

## 侧边面板

右侧的属性面板现在可以调整宽度并最大化。

拖动面板左边缘即可调整宽度，面板会记住该宽度；**双击边缘**则会恢复默认宽度。在标题栏中使用 **Maximize panel**（最大化面板），可以将面板平滑展开至整个页面，方便查看——展开期间中央栏不会重新排版；使用 **Restore panel**（还原面板）可恢复原状。

面板的 **+** 菜单可让你在标签页中打开任务界面和文档。主要视图包括：

- **Properties**（属性）——与以前相同的任务属性：负责人、项目、阻塞项等。
- **Plan**（计划）——任务有了计划文档后便会出现。它会在已接受的计划历史记录上方显示修订编号和最近更新时间。
- **Artifacts**（成果）——以只读方式查看任务的工作成果、文档和附件，并按执行分组。每项内容都会根据类型显示相应卡片——例如拉取请求、提交、文档、图片、视频、链接预览、CSV 数据或文件——并提供合适的打开操作。Markdown 和文本文件会在此面板的独立标签页中打开。如果没有任何内容，会显示 *“尚无成果。工作成果、文档和智能体生成的文件会显示在这里。”* 请参阅[从任务访问成果](../guides/day-to-day/artifacts.md#reaching-artifacts-from-a-task)。

你还可以打开 **Tasks** 来跟进祖先任务、子任务以及从此工作中创建的任务；技能卡片也可以打开自己的命名标签页。面板会记住你打开的标签页。[Agent Chat](agent-chat.md) 使用同一个面板，但其中的 Tasks 和 Artifacts 显示的是智能体范围内的信息。

Plan 标签页还有一项实用设计：计划等待你确认时，其 **accept**（接受）和 **send back**（退回）按钮会固定在面板底部；滚动查看计划内容时按钮仍会留在原处，因此你可以读完整份计划再作决定，无需返回线程中查找卡片。

## 返回经典任务页面

这纯粹是界面呈现上的变化。开启 **Classic Task Interface** 会立即恢复旧版任务页面，关闭后则会恢复聊天式页面；两种切换都不涉及迁移。评论、执行、执行记录、计划和附件无论在哪种界面下都是相同的记录，只有显示方式不同。

## 注意事项

- 这是对日常常用页面的重新设计，目前仍在积极迭代。不同版本间，细节（例如标签、间距和哪些内容会折叠）可能发生变化。
- **Classic Task Interface** 对整个实例生效，因此切换回经典界面会更改实例中每个人看到的任务页面。没有按用户选择退出的选项。
- Artifacts 标签页目前为只读。上传和删除附件仍需在现有附件界面中操作。
- 实时结构化计划清单（智能体执行过程中勾选计划步骤）依赖适配器支持，目前尚未接入实时线程；Plan 标签页只显示计划文档和获批计划历史。

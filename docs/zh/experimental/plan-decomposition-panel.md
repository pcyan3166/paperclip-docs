# 任务计划分解

智能体的计划获批后，Paperclip 会将其分解为子任务，并保证分解**恰好执行一次**，即使智能体重试或执行在创建过程中中断也不例外。通常这套机制是不可见的：你只会看到子任务出现。开启 **Task Plan Decomposition**（任务计划分解）标记后，就能查看其详细信息。

此功能会在任务详情页中添加只读的 **Plan decomposition**（计划分解）区域，按每个获批的计划修订版本显示请求创建的子任务数量、实际创建的数量以及具体创建了哪些子任务，以便你验证子任务创建是否正常。

## 此功能的用途

此面板用于调试和验证。应用本身对此功能的说明很直接：*“旨在展示界面仍在改进期间，调试和验证子任务创建行为。”* 在排查“此计划是否创建了所有子任务？”、“重试是否重复创建了子任务？”或“分解是否仍在进行？”等问题时，可以开启此功能；其他时候也可以将其关闭。

## 启用此功能

1. 前往 **Settings → Experimental**（设置 → 实验性功能）。
2. 在 **Paperclip Developer Mode**（Paperclip 开发者模式）下开启 **Task Plan Decomposition**，说明文字为：*“在任务详情页中显示获批计划的分解历史。”*

此设置对整个实例生效，并立即生效。

## 阅读面板

打开一项其获批计划创建了子任务的任务。主栏中的 **Plan decomposition** 区域会出现在 **Documents** 上方，并显示获批计划修订版本的数量。每个修订版本对应一张卡片：

- **状态徽标**——**Completed**（已完成，绿色勾号），或在子任务仍在创建时显示 **In flight**（进行中，琥珀色旋转图标）。
- **“Plan revision N”**（计划修订版本 N）和创建进度——例如 *“已创建 3 项子任务，共 3 项”*。
- 已完成记录上的 **“Idempotent claim”**（幂等声明）徽标。这是确保只执行一次的保护措施：相同指纹的重复尝试会复用此记录，而不是创建重复子任务。
- 元数据行——执行分解的智能体、分解开始和完成的时间，以及获批 **Plan document**（计划文档）的链接。
- 为每项已创建子任务显示一个标签，链接到其详情页。

除了链接之外，此面板无需配置，也不需要点击任何控件；它只提供信息。

> **注意：** 只有确实存在分解历史的任务才会显示此面板。即使标记已开启，如果任务计划从未生成子任务，也不会显示任何内容。

## 聊天式任务页面中的位置

本页介绍经典任务页面（即 **Legacy** 下的 **Classic Task Interface** 开关）。在默认的[聊天式任务页面](task-chat.md)中，相同的分解历史会移至任务属性面板的 **Plan** 标签页。该标签页显示计划文档，并在其下方显示获批计划历史，因此你可以在同一处查看计划及其生成的任务。

需要了解以下两点：

- 上文介绍的中央栏 **Plan decomposition** 区域在聊天式页面中会隐藏。相关内容并未消失，而是在 Plan 标签页中。
- Plan 标签页会自行显示历史记录，不受 **Task Plan Decomposition** 标记控制。关闭此标记后，经典任务页面中的该区域会隐藏，但如果你使用聊天式任务页面，Plan 标签页仍会显示获批计划。

请参阅[问题与任务](../guides/day-to-day/issues.md#tabs-in-the-properties-panel-experimental)，了解 Plan 标签页中其他内容，包括如何从面板批准计划。

## 关闭此功能时

只会隐藏显示界面。分解记录仍会保留，“恰好执行一次”的保护机制也仍会运行；此标记只控制是否显示历史记录。重新开启后，历史记录会再次显示。

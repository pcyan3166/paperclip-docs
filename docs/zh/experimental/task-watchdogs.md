# 任务看护器

有时智能体会因为错误原因而停止工作——它误读了阻塞项、没有证据就宣告任务完成，或者遇到可恢复的错误后便放弃。此时没有任何机制会唤醒相关人员，整个任务树就这样悄然停摆。

**任务看护器**是附加到任务上的智能体，用于复核已停止的工作。当受监控任务及其所有后代任务都已停止，且没有任何继续工作的有效路径时，看护器就会被唤醒并查看证据，然后接受停止状态，或者恢复一条有效路径，让工作继续进行。

## 启用此功能

现在无需再启用此功能。过去，任务看护器由 Experimental 设置页面上的 **Task Watchdogs** 开关控制；该标记已移除，如今每项任务始终都提供看护器控件。如果你记得旧版本中的开关，现在在 **Settings → Experimental** 中已经找不到了。

## 使用方法

看护器是按任务选择性启用的，不存在全局的“监视所有任务”开关：

- **为现有任务设置**——任务详情页会新增 **Watchdog**（看护器）属性行。点击后选择一个 **Watchdog agent**（看护器智能体），并可选填说明（*“看护器应关注什么，以及应如何推动工作继续？”*），然后点击 **Set watchdog**（设置看护器）。
- **创建任务时设置**——新任务对话框中的协作者控件会增加 **Watchdog** 选项，与审阅者和审批者并列，并提供相同的智能体和说明编辑器。

设置后，调度器会自动评估被监控的子树。当任务下的所有工作都已停止时，看护器智能体会运行并在线程中发布其判断过程；如果停止属于误判，它会在受监控子树中创建后续工作或解除其阻塞。

每种不同的停止状态只会通知你一次。每次看护器检查停止状态时，Paperclip 都会保存它所查看内容的快照：树中每个已停止任务的状态、负责人、阻塞原因，以及正在等待的问题或审批。之后的评估会与快照比较，只要情况仍然一致就不会再次通知。因此，已停止任务新增评论、文档或工作成果不会重新触发看护器，任务树的一部分完成并退出监控也不会触发。只有发生实质性变化时才会再次唤醒看护器，例如：已停止任务的状态改变、负责人变更、阻塞项增加或解除、开始或停止等待问题或审批，或者受监控任务下出现新的已停止任务。

看护器被唤醒时，会在其发布的停止状态评论中逐项列出已停止的任务及其等待事项，让你一眼看出任务树为何停滞。

完整生命周期（包括看护器何时唤醒、可以执行哪些操作，以及它与其他名为 “watchdog” 的功能有何不同）请参阅[任务看护器指南](../guides/projects-workflow/task-watchdogs.md)。

## 移除看护器

由于没有标记，也就没有全局关闭开关。若要停止看护器，请打开任务，点击其 **Watchdog** 行，然后选择 **Remove**（移除）。

## 注意事项

- 看护器执行有意受到范围限制：它们不能更改看护器配置，且创建的任何任务都必须位于受监控的子树内。
- 每次运行看护器都会消耗一次普通的智能体执行额度——只应在重要的任务树上设置，而不是监控所有任务。去重机制可避免同一停止状态重复收费，但每个真正的新停止状态都会产生一次新的运行。
- 如果看护器接受了停止状态而你不同意，它不会再次检查同一状态。请自行推进任务树（更改状态、解除阻塞项或重新分配），之后的评估便会识别出新的停止状态。

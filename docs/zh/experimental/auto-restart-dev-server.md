# 空闲时自动重启开发服务器

此开关面向 **Paperclip 本身**的开发者。使用 `pnpm dev:once` 运行应用时，开发运行器会监视后端源代码和待执行的数据库迁移；当前服务器启动状态变得过时后，运行器可以替你重启服务器，但只有在实例**空闲**时才会重启，因此不会在本地智能体执行排队或运行期间将其中途终止。

## 启用此功能

1. 使用 `pnpm dev:once` 运行应用。
2. 前往 **Settings → Experimental**（设置 → 实验性功能）。
3. 开启 **Auto-Restart Dev Server When Idle**（空闲时自动重启开发服务器）。说明文字为：*“在 `pnpm dev:once` 中，等待所有排队和运行中的本地智能体执行完成；当后端更改或迁移导致当前启动状态过时时，自动重启服务器。”*

## 工作方式

- **过时状态检测**不受开关影响。开发运行器会监视后端工作区（`server`、`cli`、`packages/*`、配置文件）和待执行的迁移。发生变化时，应用顶部会显示 **Restart Required**（需要重启）横幅，说明原因（后端文件已更改、存在待执行迁移或两者兼有），并列出已更改的路径。
- **开启此开关时**，横幅会显示 **Auto-Restart On**（自动重启已开启）标记，运行器会接管重启流程：等待本地智能体执行全部完成（排队或运行的执行数为零，期间会显示 *“正在等待 N 个运行中的执行完成”*），应用待执行的迁移，然后重启服务器子进程。如果实例当前已经空闲，则会看到 *“实例空闲时将触发自动重启。”*
- **关闭此开关时**，横幅会建议你在合适时机自行重启 `pnpm dev:once`。
- 横幅上始终提供 **Restart now**（立即重启），可立即手动重启。此操作会绕过空闲检查；如果会中断正在运行的执行，会先发出警告。

## 此功能的用途

在积极开发 Paperclip 时，后端编辑和新增迁移会使服务器运行在过时的启动状态上。盲目重启会中断正在进行的智能体执行；完全不重启则意味着只能针对过时的代码进行测试。此开关会在唯一安全的时机自动执行重启：没有任何任务正在运行时。

## 关闭时的行为和注意事项

- 关闭表示只能手动重启；检测和横幅仍然有效。
- 此机制仅在 `pnpm dev:once` 下存在。它对生产部署或其他开发模式没有作用；除非你正在开发 Paperclip，否则请保持关闭。
- 自动重启前会自动应用待执行的迁移。

# 状态卡片

你已经知道每天都会问的那几个问题：*发布还在受阻吗？* *本周迁移工作有什么变化？* *我们会按计划发布吗？如果不会，下一步具体该做什么？* 回答这些问题意味着你要再次打开看板、筛选、阅读，并把所有信息记在脑中——明天还得重复一遍。

**状态卡片**会替你处理这些问题，并将答案保存在一个固定位置。你只需写一句话说明你关心什么，Paperclip 的 Summarizer（摘要生成器）就会将其转换为实时摘要，并随着底层工作推进而更新。所有卡片都会显示在共享的 **Status**（状态）看板上，因此每个人看到的都是同一份答案。

## 启用此功能

1. 前往 **Settings → Experimental**（设置 → 实验性功能）。
2. 开启 **Status Cards**（状态卡片），说明文字为：*“启用实验性共享状态卡片看板及其受控 API。关闭此功能时保留现有卡片数据。”*

此标记控制整个功能，而不只是界面。关闭后，侧边栏中的 **Status** 项目会消失，访问 `/status` 会重定向到仪表板，所有状态卡片 API 路由都会返回 `404 Not Found`，并附带 `{ "error": "Status cards are not enabled" }`。

Status Cards 属于由 Paperclip Cloud 决定是否启用的功能。在由 Cloud 管理的实例上，此开关会显示 **Managed by Paperclip Cloud**（由 Paperclip Cloud 管理）标记并变为灰色——请参阅[开关被锁定时](overview.md#if-a-toggle-is-locked)。此功能在 Cloud 和自托管实例上默认都处于关闭状态；如果你自行运行 Paperclip，可以自行开启。

此外，公司还必须已配置并准备好内置的 **Summarizer** 智能体。没有它就无法设置卡片；请求会失败并显示 *“Summarizer 内置智能体尚未配置”*。

## 创建第一张卡片

在侧边栏中打开 **Status**（带有 *beta* 标记），然后点击 **New card**（新建卡片）。卡片创建时最重要的字段只有一个：

> **你想持续关注什么？**

像向同事提问一样写下内容。对话框中的示例包括 *“与评估相关的问题”*、*“本周所有被阻塞的事项”* 和 *“功能 X 已上线吗？如果没有，要发布它的确切后续操作是什么”*。写得更详细也完全可以：*“持续关注 ID 和 Cloud 项目。告诉我服务是否已上线；如果没有，列出让它进入生产环境所需的确切三项操作。”*

这条消息同时承担两项作用，务必记住：它既是**要监控的内容**，也是**更新的写作要求**。没有单独的“摘要指令”字段需要填写。如果你希望更新采用三个项目符号并附上下一步操作，请在同一条消息中说明。

在它下方，**Agent**（智能体）选项用于选择负责生成卡片的智能体。除非希望由公司中的其他智能体负责，否则请保留 *Summarizer (default)*（Summarizer，默认）。

![New card 对话框：只有一个“你想持续关注什么？”字段，下面有填写示例，并带有 Agent 选择器](../../user-guides/screenshots/light/status-cards/new-card-dialog.png)

点击 **Create card**（创建卡片）后，卡片会立即出现并处于 *Setting up*（正在设置）状态，此时智能体正在处理。Paperclip 会在后台创建一项真实任务并分配给该智能体，然后智能体会：

1. 将你的消息编译为结构化的公司搜索查询，并生成卡片标题后写入卡片。
2. 执行这些查询并撰写第一份完整摘要；此操作会在同一次运行中完成，不会等待第二项任务。

稍等片刻，卡片内容就会填充完成。如果你想观察过程，可以通过卡片上的链接 **View setup task**（查看设置任务）打开对应任务。

## 查看看板

每张卡片都会显示标题、状态圆点、当前摘要，以及底部信息：数据的新鲜程度、更新策略和当天的令牌及费用总计。点击卡片会打开详情抽屉，其中有四个标签页：

![Status 看板：每张卡片各占一块区域，显示状态圆点、标题、实时摘要，以及表示数据新鲜度、更新策略和当天令牌与费用的底部信息](../../user-guides/screenshots/light/status-cards/board.png)

- **Summary**（摘要）——显示当前摘要、用于查看早期版本的修订选择器，以及每次更新整合了哪些更改的列表。

![卡片详情抽屉的 Summary 标签页，显示当前摘要和修订版本选择器](../../user-guides/screenshots/light/status-cards/detail-summary.png)
- **Settings**（设置）——显示卡片名称、驱动卡片的消息、智能体、更新策略，以及只读的 **Query debug**（查询调试）区域，其中显示编译后的查询 JSON 和其版本。
- **Watched issues**（已监控任务）——实时列出当前匹配编译查询的任务。

![Watched issues 标签页，列出当前匹配编译查询的任务](../../user-guides/screenshots/light/status-cards/detail-watched-issues.png)
- **History**（历史记录）——显示每次更新的触发原因、令牌数、费用、模型和任何错误。

![History 标签页，每次更新占一行，并列出触发原因、令牌数、费用和模型](../../user-guides/screenshots/light/status-cards/detail-history.png)

卡片名称会自动生成：将 **Card name** 留空，智能体编译时就会命名卡片。手动输入名称后，该名称就会固定，后续重新编译不会覆盖它。

编辑 **What this card watches & reports**（此卡片监控和报告的内容）会重建卡片：保存更改后的消息会将新的编译任务加入队列，下一次更新也会是完整重建，而不是增量修补。

## 卡片状态

卡片保存的状态共有五种，看板会将它们转换为卡片上显示的标签：

| 状态 | 看板显示 | 含义 |
| --- | --- | --- |
| `compiling` | Setting up（正在设置） | 卡片刚刚创建或其消息已更改；智能体正在编译查询并撰写第一份摘要。 |
| `active` | Fresh、Stale 或 Updating | 卡片正常工作。没有待处理内容时显示 **Fresh**（最新）；自上次更新以来已累积更改时显示 **Stale**（已过时）；正在执行运行时显示 **Updating**（更新中）。 |
| `error` | Error（错误） | 上次运行结束时未写入摘要。卡片仍显示最近一次成功摘要，并提供 **Retry**（重试）。 |
| `paused_budget` | Paused — budget（已暂停 — 预算） | 卡片达到每日令牌上限。自动更新会暂停，直到次日。 |
| `paused_hours` | Paused — hours（已暂停 — 时间） | 当前不在卡片的活动时间范围内。变化会累积，等活动窗口开始后合并为一次更新。 |

已归档的卡片会在看板下方单独列在 **Archived**（已归档）行中。

如果卡片的生成任务在没有写入摘要的情况下进入 `done`、`cancelled` 或 `blocked` 状态，卡片就会进入 `error`。受阻任务表示它正在等待人员处理；因此 Paperclip 会将其视为停滞，而不是仍在运行，并释放卡片以便你再次运行。

## 更新机制

首先需要了解的是：**发现变化不收费，撰写更新则会产生费用。** Paperclip 会在数据库中重新执行卡片编译后的查询，将结果与上次保存的指纹比较；只有确实发生有意义的变化时，才会消耗模型令牌。每次更新都会创建一项真正的任务，并分配给卡片的摘要智能体，费用与一次智能体运行相同。

你可以在 **Settings → Auto-update policy**（设置 → 自动更新策略）中选择卡片的更新频率：

| 模式 | 行为 | 所需设置 |
| --- | --- | --- |
| `manual` | 默认模式。发生变化时卡片会标记为 **Stale**；除非你点击 Refresh（刷新），否则不会运行。 | 无。 |
| `interval` | 按计划检查，且仅在发生更改时更新。 | 设置时间间隔——界面提供 5、15、30 或 60 分钟。 |
| `reactive` | 发生变化后，在防抖时间结束时立即更新。 | 设置防抖时间——界面提供 30、60、120 或 300 秒；并设置每小时更新次数上限（默认 6 次）。 |

![Settings 标签页显示自动更新策略模式和 Advanced 区域中的变化触发条件](../../user-guides/screenshots/light/status-cards/detail-settings.png)

### 哪些情况算作变化

在 `interval` 和 `reactive` 模式下，**Advanced**（高级）区域允许你选择哪些变化值得触发更新。默认开启四项、关闭一项：

| 触发条件 | 默认状态 | 触发时机 |
| --- | --- | --- |
| `statusTransitions` | 开 | 被监控任务变为受阻、需要审阅、已完成或已取消。 |
| `membershipChanges` | 开 | 新任务开始匹配查询，或某项任务不再匹配。 |
| `humanComments` | 开 | 人员在被监控任务上发表评论。 |
| `assigneeChanges` | 开 | 被监控任务更换负责人。 |
| `anyUpdate` | 关 | 发生任何更改时触发——可能过于频繁，且包括进行中工作不断变化的情况。 |

取消勾选的事件仍会出现在下一次更新中，只是它们不会自行触发更新。

### 限制措施

**Advanced** 下还有两个设置，且只适用于自动更新——手动点击 Refresh 时始终会运行：

- **Active hours**（活动时间）——设置开始时间、结束时间和时区。不在时间范围内时，卡片会变为 **Paused — hours**，变化会累积为一项更新，等窗口重新开启后再执行。时间窗口跨越午夜也能正常工作。
- **Daily token cap**（每日令牌上限）——当天卡片更新消耗达到该令牌数量后，卡片会变为 **Paused — budget**。留空时，Paperclip 会使用每日 100,000 个令牌的默认上限。每日分界点采用 UTC 时间。

### 完整重建与增量修补

大多数更新都是**增量更新**：智能体会获得上一版摘要和发生变化的任务，然后修补摘要文本。在以下情况下，Paperclip 会改为执行**完整重建**——根据范围受限的快照重写整份摘要：你明确要求完整重建、尚无摘要、一次有超过 10 项任务发生变化、编辑了消息或切换了智能体、查询已重新编译、从归档中恢复卡片，或者连续进行了九次增量更新（用于防止内容漂移）。

### 摘要中提到的任务

如果摘要通过任务标识符（`ABC-123`）提及某项任务或链接到该任务，那么该任务就会加入卡片的监控集合，即使它不匹配编译后的查询也一样。因此，该任务后续发生变化仍会触发更新。未知标识符和其他公司的任务会被丢弃；任务数上限为 200。它们会显示在 Watched issues 标签页的 **Mentioned in the latest update**（在最近一次更新中提及）下方。

## 费用

每张卡片都会如实列出费用。卡片底部会显示当天的令牌和费用，看板标题会显示所有活动卡片的合计，History 标签页会按更新列出使用的模型和相应明细。已归档行会显示累计费用。

变化检测本身不收费——它只是数据库操作。你需要付费的是卡片决定撰写的每次更新。

## 归档和恢复

归档卡片会彻底停止其活动：不会自动更新，也不会继续监控；任何正在进行的生成任务都会取消。卡片及其摘要历史记录会保留。

点击看板下方的 **Show archived**（显示已归档），即可查看已归档卡片；选择 **View**（查看）阅读最后一份摘要，或选择 **Restore**（恢复）重新启用卡片。恢复后的卡片会先标记为过时，并安排一次**完整**重建，而不是悄悄沿用旧计划。因此你不会看到卡片归档期间已悄然过时的摘要。

删除卡片是另一项独立且永久的操作，只能通过 API 执行。

## 智能体也可以拥有卡片

拥有任务分配权限的智能体可以通过 API 创建和管理状态卡片，这些卡片也会显示在同一共享看板中。不过，智能体卡片的限制更严格：智能体只能管理自己创建的卡片，最多只能拥有 20 张；卡片消息最多 4,000 个字符，而你的卡片最多 20,000 个字符。完整规则请参阅 [Status Cards API](../reference/api/status-cards.md)，随附的 [Status Card Query 技能](../reference/skills/bundled/paperclip-operations/status-card-query.md)会教智能体如何使用该 API。

## 注意事项

- 编译和刷新都属于普通的分配任务，因此频繁更新的响应式卡片会持续产生智能体费用。建议从 `manual` 模式开始，确认卡片有用后再提高更新频率。
- 编译后的查询由智能体生成。如果卡片监控了错误内容，请检查 **Query debug** 和 **Watched issues** 标签页，然后改写卡片消息，不要试图直接修改查询。
- **Query debug** 区域只是查询编译器调优期间的临时观察窗口——不要围绕它构建工作流程。
- 卡片属于公司范围并由全员共享。任何有权访问公司的人员都能看到看板上的每张卡片。
